Literature reproduction as an application test ​

2026-11-02. Five real analyses from the 97 fully-open papers of the clusterprofiler-articles corpus, reproduced through Rho 0.5.2 in one local service: the Agent wrote and ran R in Rho's Notebook sessions, Rho captured the files, notes, commands and figures, and I reviewed what each screen showed. This record keeps what was asked, what actually ran, what Rho did well, what broke, and what is still open. No Rho source changed in this pass (the request was to test and record, not to fix).

What the reproductions found ​

  • P1 Four DEG and reversal counts, none matching the paper: 1096 up / 1549 down against 1193 / 869, and 334 / 551 reversed against 417 / 293. The Agent recorded three alternative definitions in reversal_alternatives.csv (joint model, sign-only, adjusted p) rather than tuning one to fit. GO BP for the reversed-up set gave potassium ion transport (adj. p 0.0059) and CAMKK-AMPK signalling; the reversed-down set gave neuropeptide signalling (4.5e-7) and muscle system process.
  • P4 604 DEGs at the paper's threshold (370 up / 234 down) against the paper's 500 (406 / 94), with a three-way sensitivity table over annotation and filtering. GSEA put oxidative phosphorylation, mitochondrial translation and ribosome highest lower in old endothelial cells.
  • P5 The matrix holds 40 patients (23 responders / 17 non-responders), not the trial's 54 (31 / 23). The responder contrast gave 0 DEGs at FDR 0.05 and therefore no ORA terms and no dotplot; the paired on-treatment contrast gave 2596 DEGs and 290 enriched GO BP sets by fgsea.
  • P3 CD68-vs-CD20 DE reproduced (1111 DEGs in the paired analysis, 1112 paired-only, 1116 unpaired), with the marker check; the Hallmark ORA and its dotplot were the part that kept being deferred.
  • P2 The reproduction came closest to the paper's scale: 92,597 nuclei after QC against 95,156, and 25,999 genes against 25,890. Louvain gave 31 clusters, annotated into excitatory 40,671, inhibitory 18,849, oligodendrocyte 17,457, unresolved 8,364, astrocyte 2,699, microglia 2,503, OPC 2,054. The excitatory PS19-fE4 vs PS19-fE3 contrast gave 4,113 genes at adjusted p < 0.05 and |avg_log2FC| ≥ 0.1. Its own findings call that set large for the cut-off and note the uneven groups (8,533 PS19-fE3 against 20,832 PS19-fE4 excitatory nuclei); the top hits are unnamed or non-coding features (AY036118, Gm47283, AC149090.1) and enrichKEGG returned no pathway. On this evidence the arm shows a technical signal rather than a biological one.

What broke or cost the person ​

These are recorded, not fixed: the request was to test and record.

  1. The 64-turn cap. P3 and P4 both ended with "Not answered. Internal error: Reached maximum number of turns (64)", and the conversation row then reads Failed. The cap belongs to the Agent client, but Rho presents it as an internal error and offers no in-place way to resume with a fresh budget: the person presses Continue and restates what is left. P4's first attempt cost $0.491 and produced no result file.
  2. One approval per action. With the agent in Manual mode, every shell command and every file write or edit waits for a choice. Counting the distinct prompts in my own run logs: P1 8, P2 16, P3 24, P4 12, P5 10 (some prompts were logged without their text, so these are lower bounds). Only the narrow option "Yes, and don't ask again for rtk read * and rtk ls * commands" reduces repeats; writes and edits always ask. A broader "Yes, allow all edits during this session" did appear, but only late in P2's fourth turn — after several dozen separate write approvals — and not in the other conversations. A person cannot leave the screen during an analysis.
  3. The Agent guesses Rho's resource paths. Before finding /value/cells/0/state it tried /cells, /cells/0, /value/cell/state, /value/cells/0/outputs and was refused each time; counting _(refused)_ in the exported transcripts: P1 6, P2 4, P3 6, P4 11, P5 0. In the same runs capability.index was called 36 times (P2), 11 (P3) and 19 (P4). The index does not make the resource grammar evident, and this guessing is a large part of what the 64-turn cap then cuts off.
  4. A wait that nothing wakes. P2's Agent armed a "Monitor" for the SCTransform job and ended its turn: "The Monitor is armed and will fire when SCTransform finishes. I'll wait for that event rather than polling." The conversation reported "Done in 8 min" while the analysis was unfinished, and no event ever arrived. After being told this, it continued in the same session and found the finished cells.
  5. ggsave hung in the Notebook session. P1 reported: "ggsave hung in the Notebook session, so the figure is drawn with png() instead. Several cells also stalled and needed interrupting." kernel.interrupt was called once in P1, twice in P3 and once in P4.
  6. The approval text is not the command that ran. The Agent's own text says cat README.md && ls -la …, the executed step is shown as cat README.md && …, and the choice asked for rtk read README.md && rtk ls -la …. Three spellings of one command in one conversation; a person approving it cannot tell what will run.
  7. A closed tab loses the conversation. No page has an address, and a new tab opens the Agent panel at "New conversation"; clicking the conversation in the list does not open it. The only way back that worked was Continue on the list row, which is also the resume path for a failed run.
  8. Refusals are counted, not explained. The conversation summary says "5 refused", but nothing in the screen says what was refused or why; the reason is only in the transcript export. Rho's own activity record showed every recorded call as returned (35 in P1, 50 in P3, 77 in P2), because these refusals happen inside the Agent client.
  9. Notebook editor residue. The person's own cell left ls() in the R input; edits and reruns of Agent cells are not distinguished from the person's in the input line.

Two things this sorting changes about the flat list above: the largest cost is not the 64-turn cap on its own but its interaction with guessed resource paths, and the questions a person most needs answered — what will run, did it finish, how do I get back — are all presentation and recovery problems on Rho's side of the line.

Limits of this pass ​

  • One model, one Agent, one effort setting, one machine, five papers. Nothing here is a usability claim; no independent researcher watched these screens.
  • The reproductions cover the expression → DE → enrichment → figure chain of each paper, not whole papers: the single-cell arm of P5, the metabolome of P4 and the spatial regions of P3 are out of scope. P3's region labels (GC/IF/LZ/DZ) are not in the public matrix, so that comparison cannot be reproduced from GSE232853 at all.
  • The 64-turn cap and the permission prompts come from the Agent client; only their presentation and recovery are Rho's.
  • P2 needed four turns. It finished its tables, UMAP, findings and notes; its KEGG dotplot was deliberately not drawn because enrichKEGG returned no pathway, and its scripts/analysis.R was never run end to end as a script (the cells were).
  • Continuation is not free: each continued turn re-reads the project, and Rho told me in P2 that "the Agent session this conversation had been using had ended, so this message ran in a new one, told what was said here before". The conversation kept its context; the underlying Agent session did not.

What this suggests for the next pass ​

  1. When an Agent stops on its own limit, say so in those words and offer "continue with what is left" in place, keeping the original message identity.
  2. Make the resource grammar reachable from capability.index (or accept a wrong path with a hint), so an Agent stops guessing and spends its turns on the analysis.
  3. Show what will run in the approval, once, in the same spelling as the executed step.
  4. A person must be able to close the tab and come back to the running conversation.

The practice these runs produced ​

2026-11-02, later. The five runs above were turned into a shipped Skill, rho.analysis-run, declared beside rho.workspace in capabilities and listed by skill.list/skill.read. Every conversation started here is also told to read it before a multi-step analysis (project-notes), because in these runs the Agents never called skill.list on their own: a Skill nobody points at is inert.

Its ten rules are what would have changed these five runs: spend calls on the analysis rather than re-running capability.index (one Agent spent 36 index calls and finished with only its QC table), never wait for an event that does not come, draw to an explicit device after ggsave hung, write each file complete and to disk, check packages once instead of installing into a temporary library, name what did not reproduce and compute the cheap alternatives, and report the state actually reached rather than a claim that the work is done.

The Skill was rewritten before it shipped, because the application had moved. While this pass was being written up, the checkout advanced to 0.5.3 and three of the problems recorded above were fixed by other passes: maxAgentTurns and turnWallMs are no longer set by default, a new Claude Code session opens in Auto rather than Manual, a stopped conversation is named as an Agent turn limit and can be continued in place with the original task, and the conversation row opens an addressable record (P3 continuity). The first draft of the Skill taught workarounds for a 64-step cap that no longer exists; version 1.1 is written as the practice that survives those fixes, and it says plainly that the step cap and wall time are not set by default. The lesson is kept here rather than in the Skill: a Skill written from one build's limits goes stale, so it should describe invariants.

What the Skill still cannot fix is on the other side of the line: the R session's in-memory objects do not survive a service restart, so a person who returns to yesterday's analysis gets the cells and their outputs but must rebuild the values. The Skill says so, and asks the Agent to keep a script that rebuilds what matters.

Verified: npm run build:service, test/skills.test.mjs, test/capabilities.test.mjs and test/notebook.test.mjs pass; the Skill was read back through the running service (skill.list 18 Skills, skill.read returning 1.1 with its digest), and the pointer line was confirmed in the instructions handed to a conversation. No independent Agent has yet followed the Skill in a fresh analysis.
