Rho backend acceptance 0.1 ​

Updated: 2026-10-16; execution evidence: 2026-10-15. Scope: BP-01–BP-06, schema version 1.0 as served at the time.

BP-01–BP-06 passed for the selected macOS arm64 composition. The local service, functional headless package, calling client and inert state fixtures are delivered. This record separates actual source checks and integration runs from the accepted immutable installation candidate. Browser views, native input, accessibility, layout and overall product release remain outside this backend acceptance record.

Architecture clarification, 2026-10-16: this is a successful vertical prototype whose catalog, readers and packaging remain coupled to the paired workflow. It does not accept a reusable plugin foundation. The new capability extraction gates are pending. The recorded candidate, historical results and failures below retain their original identities and scope; this clarification changes no runtime or artifact evidence.

Failures retained and repaired ​

  1. The initial bootstrap=1 recipe wrote real models/tables, then failed in hist(..., breaks="FD") on a singleton. The component now uses one bin for that supported input. A focused native R regression and later execution cover it.
  2. The first shrinkage checker did not load DESeq2 before native S4 dispatch. Explicit namespace loading repaired the checker; the original scientific output was not silently changed to manufacture a pass.
  3. An isolated Claude authentication attempt reported an expired OAuth token. The later successful experiment used the client's existing selected provider configuration, without changing user settings or exposing secrets.
  4. The first installed trial used the macOS default temporary directory and exceeded the native Unix socket path limit. The service now reports that condition before Host startup. Installation uses a shorter canonical /tmp location, retaining Chinese characters and spaces. The macOS socket path is limited to 103 UTF-8 bytes including /.rho/host.sock; no automatic Host move.
  5. The next installed analysis completed, but its independent arithmetic checker rejected a missing script digest. Rscript encodes spaces in --file as ~+~; the recipe now decodes a nonexistent raw path and verifies the real file bytes.
  6. Longer Agent repair trials exhausted first 180-second and then 600-second experiment budgets after context/document reads. Both remain failed. Later source and installed trials supplied the actual error with a focused versioned code range and the client's low-effort setting; both passed within the same 600-second bound. This is not a product latency guarantee.
  7. A developer test invocation without the required Core selection failed early as unavailable; rerunning with the explicitly selected binary passed all 9 tests.
  8. Final review exposed a launcher requirement for Rscript at service startup. The launcher now retains an unavailable selection for the action probe, allowing project/document APIs to work; the service regression exercises this condition.

Limits and UI handoff ​

Headless backend records operations, confirmation points, defaults and exceeded-limit behavior. Native output, execution, artifact integrity, scientific checking and model interpretation remain separate facts. Document saving checks the external disk digest immediately before atomic replacement; uncooperative writers do not participate in the advisory lease, so this is not a filesystem CAS guarantee.

MCP context is pulled through an actual tool. tool-fetched proves that fetch; proactive insertion into an existing external conversation is unsupported. Reads and reconnects never start/recover Hosts. The service stops only Hosts it started; adopted Hosts retain ownership. Partial/unknown and lost acknowledgements never authorize a replacement identity. Each resource has its own version.

UI developers receive protocol/index.json with one hashed file per operation, the exported client, the finite catalog, fixtures and the installed service. All four registered UI entries are currently unavailable. CodeMirror/AG Grid/ECharts/json-render/Dockview mapping, browser refresh behavior, native Unicode IME, focus, keyboard/clipboard/accessibility, responsive widths and full product performance/install acceptance remain actual UI work. No npm registry publication, signing, reproducible binary build, remote service, native execution sandbox or R-memory recovery is claimed.
