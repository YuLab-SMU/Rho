Historical record

This page records what happened on a date, with its observed failures and limits. It is not a requirement for the current implementation. Current behaviour is in Status.

Claude ACP episode ​

The user's 2026-10-27 request was to put ACP in the Agent plugin, connect Claude first, and exercise real multi-turn conversation, cancellation and recovery using Westlake HPC. Core stays unchanged. The earlier CLI episode remains the record for existing CLI sessions.

Selected boundary ​

Agent 0.4.8 owns ACP v1, its stdio process, Claude-specific options, streaming updates, native permission requests, cancellation and session loading. It pins ACP SDK 2.0.2 and claude-agent-acp 0.97.0, whose Claude Agent SDK is 0.3.310. Rho holds the user's original message identities, durable record, input and presentation. No Core API, source or binary changed. The real ACP episode starts no Core Host.

New conversations use ACP. Their ACP session ID is recorded before the first prompt, and a subsequent turn reuses that connection and its Rho MCP grant. Loading history does not append replayed updates to Rho's record. Format-1 records stay on the extracted CLI driver. --agent-backend claude-cli explicitly selects that driver for new sessions; changing the default does not migrate existing ones.

Claude's native Read, Write and Bash tools use Claude's permission policy and OS authority. The four Rho MCP tools retain Rho's project scope and original operation conditions, without an added approval. When Claude asks the user to choose, only the browser on this machine can select one of its offered options. Agent grants, paired tabs and the operator token cannot make that choice. The scoped choice is retained before being returned to Claude, and a repeated identical choice returns the original receipt. Closing or cancelling the turn resolves pending choices as cancelled. Native file writes retain native conditions; they are not Documents conditional saves or evidence of an OS sandbox.

EventObserved behavior
Browser loses acknowledgementRetry keeps the original message identity and returns that message.
Browser disconnects or reloadsThe Agent continues; the browser reads the original retained message.
User presses StopSend session/cancel; mark stopped only on the original prompt's cancelled response.
Agent transport disappearsKeep partial output and mark the unfinished message unknown. Never replay its prompt.
User deliberately sends a later messageCreate a connection if needed and load the exact recorded ACP session.
Loading is unsupported or failsFail that new turn; do not silently create a replacement session.
Rho restartsRead the existing record without execution; a later explicit send can load its session.

ACP cancellation is separate from native process-tree termination. The foreground test command exited after cancellation; this does not establish that every native background job is stopped. The adapter does not expose a verified native transcript ID here, so Rho leaves nativeSessionId null. Existing Core activity collectors remain separate; this change does not invent a second Core journal.

Real setup and observations ​

The source run used Node 22.22.3, Claude Code 2.1.311, Chrome 155.0.8059.84 and Westlake HPC model westlakehpc/deepseek-v4.1-flash. Credentials came from the existing local Claude configuration into process memory. No gateway address or credential is copied to source or the evidence record. Each run uses a disposable project and isolated Claude settings; production user settings are unchanged.

The project contains input.txt (alpha=7, beta=11), notes.txt, and a Python gate that records one actual entry before waiting for a harness release. The first two messages call the real Rho MCP index, read the input and save the remembered phrase violet river 你好 and sum 18. Scope audit after the user's review ​

The user pointed out that the intended Agent runtime → Rho observation and coordination → shared workspace loop is not established by the checks above. That assessment is correct. The source and installed runs accept the Claude conversation driver and its delivery, not the complete observation/workspace goal. The earlier statement that the remaining rounds were complete referred only to packaging and installation; it did not settle this broader goal.

  • Agent 0.4.8's observe() consumes message chunks and tool-call updates only during an active prompt. The pinned SDK 2.0.2 has 14 stable v1 update variants. Plans, usage and session metadata are not retained or presented. Counting all variants is not itself a product acceptance criterion; thought chunks and raw vendor diagnostics were deliberately excluded.
  • Simply removing the prompt-phase condition is insufficient. ACP session loading replays history through session/update. History, new live updates and gaps need to remain distinguishable, without changing an ended turn or implying that a missing observation proves a process stopped. ACP plans replace the previous complete plan; they are the Agent's reported intentions/progress, not independent evidence that project outputs are complete.
  • External Claude/dsh activity still uses its existing transcript/Core activity path. The ACP channel and external observations are not joined into one work read model. Passive attachment to another client's running session has not been demonstrated. session/load is not evidence of that capability; the original assessment also called for complementary independent observations.
  • observation.snapshot already includes a project event cursor, and ObservationClient uses it for rereads and reconnects. It still mainly assembles owner summaries without connecting an Agent plan to actual file changes, results and human responses. A shared project view does not require a global resource version or global scientific revision.
  • Only Claude has a conversation backend. That satisfies the selected first-client scope, but does not prove interchangeable Agent providers. Documents supplies buffers, versions and conflicts for editable content; no shared-notes workflow or work-progress surface has been exercised as part of the ACP episode.

This audit changes the completion claim, not the runtime. It does not accept a new progress model, external ACP attachment, a second Agent or a shared workspace implementation. Those require their own real project observations; the Core boundary and the existing source ownership remain unchanged.

The real episode increases only cancellation grace to 15 seconds and reduces turn wall time to three minutes and native steps to 16.
