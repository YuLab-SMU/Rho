dsh analysis, Rho results and a selected-row question ​

The current 0.1.2 bundle adds visible Harness entries for the complete Rho application; see Desktop installation. The earlier November 5 episode records 0.1.0. The first episode below records the retired 0.0.1 embedded-view prototype, whose source remains in Git.

2026-10-31 local / 2026-11-01 UTC. This episode implements the requested dsh-rho prototype: analyse in dsh, show the outputs with existing Rho components, select a result and continue the original conversation. It follows the native plugin example in dsh-context and the installed dsh 0.2.1-rc.5 public APIs. The result is a local package, not a published npm or signed distribution.

What was built ​

The application adapter lives in the 0.0.1 adapter. Its Cordis host registers rho_present and an authenticated result-reading route; its browser entry contributes Rho to dsh's conversation.view slot. Native session identity supplies both the tool's caller and the view's result scope. dsh owns analysis, permissions, tools, model and history. It is not started as a second Agent inside Rho.

The selected owners are Files 0.5.0, Tables 0.5.0, Media 0.4.0 and Contracts 0.4.0 from Rho-plugins commit 1173789010e4679180804aa309e661b218198f70. Their public APIs, TableView and MediaView are consumed unchanged. The adapter supplies composition, session archives and a transient selection port; it reuses Rho's existing POSIX writer lease. No Core or Rho-plugins source changed, and neither the Core Host nor the Rho backend is started.

rho_present captures completed project files. CSV columns and types are explicit; row selection needs a unique string key. Questions resolve those keys against the captured version, then use dsh's native revision-checked draft insertion and normal Send action. A question can be read or revised before sending. Closing the view, reading a result and reconnecting do not execute analysis.

Failures that changed the implementation ​

  1. Loading an absolute package directory as a host module failed with an ESM directory import error. The source fixture now resolves the package by name; delivery uses an ordinary tarball installed by dsh plugin.
  2. The first model session used dsh's retained default workspace instead of the disposable folder. It found no input and did no analysis. The fixture now explicitly creates/selects its workspace with dsh's public controller. The installation instructions require choosing the matching folder in dsh.
  3. Comparing the browser Origin with the handler's internal request URL rejected valid result reads. dsh uses a carrier-neutral internal URL. The adapter now relies on the connection service's authenticated /api boundary and retains the cross-site refusal; it still validates original session and project scope.
  4. Files' captured resources name archive paths. Routing those paths back into the analysis project made four initial store checks fail. The adapter's path provider now resolves captured internal paths in its archive and ordinary paths through Files' project containment. All five store checks then passed.
  5. An exclusive lock file survived the first owned-host shutdown. Reusing Rho's kernel-held writer lease removed stale-unlink/PID-reuse recovery. A second writer is refused, and the installed plugin reopened the same archive after both normal shutdown and an abrupt kill of its owned dsh process.

A browser assertion initially read an empty draft before asynchronous insertion completed. Waiting for the native Chat view switch resolved the observation; the same captured values were then verified. No analysis prompt was resent. Package assembly also caught nested AG Grid package metadata without adjacent licenses; notices now come from each actual bundled dependency root, including ag-stack. An installation-guide dry run also showed that npm --prefix ... pack selected the root application. The verified command now names npm pack ./adapters/dsh-rho.

What this establishes and what remains ​

This observed episode establishes the requested local loop with reused components and one native dsh conversation. The adapter is deliberately one-project and one selected dsh release candidate. It has no general Studio, notebook, live variable inspection or automatic output discovery. Row selections are transient, image questions carry references rather than pixels, and a question's structured context is visible in the native draft. React comes from Harness; broader compatibility with the components' declared React peer version is not established by this run.

The 0.0.1 package README names the budgets, configuration and refusal behavior. Invalid table content can leave a bounded captured file unlisted. There is no silent deletion of earlier results or automatic replay of unknown work. Independent researcher use, Desktop/TUI entry points, Windows locking and public package distribution remain untested.

Reuse the whole Rho application ​

2026-11-05. The user asked to reuse the existing Rho at the lowest integration cost. Inspection of Harness 0.2.1-rc.5's installed MCP client and bundle reference, and its public bundle documentation, showed that a bundle can contain configuration without Host or Client entry code. Rho already supplies the project grant, stdio MCP bridge, full WebUI and frozen review-context handoff. These existing boundaries were sufficient for the flow.

The 0.1.0 adapter now contains two configuration files, README and license. Its patch mounts Harness's existing MCP client and runs rho --mcp with an existing agent connection file. It adds no tool implementation, browser entry, service, result archive, Skill copy or model configuration. The previous 297 lines of runtime TypeScript, build script, lockfile and obsolete store tests were removed. No Core or component source changed. Rho's WebUI stays in its own window; its iframe policy was not relaxed. Unlike 0.0.1, returning a question requires one explicit copy/paste into the original Harness conversation.

Desktop installation and visible entry points ​

2026-11-05. The user installed the connection-only bundle and found no Rho tab or button in Harness. The missing entry was visible in their screenshot. Version 0.1.2 adds Rho to conversation.view and sidebar.panellist, both opening a small launcher. A small Host route reads at most 64 KiB from the chosen agent connection file, extracts its local service address and project ID, and returns only the project URL. Credential fields never leave the Host. It refuses remote or credential-bearing addresses, missing project scope and oversized files. The launcher neither starts a service nor submits analysis. The existing MCP entry and four tool names are unchanged. React comes from Harness; only the launcher is built, with esbuild 0.25.12. No Rho component code is bundled or modified.
