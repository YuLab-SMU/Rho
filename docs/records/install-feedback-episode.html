Setup reports: Windows with Codex Desktop, a Linux sandbox and a security warning ​

Updated 2026-11-09. Three reports about the setup page arrived on 2026-11-08 and 2026-11-09: #114, a first install by Codex Desktop on Windows 11 that stopped after npm install; #115, an install by another client in a Linux sandbox whose service had gone 12 hours later; and the user's report that Huorong (火绒) frequently flags a Start-Rho.ps1 as HEUR:TrojanDownloader/PS.NetLoader.ae. The user asked how to resolve them. This episode traces each item to its owner, changes Rho, and follows the page again.

The security warning ​

The name is Huorong's heuristic class for a PowerShell network loader, not a signature match. The page caused it. From Git Bash it told an Agent to write each PowerShell block to a .ps1 file and run it with powershell -NoProfile -ExecutionPolicy Bypass -File; one block downloaded the Skill's eight files with Invoke-WebRequest, another removed a log, started cmd.exe with Start-Process -WindowStyle Hidden and polled the log. A script that bypasses the execution policy, fetches files and starts a hidden process is what a PowerShell downloader looks like. Each Agent wrote its own file, so every user's had different bytes and a different hash, and no reputation or allow-list could form: hence frequent rather than occasional.

A signature or allow-list would not fix that. The page now has no script: Rho itself does what the script did, and an Agent runs plain npm.cmd and rho.cmd commands.

The script didNow
-ExecutionPolicy Bypass -File on a written .ps1Nothing to write; the page says not to write the steps into a file or change an execution policy
Invoke-WebRequest of eight Skill filesrho --install-skill DIR copies the Skill from the installed package
Start-Process cmd.exe -WindowStyle Hidden, the log removed first, a polling looprho … --background
A loop reading connection.json and requesting the addressrho --status

This has not been tried against Huorong: there is no Windows machine or Huorong here.

Changes ​

Rho (src/background.ts, src/cli.ts, src/connect-cli.ts):

  • --background added to a start runs the same start detached with its output in <state>/rho.log, renames the last log to rho.previous.log, and returns once the ready line appears, printing it first, then the process, the log and how to check and stop it. A start that ends first prints its output and exit code; a state already running is refused before anything starts. On macOS and Linux the service gets its own session. On Windows it runs under cmd.exe /d /s /c "… > log 2>&1", started with no window and no inherited handles: cmd gets a console that shows no window, which the service and the console programs it starts share, and the service is outside the job that ends cmd when the command returns. Arguments containing " or % are refused there.
  • --status [--state-dir]: running or not, address, process, whether the address answers, the log, a note on how the last service ended, and the other services announced on this machine.
  • --install-skill DIR copies skills/rho from the package, refusing a folder that holds another skill; --version.
  • The {"shutdown":…} line adds by (rho --stop, SIGTERM, SIGINT, SIGBREAK) and at.
  • --open reports a missing display and a failed opener.
  • rho connect treated one state folder named through a link as two services and refused ("More than one running Rho…"). Found below; it now compares real paths.

Pages: SETUP.md uses these commands and has no script on any system; the Skill's install, troubleshooting and connect references follow it; the site build no longer requires the page to list the Skill's files; Headless and the documentation's start page describe the commands.

Checks: launcher-background.test.mjs starts, checks, refuses a second start, stops, restarts, kills from outside and fails a start, with --open on a Linux runner with no display; it also installs the Skill over an earlier copy and next to another skill. A command that held its caller's output open would time out there. The connect test names one state through a link and fails without the change. CI's installed check runs --version, --install-skill, --background, --status and --stop through the installed rho and rho.cmd. The packer requires skills/rho/SKILL.md.

Not done ​

  • No Windows machine, Huorong or Codex Desktop here. Whether Huorong stops flagging, and whether Codex Desktop's sandbox lets a background Rho outlive the command, are unobserved.
  • The page goes to the site with the next npm release: its steps 4 and 5 need commands that 0.5.7 lacks. The front page's terminal fragment is the 0.5.3 run of the old steps and is recorded again then.
  • setup.md is still served as text/markdown.
  • The Linux sandbox's 12-hour end is not reproduced; --status can only say that the log has no shutdown line. Rho gives no service-manager unit for keeping it running across restarts.
  • No pre-install diagnosis command: Rho cannot run before npm has installed it, so those checks stay in step 1.
