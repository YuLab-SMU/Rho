An outside Agent opens a folder with Rho and works in it ​

Updated 2026-11-10. The user asked an Agent in WorkBuddy (5.9.3) to "使用rho 启动该项目" in their own airway project, ~/Projects/气道平滑肌-地塞米松, then to make a new workspace with an illustrated analysis, then "Draw the volcano plot in the notebook; I will select the genes I care about." The user found it slow, and asked for more guidance for people (that Rho is a page in the browser) and for Agents (to start Rho quickly), with the user's scenario simulated to find what hurts. This episode reads that session, runs the same requests with parallel trials, changes Rho, and runs them again.

Trials ​

scripts/outside-agent-trials.mjs gives a fresh Claude Code (claude -p, model westlakehpc/glm-5.3-flash, Claude Code 2.1.319 to 2.1.321) a copy of the airway project in a throwaway home, rho on PATH from this checkout's build, and its shell and file tools with nothing to approve; open is replaced by a recorder. Variant bare has only rho; skill also has the Rho Skill this checkout ships in ~/.claude/skills/rho. Runs go in parallel. The volcano case first runs rho open --no-browser, as if the person had asked earlier, so it starts with Rho running and the project open, and without Rho's tools in the session, as in WorkBuddy.

What was changed ​

  • rho open [FOLDER]. Uses the running Rho that has the folder, else the one for --state-dir (~/Rho/state), starting it in the background with ~/Rho/projects as its projects folder when nothing runs there. It opens the folder as a project where it is, opens <url>/#project=<id> in the default browser and prints what to tell the person: that Rho is a workspace in their web browser, what is on the page, that no account or code is needed, and how to stop it, then how an Agent works there. A folder outside the projects folder is opened by project.open with its full path, which only the state's operator credential may name; it becomes a project of the person's own tab, as a folder chosen in the system dialog, and stays theirs after a restart. Earlier Rho versions refuse the full path, and rho open says what to do then.
  • rho tool index|resolve|call|read|list --as NAME. Rho's four Agent tools from a shell. It grants the project to session NAME as rho connect does, starts rho --mcp on that grant for one call and prints the tool's reply, so the work is the Agent's session's, as over MCP.
  • rho --help opens with what Rho is and rho open, --status and --stop, then the Agent commands; plugin development moved under "Less common". Every Agent observed, WorkBuddy's included, read the help first.
  • .rho/README.md. Rho writes it when it holds a project. It says the files there are internal and names rho open, rho tool and rho connect.
  • The Skill starts with rho open when the person asks to start or open Rho, without the install checks, then what to tell the person, then rho tool when the tools are not loaded, Notebook cells rather than separate scripts, and the page's address in each report. The setup page's closing report leads with the browser page and names rho open. A --background start prints a line saying Rho is a workspace in the browser.

CI ​

CI 42736131288 on 553b7f78: the first attempt failed only in Test win32-x64, where agent-observation.test.mjs ("browser observes only its project…") got host_unavailable with os error 2 on the project Host's named pipe. The rerun passed every job, and the installed check ran rho open on a folder outside the projects folder and rho tool index through rho/rho.cmd on the four platforms, in about 1.8 to 2.7 s. The failure is Core's: on Windows IpcListener::bind creates no pipe, the accept thread that serve starts after printing its ready line makes the first instance, and each next one only on its next loop, so a client right after ready, or between two connections, can find none (read in Rho-core 8bed8ef). It is open work for Rho-core.

Not done ​

  • WorkBuddy's desktop app and model (Hy4) were not run again. The trials here use Claude Code; the WorkBuddy connector episode runs WorkBuddy's own agent core with another model.
  • The workspace request (workspace, rendered report, figures in views) was not repeated. Whether rho tool leads an Agent to markdown.reader is unobserved.
  • rho open and rho tool were run on macOS only; Windows (rho.cmd) runs in CI.
  • No person has used the opened page from these trials; the trials count what the Agent said.
  • Half the volcano answers still do not give the page's address. The note and the Skill only ask for it; nothing in a Notebook cell's reply names the page.
