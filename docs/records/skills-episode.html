Project skills ​

The request (2026-10-31): from a team discussion, a skills module. Skills record how analysis is done; a skill changes as it is used, and each person's case differs; skills are the Agent's notebook; errors and improvements should adapt them to the person and their environment; a seed skill is any skill not yet aligned with the person and the environment. The first stage built here is the project's own skills and the management of their changes. Seed skills and learning from failures come later, from what this stage shows. Rho-plugins owns the skills (Skills 0.1.0); Rho owns the page and the Overview's section.

What a person and an Agent can do now ​

  • Skills are files Agents already read. A project skill is a SKILL.md in the project's .claude/skills/<name>/, with a name, a description of when it applies and its text. Claude Code loads that folder by itself; other Agents read it through Rho (skills.list, skills.read). A skill written by hand or by an Agent's own file tools is listed like any other, with a problem when Agents could not load it (a frontmatter that does not name it or has no description).
  • Every change is recorded with who, why and from what. skills.change writes a new skill, a new text or a removal on the version the writer read (expectedVersion; a stale one is refused) and keeps the author, a one-sentence reason, the evidence (a Notebook cell, a file, the person's words as a note, a Rho conversation, an annotation or a place) and both versions. The same changeId from the same caller returns the same change and never writes twice.
  • Undo is a change too. skills.undo puts a skill back as it was before its newest change while the file is still as that change left it, and the undo can be undone.
  • Edits outside Rho are seen, kept and not overwritten unrecorded. A file that differs from the last recorded version reads as changed outside Rho, with what changed. Before Rho writes over it, it is recorded as it was found, as a change by outside.
  • Limits name what they protect. The Agent's context and the project's state folder: at most 24 skills, 32 KiB each, 1000 changes kept (the oldest go first, counted), 20 changes per read (50 at most) and 400 lines of difference (the rest counted as cut). A change past a limit is refused with the limit's name and the skill stays as it was. Links are refused.
  • The Agent's guidance (skills.project) says to list and read the skills before analysing and follow them; to record when the person corrects a method or says how they work, when a failure's cause and fix are found, or when an accepted choice changes results; never to record results; to record a rule in the person's terms and scope; and that a skill grants nothing.

The Skills page and the Overview's section are described in Frontend.

The episode ​

The pa14-qs case (in Rho-cases, a local repository beside Rho; see A study on a lab server) asks one paper's study of Agents that have Rho's tools only (Claude Code, no shell, no user settings or skills), its data on a disposable lab server. run.mjs --teach --again adds the person's side: after a step's answers, the person states how this project works, in the same conversation (a method statement from steps.json, never an answer); then the same steps are asked again, each of a new Agent, without notes. The notes for steps 1 and 2 were written knowing where earlier runs differed from the benchmark's conventions (a proportion as a fraction, the strains grown alone in the frequency fits, a mix as a ratio), so the grades measure what carried over, not analysis skill.

  • Every Agent listed the project's skills in its first turn, before its first cell. The first index's owner summary ("Skills are how work is done in this project…") was enough; nothing told them to in the prompt.
  • After each note the Agent recorded it and told the person where to see or undo it ("You can see or undo the change in Rho's Skills panel"). The reasons are the person's statement in one sentence.
  • The step 2 Agent widened a rule. The person said to give a mix "by the frequency of one strain, not as a ratio"; the line it recorded reads "write '83% ΔrhlI', not '5:1'", folding in step 1's percentage rule. The new Agent then gave a frequency as a percentage where the benchmark counts a fraction, and a mix as a frequency where one question counts a ratio. The rules carried over, including where they did not apply.
  • With no Rho conversation of their own, the Agents filled conversation evidence with descriptions ("pa14-qs co-culture bix-41/bix-54 follow-up"). The page made those chips buttons that would open a conversation Rho does not have.

On the page the widened line sits directly under the chip with the person's words, so the gap between what was said and what was recorded is visible beside Undo.

Changes, each in its owner: the guidance (Rho-plugins) says to record a rule in the person's terms and scope without folding another rule into its examples, to give the person's words as a note and to use a conversation reference only with a Rho conversation id. The page (Rho) shows conversation evidence Rho does not hold as the Agent described it, not as a link.

Checks ​

  • Rho-plugins: the skills test (create, idempotency and conflict; an outside edit seen and kept; undo, removal and its undo; limits and links; hand-written skills) 5/5, and the whole suite.
  • Rho: the contract check (131 operations); the pages acceptance with a Skills step (an Agent's two changes, the Overview's row opening the skill, Undo putting the file back, no overflow or unnamed buttons at four widths); ui:u2, person-files, agent-canvas, graph, agent-page, agent-ui and sources acceptances. The full suites' counts are in Status.
  • The page was read at 1440, 1024, 768 and 390 px with made-up skills and with both runs' skills.

Limits and open questions ​

  • Seed skills, and records made from failures without a person's note, were not exercised: every recorded change in the episode followed what the person said.
  • When a standing rule and the wording of a later request disagree, the Agent followed the rule and said so. Whether the request should win instead is open.
  • Claude Code's own loading of .claude/skills was not exercised: the case's Agents have no tools besides Rho's. Codex and other Agents read skills only through Rho.
  • An Agent outside Rho's conversations is shown as "An Agent"; its granted session's name is not shown.
  • The server's skills (from serverctl) are listed read only; they are the person's, not the project's.
  • One person, one project and scripted notes. Whether people read the changes, and undo the ones that went too far, is not observed.
