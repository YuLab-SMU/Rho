Historical record

This page records what happened on a date, with its observed failures and limits. It is not a requirement for the current implementation. Current behaviour is in Status.

Result review and retained evidence ​

The 2026-10-29 implementation follows the selected sequence: baseline, immutable capture, result review, historical Graph, macOS preview delivery and a separately checked offline reader. The two episodes are airquality selected-row feedback and Python/R agreement with a Markdown report. A human decision records a judgment about named reply/result versions; it neither authorizes execution nor changes files.

Baseline ​

The starting source included Python/R highlighting, a Documents-based Markdown reader, and native command exit, duration and bounded output. These were retained. Baseline owner tests passed 104/104. Application tests passed 223/223 with an explicit unchanged Core binary; a run without Core failed the checks requiring it. The real base-R episode passed after its workspace selector was corrected for the existing English label. Initial dirty diffs and test logs remain in work/review-evidence-implementation/; other local work and the user's service were preserved.

Capture and review ​

Files 0.5.0 captures independent bytes with immutable references, source path, observation kind/time and SHA-256. Registration keeps its original semantics. Documents 0.4.7 snapshots dirty buffers separately with their confirmed version. Agent 0.4.18 keeps the old capture entry and delegates to Files when supplied. Captures assert only which bytes were observed, not what a native process consumed or produced. An old session has no retrospective captures.

Rho starts bounded server-side capture for new Claude/Codex turns from explicit file locations and a final check of identified/changed files. Reload and Graph reads do not capture. Repeated events retain their original identity; interrupted records remain interrupted. Defaults are 8 MiB per snapshot, 64 snapshots/32 MiB per turn, at most two capture workers per project (the initial implementation serializes them), and Files' existing 512 MiB/1024-resource project store. Exhaustion keeps earlier captures and Agent output and records omissions. Selected limits are visible in observation diagnostics and configurable downward.

Annotations 0.5.0 adds whole-resource anchors and append-only human decisions. Needs changes requires a reason. Repeated submission reuses its receipt; withdrawal/correction names the preceding decision. The server supplies the browser author and refuses Agent/operator attempts to make a human decision. A later reply or result version has no inherited acceptance. Format-3 workspace archives retain decisions and captured resource metadata/bytes; older formats refuse collaboration state rather than dropping it. Conversation logs remain outside the workspace archive's existing scope.

Tables 0.5.0 compares explicitly selected numeric field pairs by declared stable keys and namespace, using a full join in the browser. Before/after/delta, row presence, null and zero remain distinct. The old single-field request retains its old result schema. Unkeyed CSV remains previewable without invented row identity. Documents shows the first/last captured code, separately for disk and dirty buffer.

Review is shared by Studio question controls and Graph result links. It retains the question, explicit Agent replies, readable result links, differences and human decisions. A first explicit conversation choice is retained for later sends. Frozen contexts are included in the original conversation message identity. Recording a decision sends nothing; a separate action sends the selected context. A busy/unavailable conversation leaves the draft/intent available for explicit retry. External handoff copies a request and reports that it was not sent automatically.

The real airquality calculation changes May from n=24 to n=26, mean 24.125 to 23.6153846, and August from n=23 to n=26. The controlled ACP/browser episode checks both runtime output and the table comparison, reason entry with Unicode, a lost decision response, exact retry, refresh and retained code versions. It uncovered full-resource objects passed where a ref was required, editing before a draft loaded, lost Review navigation on refresh, and offline overflow; each was fixed and the same episode rerun. It passed at 1440, 1024, 768 and 390 CSS px (work/review-evidence-acceptance/2026-10-29T09-52-37-665Z/). Later checks extend these observations; they do not erase the earlier failures.

Real Claude on the selected Westlake HPC model completed two turns: it fetched the frozen question, changed and ran R, captured a keyed table/figure and explicitly replied; then fetched a human needs-changes context and replied with an explanation. The browser recorded acceptance of those exact references. Native captures survived an overwrite and no Core Host started (work/review-agent/claude-1793266762448/report.json). Codex's first trial was cancelled by an overly narrow acceptance permission selector before context fetch; its failed report is retained. The ACP owner now names an otherwise unnamed permission from the original tool update and recognizes Codex's MCP operation spelling. The corrected real Codex trial completed both turns, fetched both frozen contexts and linked its exact results (work/review-agent/codex-1793267595201/report.json).

A second controlled ACP episode actually runs Python and base R once each, compares their mean of 3 with a Markdown table, retains both scripts/results/report, then overwrites the originals. Captured bytes and Graph references remain readable (work/report-evidence/1793267857010/report.json). This is runtime/capture evidence, not a second model evaluation or a scientific method benchmark.

Historical Graph ​

Graph and offline export use the same buildWorkGraph derivation for selected reported/named/observed relationships. Export omits command text and tool output. Graph file nodes distinguish paths from captured references. A later capture cannot supply preview bytes at an earlier replay time. Legacy/unavailable/limited captures state the gap, with a separate action to open the current file. Edges still name Agent report, command mention or observed concurrent change; none infers production. Selected result focus links back to its review. The browser reads at most six conversations, eight turns each, and draws at most 160 nodes; omitted work is named.

Offline reader ​

evidence.preview/export selects one review and its explicit result/input/capture references, never adjacent files or the whole project by default. The preview shows question/replies, decisions, file names/versions and gaps. The new export directory contains a static index.html, original files and evidence.json written last. It uses no project scripts, plugins, network assets, Agent or original service. Typed previews are bounded to 200 rows/20 columns, text to 64 KiB. Full file bytes remain linked. A missing reader keeps raw bytes and an explicit preview gap.

The export budget is 512 MiB, with bounded file/metadata counts. The original export identity pins the selection; a lost reply does not select today's versions or overwrite a directory. Interrupted output is not marked complete. The read-only rho --verify-evidence PATH checks sizes/digests and inventory coverage without starting a service. Integrity does not establish scientific correctness or authorship. The browser trial closes Rho, moves the project, opens the recipient copy offline, and detects deliberately changed bytes. This milestone is independent of the 0.5.1 installation acceptance.

Remaining observation ​

No independent researcher has used this flow. Arrange a trial in which a researcher finds May/August changes, asks for an explanation, corrects a decision, reopens the same review and reads an offline package. Record completion, misconceptions and requests for help. Browser assertions and developer screenshot review do not prove usability, physical IME behavior, scientific validity or Windows/Linux support.
