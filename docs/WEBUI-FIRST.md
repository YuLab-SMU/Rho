# Rho 首版交付清单：npm + 本地 WebUI

Updated: 2026-10-15

本文是首版功能、优先级、依赖和完成条件的详细来源。
[Status](STATUS.md)记录当前实现与验证事实；[Roadmap](ROADMAP.md)记录阶段顺序。
下列应用任务均为**待办**。R1–R14 的设计修订与连续状态序列见
[设计清单](DESIGN-PRIORITIES.md#r1r14-连续交互索引)，等待用户复核；
设计修订不代表应用、Agent 接入或安装验收已经完成。

实施顺序调整为[后端先行](BACKEND-FIRST.md)：先交付公共契约、本地服务和插件 headless 能力，
由真实 Agent 与无 UI 客户端完成验证，再独立开发界面。下列 WEB 任务仍是产品任务与发布条件；
BP-01 至 BP-06 只是这些任务中后端部分的工作包，不把 UI 验收从 P0 移除。

## 交付范围与责任

首版交付可安装、可完成真实分析闭环的本地单用户产品：

`npm 启动器 → 本地 Rho 服务 → Rho-core 公共 CLI → 实际功能组件 / R`

浏览器连接本地服务，呈现 Agent 交互、代码、数据表和图形。
一个浏览器窗口内的标签、分屏、布局恢复和最小 Agent 组合界面属于首版。
关闭或刷新浏览器只结束观察，任务与 Host 的生命周期遵循[执行桥](EXECUTION.md)。

| 来源 owner | 本轮责任 |
| --- | --- |
| Rho | npm 组装与启动、本地服务、项目可见性、窄接口、布局、共享交互路由、应用验收 |
| Rho-plugins | 实际 Agent 与模型循环、编辑器文档服务、文件/表格/图形/分析组件、原生依赖声明、功能结果与检查 |
| Rho-core | 公开受管执行契约、请求与原生身份、保留的执行事实、resident Host、公开 CLI |

三个仓库保持独立。Rho 选择明确版本的公开组件，不复制功能实现；应用与安装器检测自己的启动依赖，
在项目内选定组件/动作后，再于该能力处按其声明检查并准备所需环境。
分析组件声明并解释自己的 R/分析包要求；
检查只说明所选能力的实际范围，不能据此宣布整个项目环境就绪。Core 不承担产品 Agent 或全部科学环境的管理。

## 首先冻结的选择

首版交互方向已选为外部 Agent，Rho 不复制外部聊天。下表实际组合仍在 WEB-01
完成前**待选和待验证**，不将画板中的参考会话、示例命令或包名作为已有产品接口。

| 选择 | 需要记录的结果 |
| --- | --- |
| 一个首版 Agent reference adapter | 按已选外部入口确定实际产品、接口/版本、凭据方式、上下文传递和已验证能力；画板以 Claude Code 会话作参考 |
| Node / npm | 支持版本、npm 包名与命令名、安装与升级方式、包名发布权限 |
| 首发平台与浏览器 | 一个明确 OS/架构和浏览器版本范围；其他平台的未验证状态 |
| Core 产物 | 选定公开版本、平台二进制来源/摘要、随包或显式定位策略、兼容性诊断 |
| 科学运行环境 | R 版本、真实分析组件及包版本、数据来源、依赖安装与检查方式 |
| 本地服务 | 端口选择、会话建立与凭据保存方式、项目状态位置、资源预算与超限行为 |

首版只承诺选中的外部 Agent 适配器。连续动线从该 Agent 的实际输入入口开始，
WebUI 呈现会话绑定、共享资源、工具动作、参数/结果入口和连接/中断/续接状态；
把显式资源、版本、选区或未保存缓冲交回同一外部会话，不复制聊天或模型配置。
画板中的 Claude Code 终端会话 `7f3a` 是入口设计参考，实际产品支持与能力测试仍待完成。
所需依赖、上下文传递、返回会话及参数/结果的动作随 WEB-01 冻结；
不承诺所有 Agent、MCP 或协议版本兼容。

### WEB-01 · 冻结首版组合和一个实际 Agent 适配器

**责任：** Rho 选择组合；Rho-plugins 选择并交付实际 Agent/分析适配器；Core 提供已声明的公开能力。

完成条件：记录上表全部选择、实际来源与版本、适配器支持边界和未验证项；
用同一个真实分析案例确定输入、组件动作和预期产物，先验证所选实际 Agent 的最小连接。
现有 `agent-eval` 是评测组件，不作为已完成产品 Agent 的证据。
若缺少所需能力，明确归属 owner 和最小补充接口，不绕过公开边界访问 Core 私有实现。

### WEB-02 · 本地启动、项目范围、安全桥与 Host 生命周期

**责任：** Rho；Core 负责所选版本公开 Host/CLI 的行为。

- 早期搭建可打包的 npm 启动骨架，在目标平台验证打包、安装、启动和 Core 产物定位；
  启动器启动本地服务、提供访问入口，服务只绑定 loopback。
- 无项目时首屏只提供欢迎、打开/新建和最近项目，不放服务或环境信息面板；
  产品启动诊断仅在实际启动故障时出现，不增加全局环境页面。
  选择项目后识别可用组件及其依赖声明；仅在项目内选定具体能力后，于该能力处检查和准备
  它实际使用的环境，记录范围、版本与检查时点。
  打开项目不执行脚本，也不通过脚本扫描推定全部依赖；未检查能力不显示为可用。
- 建立独立应用会话，校验请求来源、会话和项目可见性；Core caller 名称不充当身份认证。
  浏览器不持有任意本地文件/进程权限，本地桥只暴露命名操作。
- 规范化路径并检查符号链接后的资源包含关系，链接不扩大项目范围。
  凭据不进入源文件、前端静态包、公开 URL 或诊断输出。
- 打开/创建项目时先观察已有 Host，核对项目；复用不转移其生命周期所有权。
  只有显式启动操作可创建缺少的 Host；读取/重连不隐式启动或恢复运行时。
- 显式退出本地服务按执行桥处理自己启动的 Host，不停止已有用户 Host。
  网页关闭、Agent 会话关闭、取消请求、确认原生停止和 Host 关闭分别呈现。

完成条件：所选平台从已安装的启动命令打开工作台；非法来源/会话、越界路径和错误项目被拒绝；
已有 Host 未被替换或停止。刷新页面与关闭最后一个网页不取消运行；服务退出的实际效果有记录。

### WEB-03 · 连续人机交互动线与状态设计

**责任：** Rho 负责主流程和容器状态；Rho-plugins 负责功能界面及 Agent 行为。

围绕下节连续动线交付可操作原型和状态说明，覆盖正常、等待、失败、断连、未知与恢复入口。
产品 UI 为英文，用户内容保留 Unicode；区分无项目、新项目无运行、已有项目空闲与实际运行中。
使用[Release 1 R1–R14 索引](DESIGN-PRIORITIES.md#r1r14-连续交互索引)复核连续操作；
R7 异常分支独立于主线，旧 S 系列仅作历史。设计修订不替代实际行为验收。
按[产品设计](DESIGN.md)使用 Paper 和用户审阅，复用已认可范围内的设计结论。

完成条件：用户能够连续找到下一步；每个异常都有可到达的继续路径；正常及受限宽度、
键盘/焦点和适用的辅助访问路径有设计依据。静态画板数量不构成本项完成证据。

### WEB-04 · 共同动作、资源和选区契约

**责任：** Rho-plugins 定义具体组件语义；Rho 实现路由、组合校验与调用边界。

实现首个 Action/Resource/Selection/View 消费契约：UI 与 Agent 调用同一组件动作和原生条件；
引用带 owner、项目、资源版本/来源和稳定实体 ID。表格行号、图上像素和当前视图位置不能替代基因身份。
每种资源保留自己的版本，不引入全局科学 revision。
选定具体动作后展示其声明的运行要求；R 分析动作可显示所需 R/包的局部检查，
提交时仍按实际原生条件校验，早先的检查不代替调用边界检查。

完成条件：排序/筛选后仍引用同一实体；过期、缺失或越界引用显式拒绝或要求重新选择，
不会静默作用于新内容。既有授权只做范围、资源和原生条件的机械校验，不增加重复审批；
模型及检索内容不能扩展授权。关闭 View 只释放观察与渲染。

### WEB-05 · 实际 Agent 接入与会话

**责任：** Rho-plugins 负责所选接入及自有 Agent 的会话、上下文、模型循环；Rho 呈现并路由共享状态。

为 WEB-01 选中的唯一适配器交付配置、连接测试、能力识别、项目/会话绑定、工具动作进度、
资源引用和连接失败后的继续入口。外部 Agent 的聊天输入/回复与会话继续使用其实际入口；
Rho 提供从该入口进入参数和结果的动作，不复制外部聊天或假定拥有外部会话草稿。
首版不增加另一份 WebUI 对话；秘密仅按选定方式在本地保存/读取。
运行中的任务不阻塞另一个会话；关闭会话不被解释为取消或停止任务。

完成条件：真实自然语言请求选中实际组件动作并打开类型化参数；用户看得见 Agent 使用的项目、
文件/缓冲区、选区与来源。断开 Agent 后保留 Rho 已获得的结果和自有草稿，重连原绑定不自动重复执行。

### WEB-06 · 共享编辑缓冲与人机共同修改

**责任：** Rho-plugins 的编辑器文档服务；Rho 路由引用、布局和修改呈现。

每个文档只有一个逻辑未保存缓冲 owner；人、Agent 和多个 View 使用同一内容版本及撤销序列。
上下文显式标记来自未保存缓冲还是磁盘版本；Agent 不静默读取旧磁盘内容代替用户当前编辑。
执行未保存脚本时由组件明确记录所用内容及其来源，不把未保存状态伪装成已保存文件。

完成条件：用户修改后 Agent 能看到所选缓冲，Agent 修改后用户可继续编辑、审阅和撤销；
直接动作按授权写入，不同时设置写前审批和写后审阅。审阅接受/撤回后收起已结算 diff。
切换视图不丢内容或撤销；外部写入在保存前产生明确冲突，未保存内容得到保留。

### WEB-07 · 真实代码、表格和图形联动

**责任：** Rho-plugins 的编辑/表格/图形/分析组件；Rho 负责视图组装和选区传播。

使用所选真实 R 组件的可追溯产物，而非演示数组：打开脚本、分页读表、排序/筛选、图形交互和
关联选区。保留原科学文件、数据来源、组件版本、数字与缺失值语义；呈现组件检查的范围与新鲜度。

完成条件：脚本、表格和图形指向同一次实际分析的资源；选中一个基因后相关视图联动，
排序不改变实体含义。可用键盘操作，有适用的图形文本/表格替代；中文输入、焦点、剪贴板和撤销可用。
已有真实产物可用于先实现视图，新执行闭环由 WEB-08 和 WEB-11 验收。

### WEB-08 · 执行中心、未知结果与失败续接

**责任：** Rho 实现公开 CLI 的应用状态机和观察；Core 保留执行事实；Rho-plugins 解释功能结果及错误。

提交前持久化原 caller/request identity。区分尚未送达、运行、执行完成、失败、部分结果与结果未知；
分别呈现执行事实、产物完整性、领域检查和模型解释。显示有界日志的截断、丢失和已获得输出。

完成条件：真实请求产生新分析结果；提交回复丢失、观察断开或浏览器刷新后，通过原身份查找/重连，
证明一次原生派发，不用新身份自动重跑。取消请求与确认停止分别显示；失败可携真实错误和资源引用
进入 Agent 修复，修改仍使用 WEB-06 的缓冲条件。有意新运行创建新身份并保留与原任务的关系。

### WEB-09 · 单窗口多视图与最小 Agent 组合

**责任：** Rho 提供布局与组合校验；Rho-plugins 提供注册视图、类型化属性及实际动作绑定。

交付标签、分屏、折叠和布局恢复，以及无需拖拽的布局操作。Agent 能从有限注册目录增加一个
绑定当前资源/选区的比较或解释视图；用户可继续直接操作。生成描述不加载有特权的任意 JavaScript。

完成条件：编辑/表格/图形可并存并切换，保留草稿、撤销和选区；组件不可用时保留资源引用并提供
恢复入口。合法 Agent 组合可用，畸形/过期/越界描述被拒绝；关闭视图不取消任务。
首版不验收跨窗口移动，这属于范围后移，不表示浏览器绝无多窗口能力。

### WEB-10 · 产物导出、草稿和工作恢复

**责任：** Rho 管工作区恢复与导出入口；Rho-plugins 管文档恢复、实际产物及其 manifest/检查。

提供脚本、结果表、原科学图及所需 provenance 的导出；明确未保存内容的保存/导出选择和目标写条件。
保存原请求、资源引用、布局、已确认的文档恢复内容及其版本，不用布局 JSON 代替文档内容或执行事实。

完成条件：刷新后恢复已确认的草稿与工作上下文，继续观察原任务；正常服务重启可识别既有项目、
保留产物和恢复草稿。突然退出只恢复实际保存到恢复存储的内容，明确未确认部分和未知任务状态。
外部文件变化或组件缺失不覆盖草稿、不伪称资源已恢复；不承诺 Host 替换后恢复 R 内存。
导出文件可独立打开，记录来源和检查范围，缺失/部分产物如实标记。

### WEB-11 · npm 安装、首启和整体发布验收

**责任：** Rho 组装并验收 npm 产品；Core 与 Rho-plugins 分别交付所选公开产物和依赖声明。

从已记录的不可变来源组装前端、本地启动器和匹配平台的 Core；实现版本与原生依赖检测，
启动时检查产品自身要求，实际故障时提供启动诊断；在项目内选定组件/动作后，
再于该能力处检查和准备它声明的 R/分析包等依赖，绑定实际使用的环境。
缺少所需 Node/R/分析包、二进制不匹配和端口占用时给出明确继续路径；
未选项目不展示科学环境已就绪，npm 安装不等于原生科学环境齐备。
记录包、源码、组件和二进制身份、摘要、许可证及显式本地覆盖；公布实际支持范围与失败限制。

完成条件：在所选平台的新环境中，从实际 npm 安装、首次启动、依赖准备到自然语言分析、共同编辑、
多视图、失败修复、刷新续接、导出和恢复完整走通。检查正常/受限宽度、Unicode 输入和辅助访问。
测量冷启动、交互延迟、常驻/峰值内存；为日志、分页数据、绘图量、并发动作、订阅及组合消息分别
记录配置预算和超限行为，保留已有输出和不确定性。源码检查、组件检查、应用验收与 npm 发布/安装
各自留证；检查一个组件不能宣布整体通过。

### WEB-12 · 更多 Agent 适配器与交互便捷功能

**责任：** Rho 与相关 Rho-plugins 组件。

首版后按具体消费者需求增加其他 Agent/协议适配器、会话检索、快捷命令和布局预设。
每个适配器单独声明版本、授权/资源条件、生命周期和验收范围；不以统一入口宣称全部兼容。
完成条件：新增功能有真实用户动线和实际检查，且不破坏首版身份、文档与结果的所有权。

## 连续的人与 Agent 动线

下表是 WEB-03 的设计与 WEB-11 的实现验收主线；每一步都使用同一个选定参考案例。
Paper R1–R14 的逐步入口、下一步、基线和示意边界由
[设计索引与场景台账](DESIGN-PRIORITIES.md#r1r14-连续交互索引)记录。

| 步骤 | 人的入口与操作 | Agent / 系统的可见响应 | 异常去向 |
| --- | --- | --- | --- |
| 1 安装与首启 | 安装选定 npm 包并启动，打开本地入口 | 欢迎、打开/新建和最近项目；不放服务或环境信息面板 | 真实产品启动故障才出现诊断，不增加全局环境页面 |
| 2 打开项目 | 打开已有项目或创建 disposable project，识别组件及其声明 | 显示项目范围、已有文件和 Host 观察结果；未选分析动作时其依赖未检查；项目内所选能力展示其实际环境的检查和准备入口 | 路径越界/错误 Host 显式拒绝；所选能力缺少依赖可准备或稍后处理，保留当前工作 |
| 3 连接与描述需求 | 在选定外部 Agent 入口建立会话，描述当前分析 | 显示连接状态、使用的项目与可引用资源 | 连接失败保留自有输入，提供原会话继续入口 |
| 4 传递上下文 | 选中脚本、表格实体或图上点，交给 Agent | 展示引用和版本，标记未保存缓冲来源 | 引用过期/越界时重新选择，不静默换成别的内容 |
| 5 参数与共同修改 | 编辑参数或脚本，直接采用已授权动作 | Agent 打开类型化参数及所选动作的依赖检查，通过同一缓冲修改并留下可审阅变化；提交前按实际条件确认 | 原生条件不满足或外部写冲突时保留草稿并解释 |
| 6 执行与观察 | 开始分析，查看进度；需要时请求取消 | 原身份提交，显示运行/未知/部分结果，分别显示取消与确认停止 | 失去回复查原身份；真实错误可直接进入 Agent 修复 |
| 7 解释与继续 | 在真实表/图中选实体，询问并继续编辑 | 同一实体联动，Agent 引用实际结果并增加注册解释/比较视图 | 组件缺失或检查未通过保留已有结果并显示限制 |
| 8 导出与返回 | 保存/导出，关闭视图，稍后刷新或重开 | 恢复已确认草稿/布局，观察原任务并显示保留的产物 | 恢复数据不足、外部变化和未知结果分别呈现，不重跑掩盖 |

## 后续客户端与发行边界

桌面安装器、原生菜单、跨原生窗口移动、系统集成、签名公证和自动更新移至后续客户端里程碑。
共享 WebUI、功能组件和本地服务与宿主桥分层；后续桌面复用仍需要自己的实际验收。
其他 OS/架构、独立产品 CLI 二进制及包管理渠道按具体需求逐个平台验证，不由 npm 分发自动获得。
云服务、远程暴露和多人协作不在本轮范围。

正式签名发行里程碑尚未选中；不因此创建 Rho-releases 或宣称签名发行已就绪。
继续遵守[发布边界](RELEASE.md)：源码、接受的应用组合、npm 安装交付与未来签名发行分别留证。
本清单调整交付范围，不改变[架构](ARCHITECTURE.md)的 owner、既有授权、资源条件与执行连续性。
