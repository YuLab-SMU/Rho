# Rho 首版交付路线：npm + WebUI

Updated: 2026-10-14

## 首版定义

交付"可安装、可完成真实分析闭环的本地 WebUI 产品"：

- **分发方式**：npm package，包含前端资源、本地服务启动器和平台相关 Core 二进制
- **运行架构**：浏览器 WebUI → 本地 Rho 服务 → Rho-core 公共 CLI → R / 分析组件
- **验收范围**：单浏览器窗口内完成真实分析，支持标签、分屏和布局持久化
- **后移内容**：桌面安装器、原生菜单、跨原生窗口移动、系统集成、签名公证、自动更新

后续桌面客户端复用 WebUI 组件，增加原生窗口能力。

## 7 个紧缺项目

### P0 — 首版必需（单窗口真实闭环）

#### 1. 首次使用与第一次分析的完整动线

**补齐内容**：
- 打开/创建项目 → 识别环境和数据
- 接入 Agent → 提出需求 → 修改参数
- 执行 → 查看结果 → 继续分析或导出

每一步说明：入口、状态变化、下一步、失败后的去向。

**完成标准**：
- 交付能连续操作的交互原型，再由实际应用跑通
- 用户无需口头指导即可完成第一次分析

**责任归属**：
- Rho：主流程导航、项目管理、状态路由
- Rho-plugins：分析组件、参数界面
- Rho-core：环境检测、执行能力

---

#### 2. Agent 接入与会话工作区

**补齐内容**：
- 一种真实接入方式：配置与连接测试、能力识别、项目绑定
- 会话创建与切换、连接失败和重连
- 对话呈现：输入、回复、工具动作、结果引用、中断状态

**完成标准**：
- 用户说"分析当前数据"，Agent 能找到实际资源并打开对应参数界面
- 现有 agent-eval 是评测组件，产品 Agent 仍待交付

**责任归属**：
- Rho：会话窗口、连接状态、工具调用路由
- Rho-plugins：Agent 协议实现、Skills/MCP 接入

---

#### 3. 人和 Agent 共享上下文、共同修改

**补齐内容**：
- 选中代码/表格行/图上点 → 交给 Agent → Agent 操作 → 用户继续编辑
- 用户看见 Agent 引用了哪些资源、选区和未保存内容
- 修改后能审阅、撤回

**完成标准**：
- 表格排序后，Agent 仍引用同一个基因
- 修改脚本使用同一编辑缓冲区，保留撤销并检测冲突
- 已授权动作沿用授权，不重复增加审批

**责任归属**：
- Rho：选区传递、引用解析、授权记录
- Rho-plugins：编辑器状态、表格实体 ID、图形选择映射

---

#### 4. 真实可操作的代码、表格、图形工作台

**补齐内容**：
- 桌面应用组装（改为 WebUI 服务组装）
- 文件打开、编辑保存、排序筛选、图表选择和跨视图联动
- 参数、数据、图形必须绑定实际组件与产物

**完成标准**：
- 一次真实 R 分析产生脚本、结果表和图
- 选中一个基因能在相关视图中联动
- 键盘、中文输入和剪贴板可用（浏览器环境）

**责任归属**：
- Rho：视图容器、布局管理、选区同步
- Rho-plugins：CodeMirror 6 编辑器、AG Grid 表格、ECharts 图形

---

#### 5. 运行中心与失败续接

**补齐内容**：
- 提交、运行、完成、失败、部分结果、状态未知
- 取消请求和确认停止
- 运行详情分别呈现：执行事实、产物检查、领域检查、Agent 解释
- 错误应能直接交给 Agent 修复

**完成标准**：
- 提交回复丢失或**浏览器刷新**后，仍找到原任务，不自动重复执行
- 已获得的输出保留，失败有明确继续路径

**责任归属**：
- Rho：任务列表、状态持久化、重连逻辑
- Rho-core：请求身份、退出码处理、有界观察

---

### P1 — 首版完整验收（单窗口多视图）

#### 6. 浏览器内多视图与 Agent 组合界面

**补齐内容**：
- 标签、分屏、折叠、布局恢复（单浏览器窗口内）
- 组件不可用状态
- Agent 能用已注册组件添加比较或解释视图，用户可以继续直接操作

**完成标准**：
- 切换标签或分屏不丢未保存内容和撤销
- 关闭视图不取消任务
- Agent 新建视图共享原资源和选区，过期或越界引用得到明确处理

**后移内容**：
- 跨浏览器窗口移动（需原生桌面客户端）
- 拆窗浮动（需原生窗口管理）

**责任归属**：
- Rho：Dockview 布局、标签管理、状态序列化
- Rho-plugins：json-render 组件目录、Agent 界面组合

---

### 发布前

#### 7. 安装、首次启动与整体验收

**补齐内容**：
- npm 安装与启动：`npm install -g @yulab/rho`（或类似）
- 运行依赖检测：Core 二进制、R 版本、分析包
- 环境缺失、版本不兼容和连接诊断
- 记录实际组件版本、性能、失败与支持范围

**完成标准**：
- 在目标平台的新环境里，从 npm 安装开始完成上述完整流程
- 源码发布、集成验收和 npm package 分别有证据

**npm 分发的实际约束**：
1. **运行依赖解决**：包中需要提供或定位匹配平台的 Core 二进制，并检查 R 和分析包
2. **网页关闭与服务停止分开**：关闭或刷新网页只结束观察；本地服务退出时如何处理自己启动的 Host，需要明确策略，已有用户 Host 保留原来的所有权

**责任归属**：
- Rho：npm package 结构、启动器、依赖检测、服务生命周期
- Rho-core：平台二进制、版本兼容性
- Rho-plugins：分析包依赖声明

## 建议执行顺序

1. **先确定第 1 项主线**（首次使用与第一次分析动线）
2. **让第 2–5 项围绕同一个真实分析案例并行设计和实现**
   - Agent 接入、人机协作、工作台组件、运行中心
3. **完成第 6 项**（单窗口多视图）
4. **最后完成第 7 项**（npm 安装验收）

每个项目的交付单位都应包含：
- 连续动线
- 异常续接
- 可观察的完成条件
