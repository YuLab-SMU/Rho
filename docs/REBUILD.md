## 先用现有 CLI 完成真实 R 分析

已选择 [airway / GSE52778 领域消费者](https://github.com/YuLab-SMU/Rho-plugins/blob/main/examples/real-r-analysis/README.md)：
四个供体的配对 RNA-seq，观察地塞米松处理的转录响应，并做四次留一供体敏感性
分析，并用 200 次全基因模型条件模拟观察计数变异。R 实際运行 9 分 23 秒，
原请求接续、取回核验和科学事实验收通过，详见[领域验收](https://github.com/YuLab-SMU/Rho-plugins/blob/main/examples/real-r-analysis/ACCEPTANCE.md)。
真实方法、R 版本、输入、统计拟合与产物归 Rho-plugins 的领域消费者负责。
外部 Agent 经现有 Core CLI 提交，独立等待客户端中断后用原身份接续，核对单次
原生执行、真实输出及取回产物；计算时间来自实际拟合。

验收分为两组事实：Core 对原请求、持有、结果接续和不重派发的现有保证；领域
Owner 对样本配对、模型方向、独立数值复核、产物完整性与科学解释限制的检查。
已有 Iris 试点、Core 夹具、模型 15/16 或退出码不能替代后者。当前 Rscript 原生
进程是一项真实批分析；不把它声称为已恢复交互 R 内存、完成新插件框架或整个
工作台集成。结果与失败见[当前状态](STATUS.md)。

## 根据实测缺口选择能力

每个候选先记录具体动作、实际结果、期望行为、原始证据、责任 Owner 和已有工具
的不足。优先复用 R 包、Rscript、原 CLI、普通文件及 Git；统一名称、目录或可能
的未来需要不能替代实测缺口。现有 Core 足够时直接使用，不增加每种统计方法的
Core 入口，也不把外部工具全部包装成插件。

以下两项是当前已有领域消费者的继续完善方向，不限定插件的整体范围；包数量与
是否需要新原生适配仍由真实缺口决定：

| 优先职责 | 现有路径与扩张条件 | 首个可观察交付 |
| --- | --- | --- |
| R 批分析配方 | Rscript、原 R 包和 RDS 已能承载本轮任务；确需既有交互 R 内存、输入或原对象身份时才选择会话适配 | 明确数据、脚本、参数、原生条件和资源预算，保留模型、版本、失败与部分结果 |
| 科学产物完整性、来源与取回 | 完成标记、manifest 与普通文件工具先完成定位和复制；跨环境取回或可变来源实际失败时才增加机制 | 关联原 run 与实际脚本、输入、产物，独立核对原目录和取回后的字节与科学事实 |

本轮消费端曾因独立核验器未准备好而收尾失败，已经据此补上入口预检；这是分析
配方的具体缺口。暂未发现需要新 R 会话平台、全局产物注册表或重建 Files 的缺口。

另已选择 [Agent 评估与改进插件](https://github.com/YuLab-SMU/Rho-plugins/blob/main/docs/REBUILD.md#agent-评估与改进插件)：
它组织用例、独立试次、证据与候选比较，复用各领域 Owner 的核验器。Core 不承担
模型循环、评分或自动改进；其自身契约回归仍独立运行。首个复用验收覆盖现有 Core
CLI Agent 场景和一个 R 配方的领域检查，不把脚本分析通过声称为模型自主研究通过。
评估与改进分别调用，候选改动有明确范围、预算、开发／验证／最终盲测材料和回退
证据。应用只在选定接入后呈现原试次、检查、限制与候选差异，不用单一分数掩盖
执行失败或科学限制。现有评估工具已迁入[评估插件](https://github.com/YuLab-SMU/Rho-plugins/blob/main/plugins/agent-eval/README.md)，
通过公共二进制调用，R 核验仍由原领域 Owner 执行；候选改进和应用接入尚未实现。
这次迁移不增加新插件框架或变更 UI。

应用的首条选定流程扩展为：自然语言选择实际动作并生成类型化参数界面，使用同一
组件能力；脚本、真实结果表和交互图共享来源与稳定选择；视图可停靠、分窗，未保存
内容、撤销和上下文仍由原 Owner 持有；关闭观察窗口后继续找回原任务，不重新派发。
执行结束、产物完整和科学核验分别展示。三类体验同时进入
[综合验收](TECHSTACK.md#joint-acceptance-flow)，目前尚未实现或做研究者界面验收。
每次交付一个 Owner 的责任，不把中间组件检查当作应用组合通过。

所选主技术方向是 Electron、React／TypeScript、Vite 和 Dockview；编辑、表格、
图形与 Agent 界面作为功能组件，首轮分别选择 CodeMirror 6、AG Grid Community、
ECharts 和受约束组件目录。独立 HTML 的 MCP Apps、Agent 互通、安装和统一发现
按具体消费者接入。详见[架构](ARCHITECTURE.md)与[技术方向](TECHSTACK.md)。
这些选型不恢复旧协议、SDK、锁、Studio／Manager 或替代聊天产品，也不迁移旧内容。
CI 继续暂缓，Mac 物理
断电已排除；残余模型命令组合失败保留，不扩大权限或重复重跑以取得全通过。

## 新实现与旧应用的边界

新 Core 目前提供受管运行库、常驻宿主与 CLI，尚无新 SDK、HTTP/MCP 或旧插件包
契约。旧应用 `sdk/`、`rho.lock.json`、`dev.mjs`、UI 与示例已移入归档。
新应用没有对应替代物或构建入口，不能按新 Core 的 `main` 自动构建或代表它。
真实试用直接使用已验证 CLI 二进制并记录摘要；旧组合收据保留原含义。
独立应用实现和所选跨仓集成需要后续真实交付与验收。

Core 保持通用受管保证；插件拥有任何所选实际功能、原生条件、资源、领域语义和
产物；应用拥有组件选择、装配、共享交互路由和界面，不另建科学执行路径。
同一组件按需在无界面与应用环境使用，不要求 Core 加载 UI 或新增模型循环。
动作、资源、选择和视图是首条流程需要的小边界，没有实现公共 schema 或通用 loader。
独立仓库可暂时不兼容，只有选定集成时才维护
必要公共边界与固定源／产物身份。不刷新旧快照来假装兼容，也不合并归档恢复旧
子系统。实质新 UI 工作按[交互原则](RHO-DESIGN.md)审阅；本轮归档旧 UI，没有实现替代界面。
