Updated: 2026-10-15

首版范围、项目优先级、责任归属和实现完成条件以
[npm + 本地 WebUI 首版清单](WEBUI-FIRST.md) 为准。本文只记录设计需要交付和审阅的
动线、状态与证据；[产品设计原则](DESIGN.md) 约束各项交互，

## 当前设计与证据边界

当前首版设计是 Paper 文件 "Rho · 工作台 v1" 的
["Release 1 · npm WebUI" 页面](https://app.paper.design/file/01M4X13H2YQGGR8NQXE8W0QDQY/p-5-0)
中的 R1–R14。此次按评审修订为同一项目 `rho-airway-03` 的连续状态序列，
统一从外部 Agent 输入和继续会话；Rho 呈现绑定、上下文、动作、参数与结果。
画板用 Claude Code 终端会话 `7f3a` 说明入口，实际适配器、接口版本、凭据方式、
可达能力和不可变组件组合仍由 [WEB-01](WEBUI-FIRST.md#web-01--冻结首版组合和一个实际-agent-适配器)
选择和验证，不能从画板推定已经接通。

"Slice A · Workbench"、"Start · Empty project" 的 S 系列和 S3′ 保留为历史设计输入；
"Archive · superseded drafts" 保留被替换草稿。它们不再承担首版当前主线，
其中旧会话入口、运行编号或数据也不作为 R1–R14 的资源依据。
Paper 自身的 "Connect your agent" 不是 Rho 产品的接入界面。

本轮修订及连续动线等待用户复核。画板和下述台账可供逐步评审；
它们不构成可操作应用、实际 Agent 接入、浏览器恢复或原生输入的通过证据。

## 首版界面与组件归属

| 功能组件（均由 Rho-plugins 提供） | 首版展示和操作 | 必要性 |
| --- | --- | --- |
| Agent 接入 | 外部会话绑定、显式上下文、通过 Rho 的动作及结果引用、返回原会话 | 把人的目标与可见的实际工作接起来 |
| 共享编辑器 | 实际脚本、一个未保存缓冲、Agent 修改、撤销和写入冲突 | 人和 Agent 继续同一份内容 |
| 分析动作与参数 | 实际输入、类型化参数、原生条件和同一个执行动作 | 让自然语言对应到可检查和直接调整的方法 |
| 数据表 | 实际数值、排序筛选、缺失值和稳定实体选择 | 核对结果并传递具体对象 |
| 图形 | 实际数据、联动选择和原科学图入口 | 理解分布、差异与异常，继续追问 |

Rho 自有项目与应用外壳、布局、资源/选区路由、调用边界校验及活动/运行面板的组装。
Core 提供执行事实，组件提供产物、来源和领域检查，Agent 提供标明身份的解释；
Rho 分别呈现这些事实。参数界面供检查和直接修改，已有授权下 Agent 调用共同动作
不再等待重复的 Run 审批。正常工作台优先显示代码、表格、图形和当前步骤；
版本、完整路径及诊断渐进展开。

## R1–R14 连续交互索引

序列的主线为 R1 → R2 → R3 → R4 → R5 → R6 → R8 → R9 → R10 → R11 → R12 → R13 → R14。
R7 是从相关步骤进入的异常状态对照，彼此不是同时发生的运行事实；处理后回到原步骤。
每张画板标明入口、当前动作与下一步，外部 Agent 始终使用同一绑定会话。

| 画板 | 入口与动作 | 可见反馈、资源与下一步 |
| --- | --- | --- |
| R1 首启 | npm 启动本地服务，选择项目并检查依赖 | 显示依赖可用性和缺失时的准备入口；就绪后进入 R2，读取不隐式启动 Host |
| R2 绑定 | 配置、测试外部 Agent 并绑定 `rho-airway-03` | 新项目无历史运行；显示会话、范围与能力，回外部会话提出需求进入 R3 |
| R3 方法 | 外部 Agent 接收首次分析请求，调用共同分析动作 | 绑定脚本与输入，展示 200 次 bootstrap 等类型化参数；已有授权可继续 R4，人可直接调整 |
| R4 提交 | 持久化原身份后提交 run 001 | 等待第一批输出，只观察同一次提交；进入 R5，不把结果区预填为完成 |
| R5 观察 | 查看 run 001 的过程与首批结果 | bootstrap 137/200，临时表/图和检查尚未完成分别标记；完成后进入 R6 |
| R6 首次结果 | 查看 run 001 的真实基线与独立检查 | 16,139 个基因，KLF15 联动；执行、33 个产物、12 项检查与 Agent 解释分开；进入 R8 |
| R7 异常分支 | 从相应步骤检查连接、依赖或执行等异常 | 各状态独立说明保留内容和继续入口；回原步骤，不拼成同一运行的同时状态 |
| R8 导出重开 | 导出 run 001 实际产物并重开项目 | 同一 16,139 行结果、来源和检查范围；只打开保留产物，继续 R9，不重跑 |
| R9 上下文交接 | 选中 KLF15 和未保存代码，交给绑定外部 Agent | 展示实体 ID、资源版本、缓冲来源与实际发送范围；回原会话继续 R10 |
| R10 共同修改 | Agent 修改同一缓冲，人继续编辑与撤销 | 保留修改者和同一撤销序列；外部磁盘写入在保存时显式冲突，进入 R11 |
| R11 恢复与布局 | 解决冲突，确认草稿恢复，切换/恢复布局 | 一个缓冲 owner、已确认草稿、选区和焦点；设计键盘/IME 路径，再进入 R12 |
| R12 失败修复 | 有意新运行 run 003 / `q-0003` 因缺少 ashr 失败 | 错误交回原会话；改用 apeglm，经同一缓冲保存，再有意提交 run 004 / `q-0004` |
| R13 原任务续接 | `q-0004` 提交回复丢失，刷新后查原身份 | run 004 结局 unknown，保留 8,204/16,139 基因的部分结果；不声称仍在运行，不自动重放，继续 R14 |
| R14 注册组件比较 | Agent 用注册 table/scatter 组合比较视图 | 两组件共享含双输入引用的同一连接数据集，按 gene ID 连接 run 001 基线与 run 004 部分 Y；未发起新的原生执行；详情可检查绑定、拒绝和缺失组件引用 |

## 场景资源与状态台账

run 001/003/004 和 `q-0003`/`q-0004` 是画板中的显示编号与场景身份，
不能替代实际组合记录的原 caller/request 和 native identity。基线来源见
[Rho-plugins 科学验收记录](https://github.com/YuLab-SMU/Rho-plugins/blob/main/examples/real-r-analysis/ACCEPTANCE.md)，
其原请求为 `dex-paired-bootstrap-001`，native run 为 `18dd91c642960ec0-44421.1`。

- **基线 run 001：** 参考已有真实 `rho-airway-03` R recipe 及其产物；
  200 次 bootstrap，16,139 个基因，33 个文件、183.5 MB、9m 23s、12 项检查。
  KLF15 的稳定实体为 `ENSG00000163884`，完整结果的 log2FC 为 4.455，padj 为 7.96e-78。
  R5 是同一运行的过程切片；R6 和 R8 使用同一完成结果，不能切换成另一行数。
- **后续修复与部分结果：** run 003/004、ashr/apeglm 修复、丢失回复和比较是设计示意，
  不宣称这些后续操作已在真实应用中执行。`q-0003` 与 `q-0004` 是两次有意执行；
  观察、刷新和重连始终沿原身份，不另建请求。`partial` 表示已获得的数据覆盖范围；
  `unknown` 表示运行结局尚未确定，不能写成确定 running 或 complete。
  run 004 的 `artifacts/shrinkage/results_shrunk.tsv` snapshot 2 含 8,204/16,139 个基因，
  其余 7,935 个基因没有 Y 值，不能补零。
- **比较绑定：** table 与 scatter 共享同一连接数据集，并同时保留 immutable run 001 的
  `artifacts/results/full.csv` 与 run 004 的 `artifacts/shrinkage/results_shrunk.tsv`
  snapshot 2 两个输入引用、各自版本与来源；按稳定 gene ID 配对，
  保留来自同一 run 001 拟合模型、输入与 contrast 的可检查依据。
  缺少 Y 的基因显示缺失，不当成零或完成结果。
  KLF15 在表、已安装的基线 MA plot 和比较视图间共享实体选择，资源各自保留版本。
- **机械拒绝与不可用：** 参数类型错误、过期引用和越界引用分别返回实际调用类型，
  拒绝前不执行组件；它们不是打开比较视图时自动启动的分析。
  可选的 `shrinkage-ma` 未安装时只标 unavailable/unknown，保留 immutable run 001 的
  `artifacts/models/full.rds` 和 run 004 的 `artifacts/shrinkage/results_shrunk.tsv`
  snapshot 2 引用及 Inspect refs / Copy request 入口，不当成执行失败，也不自动重放请求。

## P0：首版必须交付的设计

| 动线 | 设计交付物 | 审阅时必须能演示的场景 |
| --- | --- | --- |
| 首次使用到第一次结果 | 从 npm 安装/启动、打开本地页面、创建或打开项目、检查依赖，到接入 Agent、执行分析和查看结果的连续原型 | 新用户知道当前步骤和下一步；缺失 R、分析包或本地服务不可达时，有明确诊断及继续入口；新项目无运行记录，已有项目可检查历史结果 |
| 真实 Agent 接入与会话 | 一条实际接入方式的配置、连接测试、项目绑定及会话界面；覆盖未配置、连接中、可用、失败和重连 | 接入后说“分析当前数据”，Agent 引用实际资源并打开参数界面；用户能分辨对话回复、工具动作和结果引用；会话切换保留各自上下文，运行中仍可开展另一项工作 |
| 人的上下文 → Agent 动作 → 人接管 | 代码选区、表格实体或图形选择发送入口、引用展示、动作反馈、回到资源、修改后审阅/撤回及写入冲突流程 | 表格排序后仍引用同一基因；Agent 能引用当前未保存内容；已授权编辑通过同一缓冲区发生，用户接着编辑、撤销或处理冲突，不被另一份内容覆盖，也不增加重复审批 |
| 单窗口工作台与视图组合 | 代码、表格、图形和参数视图；标签、分屏、折叠、关闭及布局恢复；Agent 从已注册组件添加与当前资源关联的视图 | 一个浏览器窗口里完成编辑保存、排序筛选、图表选择和跨视图联动；切换布局不丢草稿、撤销和选区；关闭视图不取消任务；无效或过期引用能被解释和处理 |
| 运行、失败与未知结果续接 | 运行列表/详情、动作提交反馈、有界输出、部分结果、取消及停止效果、刷新/断连后的找回，以及错误交给 Agent 修复的连续原型 | 回复丢失时显示未知状态并查找原请求；刷新后重新观察原任务，不自动重新执行；保留已有输出；分别呈现执行事实、产物检查、领域检查和 Agent 解释；修复后的新执行明确作为新工作发起 |
| 保存、导出与工作恢复 | 保存/导出入口、目标写入冲突、草稿确认、刷新及服务重启后的恢复状态 | 实际脚本、结果表和科学图可导出并保留来源；恢复已确认草稿及产物引用，明确未确认或缺失内容；外部写入或组件缺失不覆盖草稿、不触发自动重跑 |
| 输入、可访问性与通用状态 | 各关键视图的空、加载、错误、不可用、部分数据和受限状态；焦点路径、可访问名称、键盘布局命令及图形的文本/表格替代 | 正常、宽屏及受限宽度均能找到操作和反馈；中文 IME、键盘、剪贴板、焦点与撤销可用；无需拖拽即可完成必要布局操作；失败不只剩不可操作的提示 |

所有 P0 动线围绕同一真实分析案例串联。设计引用的组件值、记录和结果应标明是示例
还是实际来源；原型成功与应用实际执行分别记录。
Agent 输入与会话统一为外部入口；Rho 提供绑定、上下文、动作与参数/结果入口。
实际适配器和接口组合仍在 WEB-01 冻结，不把参考会话画面当成已验证接入。

## 每项设计的完成条件

- 交付可追踪的连续原型或带操作说明的状态序列，逐步标明入口、参与者、上下文、
  用户/Agent 动作、可见反馈、下一步和异常去向；单张静态画板不足以完成交付。
- 正常路径、该动线适用的失败路径及人接管的位置可独立演示；记录关联的组件/资源、
  输入条件和未决问题，便于按首版清单逐项评审。
- 在 Paper 中记录设计来源、范围和用户审阅结果；已有认可在其范围内复用。
  这份清单不代表用户已认可后续新增布局，也不要求已授权的 Agent 动作增加运行审批。
- 实现时核对实际组件、代表性数据和宽度，并在实际 npm + 本地 WebUI 组合中验证。
  真实接入、执行、浏览器刷新、缓冲区冲突和可访问性须有行为证据，不能由原型代替。

## 本轮修订的复核重点

按上面的连续索引检查：外部入口是否始终一致；新项目是否无历史；同一 run 001
的进度、行数和结果是否贯穿；共享缓冲和磁盘冲突是否有明确继续位置；
修复新任务与原任务重连是否分开；R14 的两个输入、缺失值与拒绝操作是否可追溯。

设计用户复核和实现行为证据分别记录。参考画板不证明参数已执行、连接已测试、
草稿已持久化或原生 IME 已验证；代表性宽度与实际可访问性仍需在实现组合中检查。

## P1 优化与后续桌面设计

P1 只包含 P0 已可用之后的优化，例如连接配置复用、更丰富的布局预设、
扩展组件目录及更细的快捷操作。不能把首次接入、人机接管、标签分屏、失败续接或
基本可访问性归入 P1 来绕过首版验收。

原生桌面窗口、跨原生窗口移动、系统菜单与桌面集成属于后续客户端里程碑。
届时保留同一资源、缓冲区和任务连续性原则，重新设计并验证原生窗口生命周期；
首版本地 WebUI 的通过不构成这些能力的验收。
