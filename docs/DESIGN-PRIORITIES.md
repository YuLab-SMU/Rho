# Rho 设计优先级

Updated: 2026-10-14

## 当前设计状态

Paper 文件 "Rho · 工作台 v1" 包含初步视觉草稿：
- S1: 无项目欢迎界面
- S2: 新建项目状态（需纠正：同时显示历史运行和结果图）
- S3: 活跃工作界面（需纠正：表格数据未正常呈现，状态不一致）

**这些设计远不足以支撑首发**。首发需要完整交互动线、Agent 接入机制、人机协作界面。

## 紧缺的设计项目（按 P0/P1 排序）

### P0 设计（首版必需）

#### 1. 首次使用完整流程设计

**需要设计**：
- 欢迎界面 → 创建/打开项目入口
- 项目创建：一次性/持久项目选择
- 环境检测与依赖缺失提示
- 首次 Agent 连接引导
- 第一次分析的完整步骤

**交付物**：
- 完整交互流程图（每步入口、状态、下一步、失败去向）
- 可点击原型，覆盖正常路径和 2-3 个关键失败场景
- 用户无需口头指导即可完成第一次分析

#### 2. Agent 接入与会话界面设计

**需要设计**：
- Agent 配置入口（首次和后续）
- 连接状态：未连接、连接中、已连接、连接失败、重连
- 会话窗口：输入框、消息列表、工具调用展示、结果引用
- Agent 找到资源后如何打开对应参数界面
- 多会话切换（如果支持）

**交付物**：
- Agent 接入完整流程设计
- 会话窗口完整界面（含所有状态）
- 工具调用和结果引用的呈现方式

#### 3. 人机协作上下文共享设计

**需要设计**：
- 用户选中内容 → 发送给 Agent 的交互
- Agent 引用了哪些资源/选区的可视化
- Agent 修改代码/数据时的审阅界面
- 冲突检测与解决界面
- 撤销/撤回机制

**交付物**：
- 选区传递与引用可视化设计
- 协作编辑冲突处理界面
- 审阅/撤回操作流程

#### 4. 工作台核心组件设计（修正 S3）

**需要修正/补齐**：
- 代码编辑器：打开、编辑、保存、未保存标识、冲突提示
- 数据表格：**修正表头/数据行呈现**、排序、筛选、行选择、实体 ID 稳定性
- 图形可视化：图表呈现、交互选择、图例、坐标轴标注
- 跨视图联动：选中基因在表格/图形中同步高亮

**交付物**：
- 修正后的 S3 画板（表格数据正常显示）
- 跨视图联动交互设计
- 各组件的完整状态（加载、空、错误、部分数据）

#### 5. 运行中心与失败续接设计

**需要设计**：
- 运行列表：历史运行、当前运行、状态（进行中、完成、失败、未知）
- 运行详情：执行事实、产物检查、领域检查、Agent 解释（分离呈现）
- 提交确认、取消请求、确认停止
- 回复丢失/浏览器刷新后找回原任务的界面
- 错误直接交给 Agent 修复的入口

**交付物**：
- 运行中心完整界面（含所有运行状态）
- 失败续接流程设计（含浏览器刷新场景）
- 错误 → Agent 修复的交互流程

## 设计纠正清单

### S2"Fresh project, no runs"

**问题**：同时显示历史运行（dex-paired-bootstrap-001）和结果图（MA plot）

**纠正**：拆成两个状态
- **S2a: 全新项目**：项目树 + 中间空状态"No runs yet"
- **S2b: 已有项目、当前空闲**：项目树 + 历史运行列表 + 可选择查看历史结果

### S3"Active run"

**问题 1**：底部状态栏写"No run active"，但中间显示运行记录（exit 0 · 9m 23s）

**纠正**：统一状态
- 如果是"已完成的运行"，状态栏应显示运行标识和完成状态
- 如果是"正在运行"，状态栏应显示进度指示

**问题 2**：表格只显示列名（gene_id, logFC...），没有数据行

**纠正**：补齐完整表格设计
- 表头一行，包含所有列名，左对齐或右对齐
- 数据行多行，每行一个基因，列对齐
- 滚动容器，支持大量行
- 行选择状态可视化

**问题 3**：参数区占据大量空白（评审 01）

**纠正**：收束参数区
- 限制最大宽度（如 640px）
- 将执行状态和产物信息放在参数下方，形成紧凑的左侧主面板
- 或将参数区改为可折叠的侧边栏

## 与实现的关系

设计验收标准：
- 可点击的交互原型（Paper 或 Figma）
- 覆盖正常流程和 2-3 个关键失败场景
- 用户能看懂下一步该做什么

实现验收标准：
- 真实 R 分析完整跑通
- 所有设计的交互都已实现
- 浏览器刷新后状态恢复正确

设计与实现应迭代推进，不必等设计完全完成再开始实现。
