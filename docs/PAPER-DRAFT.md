# 按当前科学目的组织人机共享的分析界面：以单细胞差异分析为例

**摘要。** 数据分析工具已经能完成大部分计算，Agent 也能自行编写并运行分析代码，但研究者仍需回答“这项差异在供者之间是否一致”这类判断题。回答它需要的材料——图、供者映射、模型、运行状态、先前的解释——分散在对话、notebook、图表和日志中，各自的阅读入口由固定工作流或人工设计决定；而 Agent 获得的上下文来自对话历史，与研究者正在看的材料不是同一份结构。本文提出一种方法：依据当前科学目的和实际接入的能力，选取材料、组织它们之间的关系、组合可操作的视图，并把这份组织同时用作研究者理解分析的界面和 Agent 继续工作的共享上下文。方法由一份可检查的组织方案、三种必须区分的操作、三种来源有别的共享状态和五个往返操作构成；插件承担信息、算力、环境与视图能力的接入，目的决定怎样组合。我们用一个构造的单细胞差异分析场景说明机制：判断供者间一致性、理解修正分析为何尚无结果、为同一结果准备说明时，界面所需的内容和可用操作不同；本地可计算、远程排队、只有已有结果三种接入条件下的组织也不同。本文不报告实验和用户研究，贡献在于方法对象的表述与相对最近工作的边界论证：生成式界面、共享科学上下文、记忆编辑和可扩展计算接入均已各有先例，本文不认领其中任何一项，而主张它们组合后仍未被说明的那一环。

**关键词：** 人机协作分析；科学判断；工作界面组织；Agent 上下文；单细胞差异分析；插件化能力接入

## 1 引言

一次真实的组学分析很少是一条流水线。研究者在过程中反复判断：图里的每个点代表细胞还是供者，显著性来自哪种比较，读到的是否是修改后的结果，当前解释能否支持所写的结论。这些判断需要把分散的材料联系起来，而这些材料通常由不同工具产生：图表在绘图库里，代码在 notebook 里，运行状态在终端或任务系统里，结论在报告或对话里。

当前的两种默认分工都不直接处理这件事。一种把界面交给预先设计的工作流：视图和控件在设计时确定，运行后填充内容。它稳定，但组织方式与具体判断无关——判断“供者间是否一致”和判断“计算为何没有完成”，看到的仍是同一套视图。另一种把过程交给对话：Agent 写代码、运行、解释，人读回复。它灵活，但形成的材料是对话的副产品，人可以读到解释，却不易沿解释取回它所依据的材料；Agent 的下一步也主要取决于对话历史，而不是研究者此刻正在检查的对象。

本文讨论的是第三种可能：把“当前要判断什么”作为组织依据，形成一份工作界面，并让这份界面的组织本身成为人机共享的事实。系统取得或选择所需材料，声明它们在这次判断中各自承担什么，把适用的视图与操作组合起来，指出仍缺的部分；研究者在其中阅读、比较、修订，Agent 从同一份有对象、有范围、有实际计算条件的表示继续；新结果再回到相应判断。

据此，本文的候选贡献是一套交互方法而非某个界面或某个模型能力：

1. 把“目的 → 组织方案 → 可操作的工作界面 → 有依据的共享状态 → Agent 续接”表述为一组可检查的对象与操作，其中每一步都能指出它的依据、缺口和版本。
2. 用一个单细胞差异分析场景说明这套机制在什么层面对人有意义：判断对象、比较关系与可用操作随目的改变，接入条件（本地、远程、仅有结果）改变界面能显示的内容与可执行的动作。
3. 与最接近的工作正面对照，划出本文不认领的部分，并说明在这些先例之下仍成立的那一环是什么。

本文不报告实验，也没有用户研究。第 4 节的场景是构造的，其中的数据、运行和版本标识只用于说明机制；第 5 节给出会使本文主张不成立的判据与已知代价；第 6 节列出尚未建立的证据。

## 2 相关工作

### 2.1 过程可读性与洞见组织

让生成过程可读是已有明确进展的方向。WaitGPT 把 Agent 的代码组织成可阅读的操作链并展示运行状态，允许改参数、局部追问、修改代码后重跑，也支持按人的节奏回看 [R18](#r18)。AI Chains 让中间步骤可见可改 [R35](#r35)；交互式任务分解把任务切成可检查的单元，并报告了修改传播的限制 [R19](#r19)；Treadstone 让多个分析 Agent 的讨论成为可读界面 [R22](#r22)。InsightLens 进一步把洞见本身作为组织单位：持续提取并修订洞见，关联关键代码、输出和图，按主题导航，并可固定关注的洞见，其提取 Agent 也使用历史洞见记忆 [R21](#r21)。Loops 用来源与可视化支持 notebook 中的探索性分析，覆盖跨周比较与协作 [R15](#r15)。分析来源服务意义恢复则有更长的研究议程 [R01](#r01)。

这些工作共同确立了本方法可以直接使用的基础：过程可读、洞见可组织、检查可停留。它们没有回答的问题是组织的**依据**：洞见如何被提取、按主题如何归类，与“我现在要判断供者间一致性”并不相同；组织单位是已提取的结论，而不是完成当前判断所需的材料、关系与操作。

### 2.2 生成式与意图驱动的界面创作

按意图生成界面也有直接先例。DynaVis 根据自然语言的编辑意图生成可持续操作的控件，把控件连到图表属性和数据变换 [R40](#r40)。DashChat 从需求和对话上下文规划任务，生成 dashboard 的内容、布局和样式，支持迭代与历史回看 [R41](#r41)。Generative UI 按 prompt 生成完整网页与资源 [R42](#r42)。Data Formulator 2 混合界面与自然语言表达图表意图，用 data threads 选择历史状态、分支并作为下一步上下文 [R43](#r43)。

这类工作排除了两种可能的自我定位：按目的自动布局不是新贡献；界面选择成为 Agent 的上下文也不是新贡献——data threads 已经直接给出。它们留下的问题是工作对象：上述系统组织的是视图及其属性、数据变换或页面，而持续科学判断需要组织的是可核对的分析材料与其间的科学关系，并要求这些关系在后续计算和解释中仍然有效。所读版本的 DashChat 明确以静态设计原型为目标并排除视图间交互联动 [R41](#r41)，这不是其局限，只是说明它不处理本文所问的问题。

### 2.3 科学共享上下文、记忆与修订

科学状态的共享与修订同样已有先例。Mycelium 通过有来源的科学上下文图连接观察、解释和假设，并路由给人和 Agent，其补充图 6 记录了人的科学约束进入另一条后续分析的具体轨迹 [R38](#r38)。SEMV 将质疑定位到声明与证据，按受影响范围重算，保留前后报告，并把经核验的经历整合为后续可检索的记忆 [R39](#r39)。Memory Sandbox 提供可查看、编辑、摘要及返回原文的记忆 [R36](#r36)；cotomi Act 把过程整理成双方可编辑、Agent 可检索的工作区 [R37](#r37)；MemGPT 把外部记忆纳入 Agent 的工作循环 [R34](#r34)。

因此“可质疑解释”“保留旧结果”“局部修正”“修正进入记忆”“共享文件与可编辑记忆”都不能作为本文的贡献。在表示层面，本文也不新造来源本体：PROV-DM 已给出实体、活动、派生与修订的表达能力 [R02](#r02)，EVI 已给出声明、证据与质疑关系的表达 [R05](#r05)。

### 2.4 生信判断与统计约束

本文的场景涉及一个已有的科学约束：单细胞差异分析必须处理生物学重复，忽略供者内依赖会产生错误发现 [R25](#r25)。生物信息学中的主张强度、重复单位与变化后复核也已被明确提出 [R24](#r24)；领域关系与统计模型的交互澄清有 Tisane 与 rTisane [R31](#r31)、[R32](#r32)。本文不主张发现伪重复、不主张自动选对统计模型，也不主张“主张需要证据”是新观点。这些工作规定了读者必须理解的内容，本文关心的是这些判断在持续阅读与继续分析之间怎样产生、保存和改变。

### 2.5 插件化接入与异构算力

把不同算力和环境接进同一工作台同样有成熟基础。Galaxy 通过 job runner 插件和目标配置接入本地、集群及其他远程资源，并为执行目标设置环境条件 [R44](#r44)。JupyterLab 的扩展机制覆盖自定义存储浏览、内容与 MIME 渲染、运行会话与内核服务，以及应用界面本身的扩展 [R45](#r45)。由此，插件架构、可定制接入、多种计算后端和可扩展工作台都不能单独构成本文的新颖性。

### 2.6 小结：缺的一环

上述方向分别解决了过程可读、组织可见、界面可生成、状态可共享、能力可接入。它们共同留下的问题是：**当这些能力都在时，由什么决定此刻应该把哪些材料组织成一个可操作的工作界面，而这份组织又怎样成为人机共同的事实。** 现有系统或者以固定工作流决定组织，或者以已提取的洞见、视图意图、页面或对话历史决定组织；这些都还不是“当前科学判断所需的材料及其关系”。本文的方法针对这一环。

## 3 方法

### 3.1 术语

- **科学目的**：研究者当前要判断或完成的事，例如“判断这项差异在供者之间是否一致”。它可来自当前任务与明确的交互上下文；系统推断出的目的应可见、可修正。
- **材料**：分析中已存在或可取得的对象，包括数据、注释与映射、图、模型、脚本、运行记录、输出、文献依据。材料带版本与来源。
- **能力**：接入的信息读取、计算与环境适配，以及相应的视图与操作入口。能力由插件或原生工具提供，其语义归提供者所有。
- **分析单元**：一项分析及其科学问题、范围、方法与理由、运行与产物、当前解释、待解决事项和修订历史。
- **组织方案**：本次为某个目的形成的简要方案——选入哪些对象及其版本、为什么需要、分别用于比较、支持解释还是继续操作、尚缺什么、视图之间如何定位同一对象。
- **共享状态**：人与 Agent 共同依据的那份有版本、有归属的表示，界面与 Agent 上下文是它的不同呈现。

### 3.2 从目的到组织方案

目的先落实为这次需要阅读或比较的关系，再据此选择材料。判断供者间一致性，需要联系细胞与供者、分组与观测、描述材料与统计结果；仅检索包含某个基因名的文件不能完成这项组织。系统可以提出这些关系，但依据必须来自元数据、实际分析记录或双方的明确声明。

组织方案要处理四件事：需要什么材料、能从哪里取得、它们在当前判断中承担什么作用、实际可用的视图和操作是什么。把材料并置之前，还需让它们的观测单位、纳入范围和版本可辨；不适合直接比较的材料可以用于说明差异，而不是被强行画成同一组结果。若某目的所需材料尚不存在，方案应表达“缺少什么、哪一步仍待完成”，而不是为了让界面看起来完整而填入未取得的内容，也不把“未选入”解释成“不存在”。

### 3.3 三种操作必须可区分

同一份界面上的操作看起来相似，语义却不同。移动一个视图只改变布局；把关注范围限定到某个供者只改变阅读焦点；修改纳入条件或比较方式才改变分析范围。系统不能把前两者暗中解释成第三种，否则人的阅读动作会被当成分析决定，Agent 收到的是一个自己并未同意的范围。相应地，“折叠代码”不等于“从分析中移除”，“关闭界面”不等于“取消分析”，“在视图中隐藏”不等于“从共享状态删除”。

### 3.4 共享状态的三种来源与版本

共享状态的内容按来源区分：实际观察到的计算事实，Agent 给出的解释与关联，研究者明确写下的判断。三者可以相互引用，但不能相互替代：进程成功退出不推出结论正确，Agent 的解释不能自动升级为科学事实，研究者的一次阅读也不构成采用。

版本按对象而非全局：每项分析与每个资源各有版本，不引入一个把整个科学项目视为同时更新的全局修订号。人的阅读位置、分析的当前版本、Agent 最近收到的版本分别保留；范围相同不等于结果相同，收到修订不等于已经重新计算，修订被提供也不等于已被 Agent 读取。

### 3.5 五个操作构成一次往返

| 操作 | 针对的输入 | 产生的变化 |
| --- | --- | --- |
| 按目的组织 | 当前目的、可用材料与接入能力、关注范围 | 选材与取得方式、用途与关联声明、可操作布局与缺口 |
| 阅读与探索 | 组织中的材料、比较关系及明确版本 | 展开、定位、比较；区分布局、关注与分析范围三类变化 |
| 修订目的或分析 | 所选对象、目的或判断的修改及适用范围 | 重选材料或更新解释；保留原运行事实与阅读入口 |
| 从共享状态续接 | 当前目的、材料关系、有效决定、计算条件、待做与引用 | 可检查的 Agent 上下文供给，并记录实际接入状态 |
| 随进展再组织 | 新结果、运行变化及其与当前目的的关系 | 补入内容、调整主次，并说明相对所读状态的变化 |

这五个操作不是强制流程，而是往返中的可辨认环节。一次往返可以只包含阅读和确认；修订只在人明确改变分析选择或解释状态时发生，询问“为什么”只产生带归属的解释。

### 3.6 能力接入的位置

插件使系统适配不同信息类型、算力和计算环境，而不必在应用底层固定一种分析栈。本文区分**能力提供者**与**工作界面的组织者**：

| 接入内容 | 能力需要提供什么 | 怎样进入工作界面 |
| --- | --- | --- |
| 信息与领域材料 | 读取入口、实际格式与范围、版本与来源，以及有依据的细胞、供者、基因映射 | 决定哪些材料可取得、哪些能关联比较；对象适配器帮助读取单细胞对象，但不能从文件后缀推断科学含义 |
| 算力与计算环境 | 计算入口、输入与环境条件、真实任务身份、状态与结果；可针对本地或远程环境定制 | 决定当前能继续什么、哪些仍受阻，以及等待与部分结果期间如何支持阅读；不隐藏环境差异 |
| 视图与交互入口 | 适用于所接资源的呈现、选择与操作，以及它们实际作用的对象和范围 | 使材料可按当前目的阅读与操作；人与 Agent 的入口指向同一能力与资源 |

由此有三条约束。其一，接入条件要进入共享状态：当前引用哪份输入、哪些能力可用、计算在哪里运行、哪些事实尚未取得；否则“界面看起来完整”会掩盖实际缺口。其二，插件不必都有 UI：缺少某种视图不等于能力不存在，有界面入口也不等于其所需环境已经可用。其三，具体数据集、疾病比较、统计设计与分析顺序属于项目中的分析选择，不能因为可以定制插件就固化进通用应用。这个分工与 Rho 当前的源归属一致（见 [架构](ARCHITECTURE.md#source-owners) 与 [UI 扩展](PLUGIN-AUTHORING.md)）；完整插件边界见 [Rho-plugins 的能力模型](https://github.com/YuLab-SMU/Rho-plugins/blob/main/docs/PLUGIN-MODEL.md)。

### 3.7 方法对实现的约束

方法只约束什么必须可检查，不规定布局、尺寸或视觉风格。几项约束是实质性的：材料的选取与关联保留归属，模型可以提出但不能把自己生成的关系变成既成事实；组织理由与未决关系可追查，人的修正可以针对“这里还缺一类材料”而不只是针对错误结论；来源身份、可用操作、视图绑定与已有状态由对应能力承接，不由界面凭空制造；界面所依据的状态与 Agent 所收到的是同一批有版本的声明和引用，压缩不能仅凭一次自由摘要决定是否保留人的修订。

## 4 场景走查：单细胞差异分析

以下是一个构造的场景，用于说明机制。数据、运行与版本标识均为假设，不报告实际效应量。

### 4.1 情境与判断目标

设有 6 名病例、6 名对照，每名供者贡献多个单核细胞，具有原始计数、注释和供者映射。研究者要判断一组事先选定的干扰素反应相关基因是否存在疾病相关的表达差异（下称“干扰素表达差异”），并特别关心这项差异在供者之间是否一致。

研究者至少需要分清：图中的每个观测代表细胞还是供者；疾病分组属于哪一级；模型如何处理同一供者内的依赖；结果支持描述、供者层面的关联，还是更强的生物学解释。细胞数不能替代生物学重复数 [R25](#r25)。即使计算完全合理，理解仍有工作要做：细胞级分布图与考虑供者依赖的模型回答不同的问题，“看到图”“知道模型名字”和“理解为何这项结果支持该解释”也不是同一件事。

### 4.2 按目的形成组织

研究者说：“我想判断这项差异在供者之间是否一致，先不要只给我合并后的细胞图。”系统依据这一目的寻找已存在的供者分组、细胞到供者的映射、相应表达材料、模型与结果，把它们组织成支持这项判断的工作界面；研究者无需先知道它们分散在哪些文件、消息或运行里。

组织要表达判断所需的关系：细胞分布与供者层面材料可对照，使用明确一致的供者与基因标识；当前统计解释与其模型依据相连；长日志收进可展开的运行材料。选择某个供者时，相关材料沿明确映射定位到该供者，无法建立映射的视图则说明限制。这里描述的是交互关系，不是屏幕分栏或尺寸。

同一项目的组织随目的改变：

| 当前目的 | 需要组织的材料 | 布局与操作承担的作用 |
| --- | --- | --- |
| 判断细胞分布与供者层面推断是什么关系 | 表达图、供者映射、每个供者的材料、模型与结果 | 让需比较的对象可共同阅读，沿同一供者或基因定位依据，区分描述与推断 |
| 理解为什么修正分析还没有新结果 | 对应任务、脚本与输入、运行状态、已有输出、环境信息与错误 | 把受阻的计算与其依赖放到阅读重点，区分代码已改与结果已生成 |
| 为同一结果准备学术说明 | 当前图表、模型估计与不确定性、纳入范围、方法说明、可引用依据与未解限制 | 使主张与依据可一起检查，保留方法追查入口；不因进入写作就把未决解释变成定论 |

### 4.3 沿关系阅读

假设 Agent 已生成细胞级表达图和一次把细胞视作独立观测的检验，并把这项分析记为 `A@1`。界面连接比较对象、分布、检验使用的观测单位、输出对应的运行，以及 Agent 对结果的解释；尚未核对的支持关系标为 Agent 的解释，不能由系统升级为科学事实。

研究者从“病例组干扰素表达更高”这句话进入依据。关键交互不是再展开全部聊天，而是沿这句话依赖的关系阅读：

| 研究者正在判断 | 需要连起来阅读的材料 | 形成的认识 |
| --- | --- | --- |
| 图里很多细胞是否等于很多独立重复 | 图使用的细胞集合 → 供者映射 → 每个供者的观测 | 分布现象与供者层面推断需分别判断 |
| 这个显著性来自哪种比较 | 结果中的检验项 → 实际模型或调用 → 分组与重复单位 | 能定位统计依据，判断它是否回答原问题 |
| 读的是修改后的结果吗 | 解释所引输出 → 产生它的运行、脚本与输入版本 | 新代码已写、进程已结束、当前解释已更新是不同事实 |

图表、代码和运行仍可使用成熟组件；方法要求保留它们在这项解释中的关系，不要求研究者先读代码，也不要求把一个项目的所有来源图铺满屏幕。阅读可以停留在 `A@1`，Agent 的新活动不会悄悄替换这段解释所引用的材料。

### 4.4 修订适用范围

研究者发现这次独立细胞检验未处理供者内依赖，于是在该检验与供者层面结论的关联处作出修订：

> 这次细胞级检验不能作为本项供者层面关联的统计支持。细胞分布图保留作描述；按供者汇总原始计数，核对当前设计并重新分析。新的关联判断等待新结果。

自然语言是输入方式；系统需要把修订落到已选中的问题、检验和材料上。适用范围来自选择与明确声明，缺失时再澄清，不能仅凭关键词推断“以后所有分析都用同一模型”。本例的汇总选择也不被推广成适合所有单细胞设计的定律。

修订改变三处相互关联的内容：旧检验不再承担这一关联的统计支持；当前解释说明为何需要另做分析；后续任务带着理由和范围继续。旧检验跑过、生成过哪些结果，这些事实保留；描述图可在其原用途下继续存在。

### 4.5 阅读与推进并行：修订找到落点

研究者阅读 `A@1` 时，Agent 可能已补出另一张描述图，使分析推进到 `A@2`。修订仍针对 `A@1`，系统不能用旧视图覆盖整个当前分析，而要比较修订指向的对象与当前版本：

- 若新增内容只是另一张描述图，而修订依赖的细胞集合、供者映射和检验未变，则保留新增内容，把修订接入当前分析，形成 `A@3`。
- 若供者映射或正在采用的推断方法已改变，则并列呈现原指向与当前对应内容，把修订保留为待确定的意见，先确认它现在针对哪项分析，再改变相应状态。

这种比较依据资源身份、明确字段与声明关系，不自动证明两种科学解释语义等价；关系不完整时保留未知。它让人的理解按自己的速度形成，同时使干预落在仍在演化的工作上，而不是停止整个 Agent 等待逐条审批。

### 4.6 成为 Agent 的续接内容

在可以接收新上下文的下一次交互边界，Agent 获得 `A@3` 的简要内容与材料入口：

```text
当前目的：联系细胞分布与供者层面推断；界面按这一目的组织材料。
分析 A，版本 3：当前单核细胞集合内的病例/对照供者比较。
重复单位：供者；本次输入及供者映射沿各自的保留引用读取。
当前解释：旧细胞级检验不再支持供者层面关联；描述图保留。
理由：研究者指出该检验未处理供者内依赖，修订源于 A@1。
待做：按本次选择汇总原始计数，核对设计，运行并解释新分析。
尚未知：修正后的效应与不确定性；目前不能写作新的完成结果。
依据入口：原检验、运行、输出及研究者修订，各有自己的引用。
```

这份内容与人读到的 `A@3` 来自同一批有版本的声明和引用；人可以读更完整的解释，Agent 可以按需取回细节，双方不必读相同像素或相同长度的文本。

接入过程区分“已准备”“已提供”和可观察条件下的“已读取”。不能用一个“已同步”掩盖差别。在途调用不因界面编辑而被追溯改写；无法进入其内部上下文时，显示此次修订尚待后续接入。压缩也有具体对象：可以省略重复日志、完整矩阵和旧分支细节，保留取回入口；不能把当前范围、仍有效的理由、被替代的解释和未完成事项压成一句“已发现干扰素上调”。

### 4.7 新结果回到同一分析

修正分析结束后，输出按实际输入、代码、运行与环境信息关联回分析 `A`；缺失的运行事实仍标为未知。新计算完成形成新状态（如 `A@4`），并不表示结论已被认可。

研究者回到先前打开的版本时，能围绕自己的判断看变化：哪些数据与描述保留，哪种检验被替代，新结果是否已产生，原解释中哪一部分仍待重写。若新模型未支持先前的关联，系统应使“细胞分布看起来不同”与“当前供者层面证据不足”并置可读，而不是用一句总结抹去两者区别。这是假设的解释分支，不是实际发现。系统性标出新增、替换和待核对的支持关系是可以的，从“进程成功退出”推出“新结论正确”则不可以。

### 4.8 接入条件不同，同一问题的工作界面不同

同一个判断目的，在三种接入条件下需要不同的组织：

- **本地可计算**，计数、供者映射与所需 R 环境均可用：信息与运行适配能力提供入口，界面把已有描述、待计算的供者汇总、实际模型及其运行联系起来；研究者可以检查输入与设计，再沿现有任务继续。
- **远程排队**，计数位于远程存储、计算需在集群环境进行：保留同一个科学问题，把数据位置、所用环境、任务状态和已返回的材料纳入组织。研究者可以先检查已有供者信息；排队或部分输出仍是未完成状态，不被排成一份已完成的结果说明。
- **只有已有结果**，仅接入图表与元数据，暂无可用计算入口：仍组织可核对的部分，并指出尚缺的计数或计算能力。人的阅读可以继续，但 Agent 续接时不能把这个缺口压缩成“已完成供者比较”。

改变计算环境后，需要保留问题、供者集合与判断理由的连续性，同时重新辨明实际输入、软件与运行身份；相同方法名不保证结果等价。若界面只增加一个“远程运行”按钮，而没有把这些条件与进展连回当前判断，就没有完成本文所说的组织工作。

## 5 讨论

### 5.1 与最近工作的差别

| 工作 | 在同一场景中已经能帮到哪里 | 本文增加的具体操作 |
| --- | --- | --- |
| InsightLens [R21](#r21) | 提取并修订洞见，关联代码、输出与图，按主题导航并可固定关注 | 从当前判断目的出发选材、组合视图与操作，并保留这份组织供后续分析续接；增量不在洞见整理本身 |
| WaitGPT [R18](#r18) | 代码组织成可读操作链、显示运行状态、局部追问与重跑、按人的节奏回看 | 围绕科学目的组织跨图、表、模型、运行与解释的界面，把有效选择与理由延续到后续上下文 |
| Mycelium [R38](#r38) | 有来源的科学上下文图连接观察、解释与假设并路由给人机；人的约束可进入后续分析 | 把相关科学状态组织成适合当前目的的可操作界面，使探索与修订持续改变双方上下文；科学共享状态与约束传播本身已有 |
| Data Formulator 2 [R43](#r43)、DashChat [R41](#r41)、DynaVis [R40](#r40)、Generative UI [R42](#r42) | 按意图生成控件、dashboard、完整界面；界面选择与分支成为下一步上下文 | 不能认领按意图生成界面或“选择即上下文”；差别在组织对象是可核对的科学材料与关系，且组织要随计算结果和人的判断持续修订 |
| SEMV [R39](#r39)、Memory Sandbox [R36](#r36)、cotomi Act [R37](#r37)、MemGPT [R34](#r34) | 质疑定位到声明与证据、按范围重算、保留前后报告、记忆可编辑可检索 | 不认领可质疑解释、局部修正或修订进入记忆；本文处理的是这些修订怎样改变当前工作界面的组织与后续续接 |
| Galaxy [R44](#r44)、JupyterLab [R45](#r45) | 插件化接入本地/集群/远程算力与执行环境；存储、渲染、会话与界面扩展 | 不认领插件架构与多后端接入；本文处理的是接入条件怎样进入共享状态并改变界面可显示的内容与可执行的操作 |

**不能把这些差别简写成“它们各自只做一件事”。** 上表列的是各系统在所读版本中明确报告的机制；“未报告这项操作”是文献边界，不是不可实现性的断言。扩展这些系统也可能实现本方法的部分内容，那时需要比较的是组织依据、修订落点与续接边界的实际行为，而不是功能清单。

### 5.2 何时本文的主张不成立

几项判据可以直接否定本文的候选贡献：

- 若只需在现有系统上加“自动笔记 + 生成 dashboard + 向模型追加摘要”即可获得同样的协作，则已有工作已经覆盖，本文没有独立增量。
- 若“当前目的”只能退化为检索关键词或固定模板，材料选择与关系声明不产生人可检查的组织，则本文第 3.2 节没有实质内容。
- 若界面组织不能区分布局变化、关注变化与分析范围变化，则人的阅读动作会被误当分析决定，共享状态不可信。
- 若修订的落点只按时间戳取最新版本，而不按对象身份与声明关系判断，则并行推进时的修订会落到错误范围。
- 若接入条件（本地、远程、仅有结果）不进入共享状态，界面就会把未完成呈现为已完成。

这些判据也指向需要的后续工作：在真实项目上实现这条往返，观察人是否因此更容易判断依据、Agent 是否因此在正确对象上继续，以及组织错误、布局抖动和关系维护的成本是否被控制。

### 5.3 代价与风险

方法本身带来具体代价：系统可能误解目的、错选材料或掩盖反例；布局随目的变化可能打断阅读；科学关系的提取与范围维护会增加负担；统一入口可能遮蔽数据与环境的差异；人易读的组织未必是 Agent 最合适的上下文；运行时未必提供可观察的接入位置。因此选材、条件、缺口和更新必须可检查，不能用自动生成消除这些问题。“布局合理”是需要说明的设计目标，不由自动生成或功能可用直接推出。

### 5.4 与当前实现的关系

Rho 的现有记录提供了探索条件，不构成本文效果的证据：能力接入与语义由能力拥有者提供，Rho 负责选择、组合与共享交互（[源归属](ARCHITECTURE.md#source-owners)、[UI 扩展](PLUGIN-AUTHORING.md)）；从过程记录按角色组织材料已有实践（[Process Studio](SIMULATED-PROJECT-EPISODE.md#process-studio)）；共同笔记、界面解释与材料引用已有载体（[项目笔记](SIMULATED-PROJECT-EPISODE.md#project-notes)）；准备、读取与显式回复可以区分（[上下文与反馈](COLLABORATION.md#feedback-and-explicit-response)）；材料与观察缺口可保留（[保留证据](REVIEW-EVIDENCE-EPISODE.md#capture-and-review)、[状态归属](ARCHITECTURE.md#state-and-lifecycle-ownership)）。本文的远程单细胞接入是方法示例，不是已验收的连接器清单；既有情节也不证明系统能对任意科学目的自主选材并形成适当布局。

## 6 局限

本文是方法论文，不含实验和用户研究。场景中的供者数、基因集合、运行与版本标识均为说明机制的假设；没有实际效应量，也没有观察到研究者使用这类界面的行为。文献比较基于所读版本，属于定向核查而非系统综述；比较对象未安装复现，因此不对其效果作评价。

由此，本文能主张的只是方法对象的表述与边界：目的驱动的组织、三种操作的区分、共享状态的三类来源与按对象的版本、以及与接入条件的联系。人是否因此更容易理解分析、Agent 是否因此在正确对象上继续、这类组织是否优于固定工作流或纯对话，都仍需证据。若这些证据不成立，本文的候选贡献应按第 5.2 节的判据撤回或收窄，而不是以功能数量维持。

## 7 结论

当计算和 Agent 都不再是瓶颈时，人的判断仍然需要材料、关系与操作的组织。本文提出把这件组织工作显式化：按当前科学目的选取材料、声明关系、组合可操作视图，把实际接入条件一并纳入，并让这份组织成为研究者阅读的界面与 Agent 续接的共享上下文；人的判断与新的计算结果沿同一批有版本的对象往复。单细胞差异分析的走查说明这套机制具体在哪些地方与人有关，也说明它与生成式界面、科学共享上下文、记忆修订和插件化接入的先例之间的边界。本文不认领其中任何单项能力，主张的是它们参与同一交互方法时仍未被说明的那一环；这一环是否成立，取决于能否在真实项目中被观察，而不是由功能并列推出。
