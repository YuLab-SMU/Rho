# Airquality：选中、提问、修改、比较与恢复

交互规格 v1.1 · 2026-10-25 · 依据 [UI/UX 前端设计指导](../FRONTEND-DESIGN.md)。

本规格把完整设计方向落实到一条真实 base-R 工作流，供设计、前端和 Agent 工程共同使用。它规定下一轮界面应如何呈现，并标明实际能力与缺口；**本文件不新增功能、浏览器通过记录或视觉验收结论**。已执行的行为与限制见 [Base-R episode](../BASE-R-EPISODE.md)，当前进度见 [Status](../STATUS.md)。

## 1. 任务、对象与完成范围

研究者正在查看纽约 1973 年 5–9 月的月平均臭氧结果，注意到 May 只包含 24 条观测。他希望知道原因，并让外部 Agent 将纳入规则从“所有变量完整”改为“臭氧值可用”，重新计算并检查变化。

真实项目起点为 [base-R fixture](../../fixtures/base-r-airquality/README.md)。核心材料如下：

| 对象 | 身份与含义 |
| --- | --- |
| `analysis.R` | 当前文档缓冲与磁盘版本分别存在；某次运行使用的输入另外冻结。保留研究者添加的 Unicode 注释。 |
| 原始 `monthly-ozone.csv` | 该次运行的准确资源与版本；规则为所有变量完整；五个月各一行。 |
| May | 稳定行键为 `month-05`，显示名称为 May；排序位置和可见行号不是身份。 |
| 问题与上下文 | 保存时冻结原表身份、版本、行键及已确认问题；上下文准备、实际读取、显式回复分别有依据。 |
| 新表与 PNG | 新运行产物，有自己的资源身份、版本与来源；通过明确回复关联原问题。 |
| `notes.md` | 普通文档，包含尚未保存的研究记录；多视图共享同一逻辑缓冲。 |

示例问题可使用中文：`May 为什么只有 24 条观测？请只排除 Ozone 缺失值，保留我的注释，重新计算各月结果，并关联新表和图。` 产品控件和状态仍使用 English。

本轮界面目标是让人准确识别对象、交接问题、检查实际修改、比较结果，并在中断后继续。结构化 Notebook、通用自动布局、原生 Agent 聊天和持久的全局“采用版本”不属于这个场景的隐含依赖。需要研究判断时先使用真实笔记。

## 2. 状态序列与阅读重点

| 状态与触发 | 应看到什么、可以做什么 | 必须保留 |
| --- | --- | --- |
| S0 打开项目与原结果 | 可辨认的对象标签、`Original · Complete cases`、五行表及来源入口；代码和笔记可直接返回。 | 每个对象的准确版本；未保存笔记。 |
| S1 选中 May | 行高亮与 `May · Original complete cases` 摘要；就近 `Ask about selection`，数值不被遮住。 | `month-05` 与原表版本；键盘焦点独立于选择。 |
| S2 编辑并保存问题 | 可检查的上下文摘要、问题正文和真实提交动作；保存之后再按实际能力准备交接。 | Unicode、已确认内容、原锚点与原提交身份。 |
| S3 交给外部 Agent | `Copy request` 成功只显示 `Request copied`；准备、取用和回复事实可以分别查看。 | 原问题；等待期间仍可读表、代码和笔记。 |
| S4 Agent 修改与执行 | 实际代码差异、缓冲修改与保存情况、已知运行阶段；详细工具记录按需展开。 | 用户注释；执行冻结输入；当前阅读位置。 |
| S5 回答与产物到达 | 明确关联原问题的回答；以内容和方法命名新表与图；可打开、检查来源。 | 旧结果仍可见或可返回；不自动采用新结果。 |
| S6 打开并比较 | 共同问题标题、两侧方法标签、对齐的表头和数据；窄屏可在准确版本间切换。 | 两份准确引用、各自选择与来源；没有映射时不假装行已配对。 |
| S7 返回、重开或恢复观察 | 回到可恢复的对象与布局；说明保留和未恢复的范围；观察原操作。 | 原请求身份、已确认草稿和未知事实；不重复执行。 |
| S8 记录判断 | 在笔记中记录方法判断和对应结果，继续检查或研究；缺少结构化采用能力时不显示假的 `Accepted` 状态。 | 判断依据与所指版本；完成运行不变成科学采纳。 |

这是一条常见路径，不强迫系统按顺序显示八个步骤。部分结果可以先到，回复可能迟到，连接可能在任何阶段中断。状态必须来自实际观察，不能按动画计时推进。

## 3. 三组关键界面

### 3.1 原对象与问题

工作区标题和对象工具保持紧凑。方法与行数作为内容说明，完整来源进入详情。选择摘要和问题输入使用稳定的局部位置，避免每次选择把表格推下去。

提交前再次检查当前问题的依据；提交后保留冻结锚点。用户换到 June 或新表，不改写已提交的 May 问题。若筛选使 May 暂时不可见，说明被筛选隐藏，并提供显示或清除选择的真实入口。

设计不能把长回答堆在原表上方。持续回答放辅助阅读区，关闭后回到触发它的对象。关闭输入不应无提示丢失已有草稿；具体保留范围按该草稿 owner 的真实契约表达。

### 3.2 新旧比较

共同标题采用 `Monthly ozone — missing-value rule`，两侧分别标为 `Original · Complete cases` 和 `Updated · Ozone available`。同名 CSV 需要方法标签帮助区分。表头、方法说明和首行共享基线，局部工具数量不同也不让数据行错位。

May 的预期描述性结果来自已有独立检查：样本数 `24 → 26`，均值 `24.125 → 23.615385 ppb`（右值为显示近似）。展示精度与原值分开；变化方向不自动标为好坏。科学上是否应改用该规则，仍由研究者判断。

现有 `data.compare` 提供显式表版本、键、命名空间、字段和 join 策略的比较入口。是否适合此任务必须由调用参数及结果验证，不能从相同列名推断。它也不自动提供成对 UI、联动滚动、共同排序或科学可比性。没有可靠映射时显示 `Rows are not aligned`，继续允许独立查看两份表。

共同比较入口和成对版式属于下一轮呈现目标。当前已验证的路径是打开回复中的准确结果，由用户安排分屏；现有能力可复用，不能据此把目标版式写成已经完成。

### 3.3 中断与返回

观察断开时，显示 `Connection lost. Showing the last observed state.`，保留已得到的内容和可恢复输入。`Reconnect` 只恢复观察；不写成 `Run again`，不让无限 spinner 声称原生进程仍在推进。

恢复后按原请求更新实际事实。新结果到达可以提示，但不抢焦点或替换原表。重新打开项目时说明真实恢复范围：已有闭环证明准确版本、选择和已确认笔记得以保留；它没有证明所有排序、筛选或本地滚动设置都会恢复。

## 4. 必须设计的分支

| 分支 | 行为与呈现 | 验证条件 |
| --- | --- | --- |
| 问题提交回执丢失 | 明确待核实；按原身份查询或重试原问题，保留输入。 | 最终只有一个已提交问题，文本、行键和原版本不变。 |
| 上下文已准备但无人读取 | 保留准备事实和外部交接入口，不写 `Agent read it`。 | 没有读取记录就没有读取声明。 |
| 已取用但无显式回复 | 显示取用事实及时间，说明尚未观察到明确回复。 | 时间上较晚的运行、文件变化或普通消息不自动算作回应。 |
| 人与 Agent 先后编辑 | 展示实际版本和差异；遇条件冲突保留草稿与可检查内容。 | 人的注释不丢失；保存条件不能因 Agent 说明而放宽。 |
| 保存回执未知 | 保留当前缓冲和原写入身份，核对回执再更新保存状态。 | 没有确认前不显示已保存，也不盲目重复不同身份的写入。 |
| 布局已变化或视图受保护 | 解释建议当前不能按原方案应用；用户可继续原工作。 | 不覆盖新布局、不移动或重绑定受保护视图；无另起布局引擎。 |
| 新结果部分缺失或检查失败 | 明确已取得部分和失败范围，可检查已有材料。 | 执行结束不遮蔽产物问题，不汇总成绿色通过。 |
| 服务观察断连 | 保留最后事实，恢复后观察原请求；未确认保存不能假装离线成功。 | 该场景的 baseline 与请求修改合计仍只有两次原生提交。 |
| 外部 Agent 不可用 | 说明交接或模型侧状态，按可用能力继续看材料。 | 不把 Agent 不可用误报为本地服务、R 进程或所有数据均不可用。 |
| 原操作结果未知 | 明确不能确认的事实及继续观察入口。 | 不因刷新、关闭视图或缺少回执创建新运行；Host 故障另有验证范围。 |
| 插件或资源不可用 | 保留名称、准确引用和已有内容，说明可用的查看路径。 | 不替换成同名新资源，不自动安装插件或启动运行时。 |

未知、过期和失败分别处理；对上表的错误注入只在一次性项目和自有服务中开展。现有验收中已做过的分支可引用其证据，其余分支在实际执行之前保持待验证。

## 5. 实际能力与实现入口

下表用于定位 owner，不复制或扩展 wire schema。参数、条件与版本以选定组合的[公开操作契约](../../protocol/index.json)为准。

| 设计需求 | 当前入口 | 设计不能据此推断 |
| --- | --- | --- |
| 选择准确实体 | `interaction.selection.read/set` 与 Tables 键验证 | 可见行号是身份；任意两个版本可以互相迁移选择。 |
| 保存问题、链接回复 | `annotation.create/read/list/reply` | 保存就是读取；任意后续操作就是回答。 |
| 准备与读取上下文 | `context.create/read` | 复制等于发送，或取用等于理解。 |
| 检查与修改文档 | `document.open/read/edit/undo/save` | 每个标签可以另建一个缓冲；编辑当前内容等于改变运行输入。 |
| 执行、观察与结果检查 | 既有 `action` 操作及 artifact 检查 | 原生结束、字节完整、领域验证和研究采纳是一个状态。 |
| 打开、安排、保护视图 | 既有准确绑定、`composition.apply/undo` 与 `view.protection.set` | 所有临时视图已持久化；普通布局操作可解除保护。 |
| 表格比较 | [`data.compare`](../../protocol/operations/data.compare.json) 及实际 Tables 结果 | 已有统一比较界面、自动科学映射或同步滚动。 |
| 保留研究判断 | 普通 Documents 笔记与准确引用 | 已有跨报告传播的采用状态或结构化 Notebook。 |

进入实现前先检查选定版本的支持范围。新增的界面信息如果没有事实来源，保留明确的缺失说明；确需扩展能力时在对应 owner 完成并验证，再由 Rho 呈现。

## 6. 设计与浏览器检查

先用同一套真实内容审查原对象、输入、等待、结果、比较、失败和返回；浅深主题至少各覆盖正常阅读、选择、输入与错误。检查 1440 × 900、1280 × 800、1024 × 768，以及 768 / 390 CSS px 窄窗口和放大文字。选有代表性的组合验证，不把只换背景色的截图当作完整状态覆盖。

视觉审查重点：第一眼能辨认对象与方法；主要动作清楚；表格数值未被输入或回答遮挡；两侧比较对齐；局部更新不引起工具栏反复换行；恢复提示可见但不阻断阅读。窄屏使用准确版本切换，关键值仍能访问。

实际操作重点：键盘选中和返回、原生 IME、复制交接、条件保存、版本保持、明确关联的回复、布局恢复、冲突及断连。原闭环的提交计数、身份和独立数值检查继续保留。只改变静态布局时可以复用有效执行证据；影响状态、交接、执行或恢复时重新检查对应路径，明确哪些证据复用、哪些是新执行。

研究者观察重点：能否在无需提示的情况下指出原表方法、问题依据、新结果身份、当前未知项和恢复动作；能否解释复制、取用、回复、完成与采用的区别。记录具体误判和求助；自动化浏览器操作者不能替代目标用户。

## 7. 完成记录

每次本场景交付记录所选源组合、完成范围、实际检查的状态与尺寸、视觉问题及修正、用户观察和领域判断的证据缺口。原型可以完成设计探索，功能实现必须走真实 owner 路径；模拟能力不计入实现完成。
