RHO / PRODUCT DESIGN BRIEF 01 / COMMISSION

Rho：从零设计一套研究工作台

给产品设计师的需求稿。重新设计应用结构、交互语言与插件体系，不以现有页面为实施目标。

一个完整的应用。
进入项目后，拥有自己的工作世界。

两层外壳

主应用与项目内部拥有清晰区分的导航和侧边栏。用户知道自己在哪个层级、哪个项目，以及如何返回。

三种工作模式

Studio 直接操作内容；Graph 理解全景关系；Agent 动态工作面组织任务、过程、结果与介入点。

一套插件语言

共享设计规范和交互习惯，保留每种插件的功能化特色。Agent 对话另有完整的专用组件设计。

委托范围

上述范围来自本次用户澄清。后文将其展开为设计任务、场景和交付要求；具体布局、视觉语言、动效形式与组件细节由设计师探索。

当前前端与上一版 20 页稿均不作为参考布局或验收基线。保留的是不丢工作、状态真实、可追溯等产品行为底线。

RHO / PRODUCT DESIGN BRIEF 02 / USERS & JOBS

用户要完成的工作，决定界面如何组织

首轮面向个人研究者与和 Agent 协作的分析者。多人实时协作不作为本次设计委托的隐含前提。

用户处境需要完成的事界面帮助其回答
跨项目工作找到项目、恢复上次进度、知道哪些工作需要关注。我在哪个项目？哪些状态属于哪个项目？
直接分析与制作编辑代码、检查数据、调整图形、组织研究笔记。我在改什么？哪些内容相关？如何并排检查？
理解研究过程从一个结论追到数据、代码、运行和讨论。它从哪里来？哪些是事实，哪些是建议？
委托与监督 Agent表达目标、给上下文、跟进任务、必要时介入。它在做什么？需要我做什么？产出了什么？
接续与判断切换视角、离开再回来、理解结果并形成自己的判断。刚才选择的对象、输入和工作位置还在吗？

内容模型

Project 容纳研究工作；数据、代码、运行、结果、问题和笔记是可关联的对象。文件是对象的来源之一，不是全部产品信息结构。

视图模型

同一个对象可以在 Studio、Graph 和 Agent 中呈现。视图切换改变看法，不创建另一份工作或另一套项目事实。

设计探索

设计师需要确认对象命名、信息层级和首屏主次。当前页面名称和文件目录树不构成最终信息架构。

RHO / PRODUCT DESIGN BRIEF 04 / NAVIGATION & SCOPE

外壳需求：作用范围要在结构中成立

通过位置、选中态与切换行为体现层级。无需在每个按钮旁重复解释作用范围。

组件 / 范围承担的任务需要画出的关键转场
主应用导航Home、Projects、应用级 Plugins 与 Settings；最终名称由设计师确定。无项目 → 项目列表 → 进入项目；从项目返回。
项目切换与标题始终能辨认当前项目；切换时知道旧项目有哪些工作仍在进行。Alpha → Beta → Alpha；恢复原模式与工作位置。
项目内侧栏概览、Studio、Graph、Agent、资源入口、项目设置。首次进入、展开/收起、内容增加和空项目。
模式内导航Studio 的场景/视图；Graph 的范围；Agent 的任务/会话。切换局部对象；不复制出第三套全局菜单。
查找与定位能找项目，也能找当前项目里的对象、任务与对话。结果显示作用范围，打开后有清楚的返回路径。
上下文与状态选中对象、详情、后台工作和需关注事件。按需展开；不以常驻说明挤占内容。
插件入口按用户任务找到功能，知道它作用于什么对象。打开、加入工作面、不可用、移除后的既有内容。
设计边界

不把当前只有一个侧栏的实现当约束，也不预先锁定宽度、图标、颜色与菜单层数。用完整进入、返回和切换流程证明层级清楚。

RHO / PRODUCT DESIGN BRIEF 05 / MODES

Studio、Graph、Agent 是三种工作模式

同一项目、同一批对象，三个不同的主要任务，需要各自的界面组织。

MAKE & INSPECT

Studio

直接操作内容

Code │ Data │ Figure
UNDERSTAND & CONNECT

Graph

理解全景关系

Question → Data → Result
DELEGATE & INTERVENE

Agent

组织动态工作

Goal → Work → Result
模式主内容 / 主动作跨模式连接
Studio编辑器、表格、图形、笔记；编辑、选择、排列、比较。选中内容带给 Agent；查看其在 Graph 中的关系。
Graph对象、关系、分支、来源和路径；缩放、筛选、追溯、定位。节点在 Studio 打开；路径或对象组带给 Agent。
Agent 动态工作面目标、计划摘要、实际进展、结果与介入点；委托、查看、调整。结果回到 Studio；有依据的关系进入 Graph。
Agent 专用对话组件消息、上下文、输入、步骤与结果。它是交互组件，不是第四种模式。在 Agent 中完整使用，在 Studio/Graph 中连续使用。
共同要求

切换模式保留项目、对象与上下文；分别恢复 Studio 布局、Graph 视角、Agent 当前任务和未发送输入。避免切换模式就像进入另一个产品。

RHO / PRODUCT DESIGN BRIEF 07 / PANORAMIC GRAPH

Graph：看见整个项目，而不是一团节点

全景用于定位、解释和发现关系。必须能从全局概貌缩小到一条可读的证据路径。

Project GraphOverview　 Focus path　 Search

表达什么

  • 数据、代码、运行、结果、问题、笔记等有意义的对象。
  • 输入、产出、引用、派生、讨论等有类型的关系。
  • 历史对象、当前对象与待验证建议有可辨认的状态。
  • 已有关系与 Agent 建议明确分开；连线不能制造科学因果。

允许做什么

  • 查找、按类型/任务缩小范围、折叠分组、聚焦上下游。
  • 节点摘要与关系依据；打开 Studio 或带入 Agent。
  • 从局部回全景，返回保留视角和选中对象。
  • 大量节点仍可使用；提供可键盘操作的列表/大纲入口。
交付重点

展示全景、局部路径、节点详情、筛选、无关系、关系不完整和大项目场景。不能只交一张网络图。图中对象与关系是需求示例。

答案与检查入口

轻量动态入口

人在 Studio 或 Graph 中工作时，用紧凑形态表达相关进展、结果和需介入事项；可展开查看，再收起回到原工作。

  • 状态条、状态岛、局部卡片等是待比较的方向。
  • 明确对应哪个任务；多任务不混成一个总状态。
  • 可静默、收起、稍后查看；重要性与打断程度匹配。

完整动态工作面

在 Agent 模式中，围绕任务组织目标、计划摘要、实际动作、可操作结果与必要输入；按任务组合表、图、表单和说明。

  • 不把所有内容压成聊天气泡或日志列表。
  • 结果直接进入专业插件，也能成为后续对话上下文。
  • 新增内容不抢焦点；显示变化有来源与时间。
动效与真实状态

展开/收起和内容转换有连续性，并支持减少动态效果。只呈现实际状态与可解释的计划摘要，不制造“思考过程”、伪进度或装饰性的忙碌动画。

组件必须覆盖

  • 会话身份、标题、历史和当前任务的关系。
  • 用户消息、Agent 回答、工具/步骤摘要、结构化结果与错误。

RHO / PRODUCT DESIGN BRIEF 10 / APPLICATION COMPONENTS

主应用组件：设计完整的产品骨架

这些是设计系统里的应用组件，服务多个工作模式；不等同于当前代码中的组件目录。

组件组要解决的问题设计稿应展示
应用导航与项目入口跨项目定位、打开、最近访问、返回与应用管理。首页/项目列表、进入与离开、空状态、搜索。
项目外壳与侧栏项目身份、模式切换、资源入口、项目设置。项目完整外壳；与全局导航的关系。
视图与布局容器专业内容组合、焦点、拆分、切换、关闭与恢复。单/多视图、窄面板、隐藏内容、键盘替代操作。
对象摘要与上下文选了什么、准备交给谁、来自哪个版本。单/多对象、范围、旧上下文、不可用对象。
结果与证据入口结果可读、可操作、可追到生成过程。表/图/代码/笔记、部分结果、比较与来源。
Agent 动态入口与任务容器不离开工作也能跟进；需要时展开完整任务。紧凑、展开、多任务、介入、完成、失败、断线。
Agent 专用对话表达、上下文、消息与继续协作。完整与紧凑形态、输入/流式/错误/历史/结果。
查找、菜单、详情与反馈发现操作，理解状态与恢复途径。搜索范围、菜单、对象详情、局部错误、通知。
与专业插件的分工

外壳管理位置、范围、组合与跨模式协作；专业插件决定内容如何阅读和操作。插件不重复建设项目导航、会话系统与全局通知。

RHO / PRODUCT DESIGN BRIEF 11 / PLUGIN DESIGN STANDARD

插件统一设计规范：一致性要落到交互

统一不只是一套颜色。定义可复用的视觉、行为和组合规则，并用不同插件检验。

需要统一的部分需求保留给插件的空间
身份与外框对象标题、类型、状态、布局菜单与焦点有一致语法。内容标题、对象摘要与专用信息。
动作层级主动作、局部工具、更多操作与高影响操作有一致层级。具体动作及其领域词汇。
选择与上下文选中范围、附带给 Agent 的内容可见且可检查。行、实体、代码范围、画布区域等选择方式。
结果与关系可打开精确对象、查看来源、在 Graph 中定位。领域结果格式、验证方法与解释。
状态与恢复加载、空、失败、部分、过期、只读、不可用有可理解的语法。真实领域条件与对应的修复动作。
输入与撤销焦点、菜单、键盘、组合输入与撤销范围不相互抢占。编辑器、网格、画布等成熟的专业习惯。
主题与密度颜色语义、字级、间距、图标、对比度与焦点表达可复用。密集数据、长文本、大画布的内容密度。
组合与尺寸进入 Studio、从 Graph 打开、作为 Agent 结果时仍是同一种能力。完整、紧凑、只读摘要等合理形态。
设计交付

组件变体、设计 tokens、用法与禁用例，至少三种内容形态的组合示例。本稿不预先指定颜色、字体、圆角或技术框架。

RHO / PRODUCT DESIGN BRIEF 13 / FUNCTIONAL PERSONALITY

插件实例：共同规范下的四种专业性

这些实例用于验证规范是否有用。名称描述功能，最终命名与内容分组可由设计师调整。

Code / 代码编辑

精确编辑 · 对比修改 · 执行联系
  • 代码、范围选择、诊断和修改差异是主内容。
  • 解释、重构、执行代码与查看输出有清楚关系。
  • 共享编辑、自己的撤销、保存冲突与运行快照不混同。

需要画：人与 Agent 的修改对比；执行后定位相关结果。

Data / 数据表

结构与质量 · 实体选择 · 比较
  • 列类型、缺失值、单位、过滤与排序帮助理解数据。
  • 实体对齐比较，显示前后值、差值与未匹配项。
  • 浏览状态与修改区分；大数据保持范围感。

需要画：选择一组实体提问；比较结果与窄面板。

Figure / 图形工作台

RHO / PRODUCT DESIGN BRIEF 20 / REVIEW & BOUNDARIES

评审需求与设计成果，看这些问题

目标来自未来产品需要。实施团队再为选定体验建设能力；当前实现不决定应当设计什么。

必须能够清楚演示

  • 区分主应用和项目内部；进入、返回、切换项目清楚。
  • Studio、Graph、Agent 各有主要任务与界面组织。
  • Graph 能追溯和行动；Agent 随状态变化并允许恰当介入。
  • 对话是完整组件，输入、上下文、步骤与结果连续。
  • 插件既有统一规范，又保留代码、表、图、笔记的专业差异。
  • 跨模式、离开返回、异常恢复，保留人的输入和已获得工作。

产品行为底线

  • 对象有各自身份、版本与来源；没有代表全项目科学正确的“版本”。
  • 同一文档多视图共享内容，保存、撤销与冲突可理解。
  • 任务、消息、重连保持原身份；未确认结果不伪装成功或自动重做。
  • 已有授权按实际范围执行；模型和界面建议不能扩张权限。
  • 执行结束、产物完整、领域检查与 Agent 解释分别有依据。
  • 动态界面组织真实能力与内容，不把视觉效果当执行或授权。
