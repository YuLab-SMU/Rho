RHO / DESIGN HANDOFF 02 / EVIDENCE

从已有结果出发，找出真正需要设计的部分

当前功能已经跑通；本稿重组信息层级，并为缺少的呈现补上明确提案。

实际界面暴露的问题

  • 回答藏在“Explicit Agent response”后，工作区只显示截断的 Markdown。
  • 两张表的首行相差 48 px；用户需要逐格比较，自己找出变化。
  • “Open linked result · 短 ID”没有告诉用户是表格还是图。
  • 390 px 视图把两个版本分到不同页签，比较需要记住前页数值。

依据：2026-10-25 Base-R episode 的评审；本次已复看实际比较截图。

设计判断

让工作区首先呈现问题、答案和变化；表、图、代码与来源作为可展开的证据。统一视图的外框，不统一插件内部的专业操作。

证据级别本稿如何使用
现有能力共享文档、表格/图形、分屏布局、精确上下文、Agent 会话与 Activity、重连。
已有 API，缺少视图Tables 的 data.compare 已有按键比较；本稿设计比较视图。
设计提案答案聚合页、上下文附件呈现、差异高亮、冲突比较界面、窄屏摘要。
尚无所需能力Project Notebook、任意插件热加载、跨原生窗口拖动、通用 R 内存环境。
边界本稿由本次需求新建，不继承 2026-10-25 已撤回的设计稿。画面中的提案没有被写成当前实现或已验证的可用性。
已有的行为约束继续成立：同一文档一个缓冲区；版本按资源独立；重连只观察原任务；关闭视图不取消执行；执行完成与科学判断分开。

RHO / DESIGN HANDOFF 06 / PLUGIN DESIGN TEMPLATE

插件模板：统一接口，留下专业空间

这里约定设计交接结构；不是一个已发布的新 UI SDK，也不要求所有插件长得一样。

A · Rho view frameTitle · focus · layout menu · close
B · Plugin tools对象相关动作、筛选、显示方式；只保留本插件需要的项
C · Primary content

Editor / Grid / Canvas / Conversation

主体可完全不同；鼠标和键盘操作遵循该领域成熟习惯。

D · Contextual action
随选择出现，不固定堆在顶部
E · Relevant state仅当存在保存、范围、采样、部分结果或连接问题时出现
F · Shared routesOpen exact result · Attach context · Details

由外壳统一

  • 项目位置、页签、分屏和布局撤销。
  • 焦点外观、通用菜单、通知与字号基础。
  • 上下文附件与精确结果的打开方式。
  • 不可用插件的占位与返回入口。

插件保留自己的特色

  • 代码：行号、语法、光标、撤销与保存。
  • 表格：密度、列类型、排序、筛选和比较。
  • 图形：坐标、缩放、点选和图例。
  • Agent：消息、步骤、草稿和输入归属。
约定的边界共享的是路由和习惯；数据意义、原生条件、结果解释与状态事实由各插件提供。

插件的专业性

  • 单位放在列标题；同列统一精度，Details 可看原值。
