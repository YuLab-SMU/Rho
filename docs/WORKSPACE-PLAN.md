- 日期：2026-10-24（同日按评审修订）
- 状态：2026-10-24 用户指示“执行完整计划”，批准 W0–W7；决定 1、2、7 按默认执行，W2 检查点
  报告照常提交并按证据复核（第 8 节）。npm 注册表发布等对外动作仍需用户另行确认。取代[交互计划](INTERACTION-PLAN.md)第 5 节的高保真门槛，成为
  [WEBUI-FIRST](WEBUI-FIRST.md) 中 WEB-02 至 WEB-11 界面部分的执行顺序。
- 读法：开工前读第 1–4 节和自己的里程碑。

## 0. 终点

**产品要成立的一句话：** 一个真实 Agent 工作时，人不用翻对话和工具调用，就能看到正在发生的
工作、看懂重要结果、针对具体对象提问，并让工作继续。第 2.1 节的行为契约 E1–E5 是这句话的
可测形式，贯穿每个里程碑。

**首版完成 = WEB-11 通过：** 在选定平台的干净环境里，从实际 `npm install` 开始，一个真实的
Claude Code 会话和一个人在同一个浏览器窗口里走完 [ROADMAP](ROADMAP.md) 的 Slice A 与
Slice B。每一步都由自动检查判定，不由人的评审判定。

不另设“高保真”阶段。每个里程碑交付的界面就是最终质量：视觉语言是 `web/theme.css` 的令牌；
行为契约、结构尺子和性能预算一起判定质量。令牌统一不等于体验成熟，所以三者缺一不可。

## 1. 原则：怎样不走偏

1. **先立尺，后施工。** 每个里程碑的退出条件写在本文件，开工时先把它们写成检查脚本或测试，
   然后只做让它们通过的改动。
2. **不靠人验收。** 判断从第一性原理出发，落成可量化的浏览器检查或单元测试。工程检查就记为
   工程检查：通过只说明满足了已定义的契约，不说明人已经能自然地看懂。人的理解证据目前
   **未获得**；如果有人试用，观察记进第 7 节作为输入，不作门槛，也不写成“已验证”。
3. **退出条件固定。** 发现退出条件本身有错时，先在本文件改正并写明理由，再改代码；放宽条件
   需要用户决定，收紧或纠错不需要。
4. **停车场。** 不在当前里程碑范围内的发现，记进第 7 节（日期、来源、一句话），不顺手去做。
5. **一个规则源。** 屏幕怎样随事实变化只写在 `src/expression.ts`；外壳只渲染 `Screen` 和
   所有者记录，自己不判断“该不该跟过去”（W1 用导入边界测试守住）。
   [交互计划](INTERACTION-PLAN.md)第 1 节的六条不变量继续有效。
6. **旧外壳冻结。** 旧工作区不再加功能，也不修缺陷；只做保持编译所需的类型改动。
   缺陷记进停车场，由新外壳解决。W3 后旧外壳退到 `#shell=legacy`，W6 删除。

## 2. 判定标准

所有浏览器检查都在真实 Chrome 的四个视口进行：1440×900、1024×768、768×1024、390×844。
共用实现放在 `scripts/rulers.mjs`。编号用 E 和 M，避免和[设计清单](DESIGN-PRIORITIES.md)的
R1–R14 混淆。

### 2.1 行为契约 E1–E5（主线）

检查人能否从屏幕找到 Agent 的工作；数据来自所有者记录和浏览器状态，不需要人工判断。

| 契约 | 要求 | 测法 |
| --- | --- | --- |
| E1 当前工作 | 从默认屏幕能定位 Agent 正在处理的真实对象和它的状态 | 有一个元素用显示名（不是 ID）写出 `Screen.agent` 指向的对象和状态；一次操作到达该对象 |
| E2 产物关系 | 从产物到产生它的运行，再回到确切版本，往返可走 | 从任一产物视图，一次操作打开产生它的运行，运行里能看到同一产物的同一版本；从运行，一次操作打开它登记的每个产物的该版本；没有生产者记录时写“未记录” |
| E3 对象反馈 | 人针对对象提问，Agent 读到带版本的上下文，回应与行动能关联回问题 | `context.read` 记录确切版本和所选实体；带 `replyTo` 的回应显示在原问题下；回应引用的产物打开确切版本（S7 已有，改为回归检查） |
| E4 三种说法分开 | Agent 的解释、系统观察到的事实、领域验证状态不混为一谈 | 三者分别渲染在 `data-fact="agent"`、`"observed"`、`"verified"` 的元素中；Agent 的文字不使用已验证的样式令牌；没有领域检查时明确写出，而不是留空 |
| E5 无声明也成立 | Agent 不调用 `task.map.*` 时，工作过程和产物照样能导航和检查 | 在 Agent 零次 `task.map.declare` 的项目上，E1–E4 全部通过（S7 的真实 Claude Code 运行就是这种项目；从活动记录核对次数为零） |

### 2.2 结构尺子 M1–M10

尺子量的是结构，防止为了过尺子而把必要信息藏起来：附加信息占用的空间要和它当前的价值相称。

| 尺 | 原理 | 测法 | 阈值 |
| --- | --- | --- | --- |
| M1 工作先见且可读 | 人来这里是为了工作 | 活动视图的首个内容单元（表格首个数据行、编辑器首行、图片上半部、运行视图标题），其四角和中心的 `elementFromPoint` 都落在它自身之内；文字的计算字号；图片的显示比例 | 四个视口都通过；文字 ≥12px；宽 ≥768 时图片比例 ≥0.5，<768 时一次操作可切到原始大小 |
| M2 附加与价值相称 | 例行进展让位于真实对象；等人判断的事可以占用适度注意力 | 常驻的 Rho 层（栏、来源条）占视口高度的比例；临时附加（打断、回来摘要、人自己提出的问题线程）只在 `Screen` 有等人的事实时出现 | 常驻：宽 ≥768 时 ≤10%，<768 时 ≤15%。临时：总计 ≤40%，一次操作可收起，收起后回到常驻预算；例行进展从不使用临时位置；同时可见的打断 ≤1 条 |
| M3 旧失败可达 | 退场不等于消失 | 被同一来源后续成功运行取代的失败，从默认屏幕打开其运行详情所需的点击数 | 1 次 |
| M4 无占位 | 没有记录就写“未记录” | 可见文本中独立出现的 `?`、`undefined`、`null`、`NaN`、`[object Object]` | 0 |
| M5 无内部标识 | 人读名字，不读摘要 | 证据面板之外出现的 principal 摘要（≥12 位十六进制）和协议方法名（取自 `protocol.operations`）；证据面板里的作者是否显示为名字 | 0；作者全部可读 |
| M6 无意外裁切 | 能滚动的地方要让人知道 | overflow 非 visible 且内容超出的元素，必须是声明过的滚动区域：有可访问名称、可用键盘聚焦、有可见的溢出提示（所有者视图主体属于此类）；摘要行数 | 未声明的裁切为 0；摘要 ≤6 行 |
| M7 一套视觉，层级可辨 | 只有一个视觉系统，且看得清 | `test/web-style.test.mjs`：读取的令牌都有声明；新外壳样式没有色值字面量；其他样式的色值数只降不升。文字对比度：正文 ≥4.5:1，大字 ≥3:1（禁用控件和对读屏隐藏的装饰除外；所有者视图内的结果单列，归插件）。每个交互控件在 `:focus-visible` 时样式与静止时不同 | 全部通过 |
| M8 控件有名 | 读屏可用 | 每个 `button`、`[role=button]`、`input`、`select` 都有可访问名称 | 缺失 0 |
| M9 不横溢 | 页面不溢出 | `scrollWidth ≤ innerWidth` | 四个视口都通过 |
| M10 键盘可达 | 不依赖拖拽和指针 | Tab 顺序能到达每个可见控件；分屏、移动、关闭、恢复布局都有键盘命令 | 全部 |

**截图记录：** 每个里程碑收工时，在四个视口保存各关键状态的截图，并列出与上一里程碑的
像素差。差异如果没有对应的有意改动，就按缺陷处理。截图差异只作报告，不作门槛：基线是我们
自己产出的，不代表正确。

### 2.3 性能预算（W0 定义，W7 验证）

- **测量环境：** 本机 macOS arm64，Node 22.22.x，记录机型和 Chrome 版本。
- **冷启动：** 启动命令 → 首页首次渲染 ≤3 s（不含首次安装）。
- **打开工作区：** 选择项目 → 首个所有者视图的 M1 单元可见 ≤1.5 s（S7 项目）。
- **交互延迟（Event Timing）：**
  - 编辑器按键到绘制 p95 ≤50 ms；
  - 点击、切换视图、表格排序 p95 ≤100 ms。
- **内存：** 服务 RSS 和浏览器 JS 堆，分别在空闲和 8 个重视图时测量；预算为 W0 基线 +20%。
- **体积：** 首屏和总 gzip 不超过 W0 测得的旧工作区基线。

**为什么替换而不是修补：**

- 旧外壳在 1024×768 的“回来”状态下 M1 不通过：提问线程、来源条和表达栏依次叠在表格上方，
  把首个数据行挤出视口。屏幕上没有一个地方统一决定谁占位置，每修一处都要再加一层。
- dockview 自带一份布局模型，要和所有者的组合记录双向同步。Agent 的布局提议、人的布局改动、
  恢复布局都要经过这层翻译。
- 旧表达层读取未声明的令牌，所有颜色都落到了硬编码的回退值。

## 4. 新外壳必须继承的义务

1. **组合保真：** 按所有者的组合记录渲染分屏（轴向、权重）和标签组。人的布局改动写回组合；
   Agent 的布局变更按 S7 规则成为提议。
2. **呈现见证：** 每个挂载的视图照旧上报 `view.observe`。
3. **挂载预算（沿用现行规则）：** 最多同时挂载 8 个重视图；这是渲染预算，从不驱逐缓冲。
   第 9 个视图显示“已到视图上限”，并保留已有视图和输入，由人关闭别的视图后再打开。
   不引入 LRU 卸载；活动视图、正在输入的视图、受 `view.protection.set` 保护的视图都不会被卸载。
4. **单一缓冲：** 一个文档只有一个未保存缓冲 owner；切换或分屏不复制缓冲，也不丢撤销。
5. **输入安全：** Agent 活动不抢焦点；IME、剪贴板、选区不受跟随影响。
6. **窄屏：** 宽度 <768 时分屏折成标签，顺序不变；保留抽屉和上下文面板。
7. **续接：** 刷新或重连时恢复布局并显示回来摘要，不重放焦点、写入或执行。
8. **凭据（沿用现行配对）：** 一次性配对码只出现在启动器打开的 URL fragment 中，不随任何请求或
   Referer 发出，并在渲染前从地址栏移除；会话令牌只存在本标签页的 `sessionStorage`。
   新外壳不新增任何携带令牌或秘密的 URL、`localStorage`、页面文本或截图。

### W4 Agent、动作与执行（Slice A 2–5）

**做：**

- Agent 接入面：连接状态、项目绑定、可用动作和资源范围、连接失败后的继续入口；
- 类型化参数界面（决定 3）：Agent 选中动作后打开，人可直接查看、修改参数并提交；
- 执行视图：运行、未知、部分结果、取消请求与确认停止分开显示；有界日志标出截断；
- 取消授权按决定 2 的规格实现；
- 失败时提供带真实错误和资源引用的 Agent 修复入口，修复后的运行是有意的新身份，并关联原任务。

**退出（浏览器检查）：**

- 真实自然语言请求打开一个绑定实际输入的参数界面；人修改一个参数后提交，原生派发恰好一次。
- 运行中刷新：仍观察到同一个 operationId，派发计数不变。
- 取消：请求显示为“已请求”，Core 确认停止后才显示“已停止”。
- 失败后修复：创建的上下文包含错误文本和资源引用；新运行带新身份并链接原运行。
- 未知状态如实显示（M4）。

**退出（服务端测试，决定 2）：**

- 跨项目请求被拒绝；
- 配对范围之外的浏览器被拒绝；
- 猜测的 ID 与不存在的 ID 返回同一个错误；
- 取消记录了请求者；
- Agent 取消自己运行的行为不变。

## 8. 授权与固定动作

**执行权与决策权分开：**

- **批准本计划 = 授权 W0–W2。** Agent 在此范围内自主实施、验证、修订、提交，检查通过后
  fast-forward 推送 main。这期间不删除旧外壳，不改授权，不改配对。
- **决策检查点（W2 结束）：** Agent 提交检查点报告，用户就决定 1、2、7 和是否继续 W3–W7
  作出决定。批准后，W3–W7 同样自主推进；删除 legacy 与 dockview、取消授权等边界变更，
  按检查点批准的规格执行。
- 改变终点、放宽退出条件、实质改变产品方向，或做检查点未批准的边界变更，需要用户另行决定。

**每个里程碑的固定动作：**

- **开工：** 读第 1–4 节和本里程碑；跑上一个里程碑的全部退出检查，确认基线；
  先把本里程碑的退出条件写成检查。
- **施工：** 只做让退出检查通过的改动；范围外的发现进第 7 节。
- **收工：**
  - 本里程碑和之前所有里程碑的退出检查、带 `RHO_CORE_BINARY` 的 `npm test`、
    `npm run check:replay` 全部通过；
  - 保存截图记录；
  - STATUS 写一段；
  - 更新第 5 节状态（附提交号）；
  - 提交并推送。
