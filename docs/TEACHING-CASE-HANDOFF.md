# 成绩平均值教学案例前端交接

Updated: 2026-10-22.

交接对象：前端设计与实现团队，以及负责 Rho / Rho-plugins 接口的开发者。
目标是用“这组成绩的平均值为什么偏高”验证最初 Paper 的工作方式：
围绕一个问题查看证据，指出疑问，检查 Agent 的修改，作出判断，再继续工作。
当前成果是动线、能力与缺口说明和一份待评审的 Paper 动线稿；教学项目和这条浏览器
动线尚未完整实现或验收；后续 UI 实现等待动线评审。

## 1. 设计依据与交付边界

主依据是 [Paper 原始体验稿 V0.1](https://app.paper.design/file/01M4X13H2YQGGR8NQXE8W0QDQY/p-9-0)
的首页、进入工作、检查结果、对象反馈、候选比较、返回继续和组合能力。
[产品设计](DESIGN.md)规定问题、证据和人的判断之间的关系。
[U2 补稿](https://app.paper.design/file/01M4X13H2YQGGR8NQXE8W0QDQY/p-F-0)
继续约束编辑器的作者标记、Changes、Show before、Revert 和冲突恢复。
补稿的局部确认不能替代原始体验的整体核对。

前端沿用原稿的信息层级、已有布局和交互，决定教学内容怎样落入对应区域。
本说明规定内容、行为和事实来源，不规定新像素尺寸、卡片样式或新组件布局。
需要裁剪、补充或改变界面的地方，先由前端补齐 Paper 并取得相应确认，开发再消费。
尚未具备的语义或接口须列为依赖，不能用临时前端状态伪装成已交付能力。

教学项目是独立的普通项目和验收素材；成绩、字段、计算和教学步骤不能写进主壳、
基础插件目录或通用组件。应用文案为英文，中文问题、反馈和文档内容保留原文。
聊天留在外部 Claude Code；不增加聊天客户端或推断外部思考状态。

## 2. 固定案例与计算预期

这是合成数据，无真实学生信息。一次百分制测验有 8 条记录，稳定实体键为
`student_id`；`record_no`、`score` 声明为 number，`student_id` 声明为 string。
普通项目拟包含以下文件，当前尚未创建：

| 文件 | 用途与条件 |
| --- | --- |
| `grades-original.csv` | 原始输入 A，保留下面的 8 行；注册真实字节与精确资源版本 |
| `teacher-record.md` | 独立核对材料：满分 100，STU-008 的原始记录为 80，其他记录一致 |
| `explanation.md` | 人与 Agent 共用的解释文档，保存问题、算式、证据引用、疑问和决定 |
| `grades-corrected.csv` | Agent 核对后才创建的候选 B，只把 STU-008 的 180 改为 80；保留 A |

```csv
record_no,student_id,score
1,STU-001,70
2,STU-002,72
3,STU-003,75
4,STU-004,78
5,STU-005,80
6,STU-006,82
7,STU-007,85
8,STU-008,180
```

| 事实 | 独立算术预期 |
| --- | --- |
| 原始 A | 总分 722；人数 8；平均值 90.25 |
| 核对后的候选 B | 总分 622；人数 8；平均值 77.75 |
| 变化 | 一条记录少 100 分，平均值下降 12.50；其他 7 条不变 |
| 直接删除 STU-008 | 人数变为 7，平均值为 542 / 7，约 77.43；与纠正录入不同 |

在核对材料被实际读取前，只能说明 180 超过百分制上限，需核对；不能先宣布录入错误
已经证实，也不能自动删除。核对后应能解释平均值偏高的具体原因和纠正依据。
算术预期是验收基准，不是已经发生的 Agent 读取、计算或回应记录。

A、B 和解释文档各有自己的版本；文中的 A / B 是教学简称，不是全局项目修订号。
两表只有在声明同一测验的实体 namespace、验证键唯一并明确映射后才可联动或比较。
图表若用于后续扩展，可消费 `record_no` / `score` 的真实散点数据；本例第一轮评审
用表格与解释即可核对主要关系，不以新增图表 UI 为前置要求。原稿图表区域如何裁剪，
由前端在 Paper 中明确，开发不自行替换或重新排版。

## 4. 供前端串联的完整动线

### 1. 进入并理解问题

Agent 启动本地服务、打开一次性浏览器链接；人打开教学项目。
进入后应能辨认中文问题、8 条记录、当前结果 90.25，以及解释来自哪张表。
连接信息、权限和内部标识按原稿按需展开。首次为空时不给出虚构结果或任务。
项目本身存在，不代表“上次看到哪里”或“已采用哪个结果”的状态也已经存在。

### 2. 看解释并检查证据

`explanation.md` 的起始内容说明总分 722、人数 8、算式 722 / 8，以及尚待核对的 180。
人可以检查原始成绩表，也可以编辑同一份说明。阅读说明和编辑源码的具体呈现由前端
沿用原稿确认；仅挂载 CodeMirror 不能代替这一阅读任务的验收。
算式与数值是项目内容，不由 Rho 主壳内置成绩计算器产生。

### 3. 定位同一个对象

人按成绩排序并选中 STU-008，检查该条记录与解释的关系。选中身份来自稳定键、
namespace 和 A 的精确资源版本，排序后的行号不能成为身份。
哪些视图跟随选区、何时向 Agent 显式共享，由前端按原稿明确。
个人光标、视图选区和共享通道保持分离；Agent 的个人选区不能覆盖人的选区。
当前表格会把选择写到以 viewId 命名的共享通道，这还不是完整的上述交互。

### 4. 留下锚定反馈并继续

反馈示例：“STU-008 的 180 超过满分。是不是录入问题？请核对原始记录，不要直接删掉。”
草稿属于 Documents；提交后由 Annotations 冻结草稿内容与 A / STU-008 的实体锚点。
人可继续在解释文档中输入另一句教学说明，反馈不应变成阻塞对话。
也需覆盖解释文档的 UTF-16 范围反馈，保留中文与 emoji 的完整范围。

### 5. 准备上下文并交给外部 Agent 读取

从已提交反馈准备冻结上下文，能检查反馈、A 的实体快照和相关文档版本。
准备完成仅说明上下文可供读取。外部 Claude Code 在其聊天中获得上下文引用，
实际调用 `context.read` 后才展示工具读取事实；不把准备完成写成“已发送”或“已理解”。
需要怎样把引用带入外部客户端，由前端交代可执行入口，不承诺主动注入聊天。

### 6. 实际核对并修改

Claude Code 通过统一 MCP 发现授权能力、读取冻结上下文及明确提供的核对材料，
再读当前已确认的共享文档，按当前条件修改说明；如果人已编辑，重新读取后作有意修改。
不得凭旧上下文覆盖新内容，也不得读取浏览器尚未确认的输入。
候选 B 由外部 Agent 显式创建、写盘和注册为新资源；表格 UI 仍只读，A 的输入保留。
读核对材料不必引入原生执行，本例协作验收要求 Rho Host 启动与原生派发均为 0。

### 7. 显式回应并检查改动

Agent 回应必须通过 `annotation.reply` 的 `replyTo` 关联这条反馈，说明读了什么、
改了哪条记录、为何保留人数 8，并引用实际 B 和已确认文档版本。
共享文档发生变化不能代替显式回应；外部聊天的一句话也不能代替 owner 回应记录。
人能检查 Show before、作者和单条 Revert；⌘Z 只撤本标签身份的编辑，没有假 redo。
如果原文发生变化，旧锚点说明版本不同，仍能看到原来提交的对象与内容。

### 8. 比较、决定并继续编辑

人检查 A 的 90.25 与 B 的 77.75，理解纠正与删掉一人的区别。
先保留 B 为候选；人可以暂不决定，也可以明确要求按 B 更新最终说明。
当前没有通用“结果采用 / 分支 / 下游失效”模型。此例可先用普通共享文档记录
人的决定及精确来源，不据此声称已实现全局采用系统。
若界面需要可查询的采用状态、自动引用更新或独立决定按钮，须先确定最小持久契约，
不能从最新资源、当前标签或前端布尔值推断。未经确认不自动改绑正在检查的 A。
人随后继续编辑同一文档，Agent 的到来和视图更新不夺焦点、不清空个人选区。

### 9. 离开、返回与归档恢复

刷新、断线和同端口服务重启后，用原身份和当前快照核对已确认状态；未知结果保留未知。
冻结上下文不随 live 文档更新；原始表锚点也不自动指向 B。
归档采用格式 3，核对文档、组合、保护、共享选区、反馈、上下文和显式回应的关系。
缺 owner、缺资源或恢复冲突保留来源与原因，不安装、不重跑；观察关闭不取消工作。
本次不承诺完整时间线、任意历史点分支、报告生成或分享页面。

## 7. 教学案例的验收条件

以下均为待执行条件，不预填通过结果。第一轮先评审动线与事实对应，再运行真实场景。

1. 首次进入能说明“在问什么、现有结果是什么、依据在哪、下一步检查什么”。
   不借助协议 JSON、开发者讲解或记忆标签名才能完成任务。
2. 用上面的真实项目文件得到 A / B 的算术预期；保留 A，核对后才生成 B。
   比较可以解释纠正与删除的区别；候选不自动成为人的决定。
3. 排序 / 筛选 / 翻页后反馈仍锚定 A 的 STU-008；旧版本不自动迁移。
   人的个人选区与 Agent 私人选区互不覆盖，共享有明确入口和资源映射。
4. 人在浏览器编辑同一文档，真实 Claude Code 从明确上下文读取已确认 buffer，
   条件修改并通过 `replyTo` 回应；人继续编辑、自己的撤销和单条 Agent revert 均可核对。
   确定性 HTTP 调用与模拟聊天不替代真实 Agent 验收。
5. 丢响应沿用原 caller / changeId / 条件；冲突保留未确认输入并停自动提交。
   保护视图、焦点、IME 组合和当前检查版本在后台更新后保留。
6. 刷新、重连、事件 gap、同端口服务重启和格式 3 恢复后，已确认内容与关联可查；
   缺插件 / 缺源 / 权限撤回 / 恢复冲突有真实原因，且不自动执行或扩权。
7. 对照原稿检查 1600 / 1280 / 1024 / 390 宽度、键盘路径、焦点、中文 IME 和剪贴板。
