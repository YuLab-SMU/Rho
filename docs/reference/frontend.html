On this page

Browser application ​

Updated 2026-11-11. The frontend was reset at the user's request. Previous frontend plans, visual specifications, Paper references and appearance rulers have been removed from the working repository. Git retains their history; they do not govern this implementation. This document describes the current application, not another prescriptive design system. How it changes next is decided by reviewing real runs (Development); the current base-R review records what the screens do not yet show. Avoid unnecessary secondary labels and descriptions: let the layout do the explaining.

The clip runs for about 30 seconds: the projects list, the answer board with its figure and table, a script and a table opened, and panes moved and resized while the work stays in place. It was recorded before the frame below; the places and the work are the same.

The frame ​

Every page of a project has the same three regions. The sidebar says where the person is and what is going on there: the projects, then the open project's tasks, then its files. The project's places are tabs above the work, which is one panel. One panel beside the work holds the Agent's conversation or the project's notes. Each can be switched with one click from any page, and switching never changes what is running (record).

  • Projects lists the eight most recently opened projects by name, in the service's order, the one on screen marked and a dot on each one whose Agent is answering (from one bounded conversation.list per project every five seconds while the page is visible; the open project's own record also says when it needs a choice). Choosing one returns to where it was left in this tab; + and Rho open the projects list, where a project chosen opens on its Overview. A project is a folder, and the cross on its row here or in the projects list takes it off Rho's list and leaves the folder and its files as they are (project.remove), with Undo for fifteen seconds (project.restore). While an Agent answers in it, or a session, terminal or command of the person's runs in it, the service refuses with their counts and the page asks before each is stopped (record). A project whose folder is gone from disk is removed the same way, and rho remove [FOLDER] does it from a shell.
  • Agent holds the project's Agents and their conversations in one place. The row opens the Agents that work here and says when one is working or needs a choice; + starts a new conversation, and is the one New while this list is on screen. Under it are the open project's conversations, newest first (eight, then "All N", which opens every conversation with its search, usage and trash), each one line: its Agent's mark, its title (from its section of the project notes, else the Agent's title, else its first message) and how long ago it last moved, or that it is working or needs a choice. Choosing one opens its Studio with its conversation in the panel, whichever window its session began in. The conversation the panel shows is tinted, on any page. The person's own workspaces follow, with New workspace.
  • Sources lists the project's files by kind, as described below.
  • At the foot, what the project is set up with: Plugins, Project settings, and the connection's state with Connection & access.
  • The tabs are the project's places: Overview, Studio, Graph, Skills, and Review while the project has review records. The Notebook, the Terminal and the project's files are views of a Studio workspace, beside each other, and have no tab or page of their own (episode). The settings or another page reached from the sidebar is named after the tabs while it shows. A bar without room keeps the icons and the name of the place on screen. At the bar's end: what the Agent is doing while it works, then Notes and Agent, which open the panel beside the work.
  • Below 768 CSS px the sidebar is a drawer that also lists the places, the bar names only where the tab is, and the panel is a sheet over the page.

The Agent's view of the sending tab ​

Each message sent from the Agent panel carries that tab's page and, in Studio, its workspace ID, observed layout version and replay position. The service freezes a bounded view summary with the message; a retry keeps that original context. Under a Studio message, the workspace name records where it was sent from. An empty workspace has no views, even when the project contains files. An Agent can delete a workspace's layout, with its views, through composition.delete and restore it through composition.undo; one holding a protected view is refused. Deletion removes the sidebar entry and moves an observing tab to another workspace, or Overview if none remains. Project files, unsaved buffers and sessions are separate. The Studio context episode records the original misunderstanding, the real OpenCode run and the limits of this summary.

Starting from the work ​

A person needs to find a project, work on its contents, ask an Agent for help and inspect what happened. The application gives those actions direct places:

  • Projects lists and searches available projects, names the folder each one works in, opens folders and creates a named project from selected source folders. It opens as one list with one primary action, and with no projects it shows what can be started instead of an empty page. A new service state also holds the study Rho ships with: the application copies it into the projects folder once, under the name it is listed with, and from then on it is an ordinary project the person reads, edits, continues or removes (example project).
  • Overview opens with the answer board: the newest message that produced results, derived from the Graph. It shows the question and the answer, then the results by role. The figure or table the answer names leads, with the other results beside and below it. Then come the method (an outline of the script), the run that produced them with its command and output, the message's other commands (which open in the Console), the data it read and any report. A result or script the project notes describe carries that description, and the session's choices follow the results: what each is about and what was taken, with any other option the notes name, under the choice or in the same sentence, in a well below with what it gives. Each result has Ask, and selecting a passage of the answer offers Ask about this. Either one sends a question to the same conversation with what it is about (the exact kept version for a file). Questions that make no new results are listed under Asked since with their answers, and the board stays on the answer they ask about; a header link names a question being answered now. Use this answer or Needs changes (with a note, also sent to the Agent) records the person's word for the file versions that message kept, and the board names results it does not cover and files changed since. Earlier answers are chosen from a menu. Below the board come a count for each kind of step (asked, read, edited, ran, changed on disk, answered), which is also the legend and filter of the Graph's timeline below it, in at most three rows: each conversation a named piece, with the person's own work and callers outside Rho among them (timeline events). A project where only the person has worked shows the same strip as What you did. Without conversations, the results show as pictures, newest first: the newest at twice the size, then two or five more, with the rest in Files. A side column draws each workspace as its panes, opens the shared notes, and lists the files the Agent's tools named, most used first, each with a bar for its tool calls. Its Work progress shows Agent sessions started outside Rho and any choice waiting in a session; conversations started in Rho answer on the board. Work in the Notebook is work: a Notebook section names each session with cells (where it runs, its cells and values) and the three newest cells by their purpose, each opening the Notebook at that cell; a project with only Notebook cells is not shown as empty. A project with nothing recorded yet shows its two next steps — work with the Agent or browse its files — rather than empty sections, leading with whichever one the project's listing says has something behind it.
  • Sources counts the project's Data, Code, Results & figures and Notes from one bounded walk of its folders, by file name. A project that holds them also lists Workflows (Makefile, Snakefile, .smk, .nf, .wdl, _targets.R…), Reports (.Rmd, .qmd, .Rnw and the page rendered beside one, whose _files folder is left out, as are the versioned libraries a saved page keeps in a lib, libs or site_libs folder beside it), References (.bib, .ris, PDFs in a refs or literature folder) and Environment (renv.lock, requirements.txt, environment.yml, pyproject.toml, Dockerfile…); each file is in one row, while the Graph and the board keep calling a file by what it is. Variables, between Code and Results, lists what the live R and Python sessions hold, by session, each name with its type, read again (at most once a second) as cells run (episode). A kind's row shows the kind in the person's workspace, as a view at the workspace's left edge: its files in a list (by folder for what the work starts from, newest first for results and reports, each with its size and when it last changed, a filter and Read again); for Files, an explorer of the project's folders and the source folders it works in (a folder opens in place, one level at a time; hidden files on request; a file found by name among the files the sidebar counted, the first 200 shown); for Variables, the Variables view of the live sessions. These share one pane as tabs, a fifth of the workspace wide when first placed, and widened again when another view would squeeze it under 15%. A file chosen in a list, in the explorer or in the sidebar opens as a view of the same workspace, so the list stays on screen beside it: a CSV as a table, an image, a Markdown file in the Markdown reader (its to-dos tick in place; Edit shows the editor with a formatting toolbar), an HTML file as its page (below), other text in the editor, highlighted when Rho has its language, a registered result as its exact version. A script opens right of the lists. The workspace is the person's own one on screen, else the one they last used; a conversation's Studio is not written to. The chevron at a row's end lists the kind in the sidebar instead, without changing the workspace: the top level first, then by folder, at most 40 there. A tab that cannot arrange views (one opened from a link) keeps the kind's page and a file's own page, with ← and → through the kind and Open in Studio (pass). + adds a source folder.
  • Terminal is a view of a Studio workspace, placed along its foot from a group's + or the command palette, with two forms chosen in its header (episode). Terminal is the person's own login shell on a pseudo-terminal in the project folder, drawn with xterm.js: its prompt and colours, keys to a running program (Ctrl+C), full-screen programs, at the size of the view. The view keeps its terminal with the page, so a reload or another tab returns to the same shell and the last megabyte it printed. Closing the view hangs the shell up, a shell that ended offers a new one, and a project keeps four at once. An Agent may use it too (episode): it reads what the screen shows as text and types there, and the view says who last did and when; a terminal an Agent opened of its own is offered here to show, and the person's own is offered back. A terminal records its commands with who typed each (zsh, bash, fish, sh, dash and ksh93; not mksh or tcsh), and keeps a shell history of its own, apart from the machine's. A terminal command's row shows the start of what it printed and reads all that is kept, and the full screen a program such as less left, when asked. Only the person at this machine draws one; a tab opened from a link shows Commands. It needs python3 on macOS or Linux; on Windows the view says so and offers Commands. Commands is the record the Console page showed, also opened by the board's command count. It runs the person's own single shell commands in the project folder. Newest first, it lists each message's commands under that message in the order they ran, with the person's commands and the commands typed in the terminals (In the terminal, each naming You or the Agent) between them, and Rho's managed runs at the end. Each command leads with the Agent's own words on what it was for, over the command with the project folder read as "."; without those words, it is named by what each part runs ("grep → python3 analysis.py"). Commands in a row that changed no file fold into one line. A row shows its time, its duration, any ending other than a clean exit, and the files that changed on disk while it ran; opening it shows the whole command and its output, which streams while it runs. A running command has Stop. Run again runs the person's command again, and puts an Agent's command into the prompt to check before Run. The board's command count opens the Console at that message. Only the person at this machine can run or stop commands; an Agent may read them (episode).
  • Notebook is a view of a Studio workspace, from a group's +, the command palette, Skills or the Overview (offered while the Notebook plugin is selected). Each Notebook put on a workspace, the first too (episode), is a notebook with R and Python sessions of its own (episode): a value made in one is not in another. A workspace can hold several (episode): once a page has one, a group's + offers New notebook (Notebook 2, 3, …, renamed from its tab's menu). An Agent's cells run in the project's own sessions unless it names a notebook; they show in its conversation's Studio and, from a cell's link, in a Project notebook view. A Notebook saved before this without a notebook of its own stays the Project notebook. A notebook split beside itself or shown on another page is the same notebook. Each lists only its own cells. A script's line, a table to explore and an expression from a value's view go to the notebook the person last worked in, and Variables, Plots and Data flow show its sessions (at first the first Notebook drawn), with a choice of notebook in their header when more than one has a session. Sessions lists every notebook's sessions, by notebook. Cells read in the order they ran, drawn as a notebook draws them (record): the cell's count in the gutter beside the first line of its code ([3], [*] while it runs, red when it failed); above the code, who ran it (the Agent's name opens its conversation) and its purpose, for an Agent's cell or a named one only; the code highlighted; under it how long it took or how it ended, and when; then what it printed, streamed while it runs, with messages, warnings and errors in their place and its plots. A cell names its language only in a notebook that holds cells of both. Long code and output show their first lines. Where a session started or ended the list says so, and that values from before an end are gone. A cell is edited where it stands (record): pressing its code, or Edit over its corner, makes it a box to type in with the caret where it was pressed; Shift+Enter (or ⌘/Ctrl+Enter) runs it there, Esc leaves it as it was, and code left unchanged is a cell again once the keyboard leaves it. Run again, the other icon, runs it there too. The run is a new cell in the same place (kernel.run with replaces), with its own count; the runs it took the place of stay in the record and open under it from "1 earlier run". The new cell stays at the foot, drawn as a cell, with a hint from what the session holds; under the code R or Python, and Run. Both boxes are Rho's editor (codeBox): the language's colours, matching and closing brackets, indentation, undo, and the names the live session offers (kernel.complete) once a name is three letters long, at once after $, @, ::, a dot in Python or an open quote in a subscript, and on Tab: its values, a table's columns, a call's arguments, files, installed packages. Esc closes the list; in the new cell Esc then Tab moves on from the box. With no session to ask, or one running a cell, the values it listed last are offered. On the person's own page the Notebook is the cells and that line, and leaves the rest to the other views of the sessions (one set of views): a plot of a live session is a picture in its cell, numbered as Plots counts it, that brings it forward in the Plots view, which is put on the page when it has none; a value named under a cell opens in its own view; and the session's state ("R 4.5.2 · idle"), in the view's own bar beside the form switch, opens Sessions, with where the session runs next to it when the project names a server. Interrupt stays at the new cell while a cell runs. A wide view centers the cells; under 840 px where the session runs moves to the new cell, which is one line there, and below 420 px the code takes its own line above R or Python and Run. Elsewhere (a conversation's Studio, and the Notebook page of a tab that may not arrange one) the Notebook keeps the sessions' state, variables and latest plots beside the cells, or folded into one line above them in a view under 840 px. A conversation's Studio has a Notebook view of the sessions its Agent ran cells in, with the person's cells since the conversation began, cut at the moment shown; on the person's own pages it shows the sessions whole. The view scrolls itself and stays at the newest cell while the reader is there, also when it is shown again or resized. Only the reader's own wheel, touch, keys or scroll bar take it off the end (episode).
  • Figures. An R plot built with ggplot2 (directly or by a package on it) is drawn in the cell and in the Plots view from its figure record. Pointing at a mark shows its row; click, Shift/⌘-click or drag selects, Esc clears, and the rows behind the selection are listed by layer. Ask the Agent keeps the selection and opens the Agent panel with it attached to the next message; the chip's × detaches it. Marks the Agent pointed at appear as an amber chip above the plot with its note, shown on the plot when the person has nothing selected. A plot nothing described stays a picture; one that failed says why under it (episode). A ggplot a cell saved with ggsave is drawn the same way wherever its file is shown with the bytes the cell saved: on the answer board, in the Results & figures file view and Studio's media view, and under the cell, which names the file (episode). Layers that draw the same rows count the selection once. Pages drawn with base graphics and ComplexHeatmaps are drawn and selected the same way; heatmap cells keep their colour while others are selected, and a selection outlines them (episode).
  • Two forms. Notebook | Console switches how the same sessions read: as a notebook (above) or as a console, one transcript as R or Python print it at a terminal. Each cell is its code after the prompt (>/+ in R, >>>/... in Python, a new statement at the prompt) and what it printed under it, messages muted, warnings amber, errors red; a cell someone else ran has a comment line with who and why (# Claude Code · Fit the model). Plots show under their prompt, or on the person's own page as a line that brings them forward in Plots. Session starts and ends are marked. A bar above names each session's state (there, a click opens Sessions) with Interrupt, and Stop where Sessions is not the place for it, and Clear (Ctrl+L) hides earlier output from this view only. The prompt sits under the last output: Enter runs finished code and goes on to another line, indented, in unfinished code (an open bracket or string, a trailing operator, a Python block before its empty line); Shift+Enter adds a line, ⌘/Ctrl+Enter runs whatever is there, ↑/↓ bring back what the person ran, a closing bracket on an empty line steps back, Esc interrupts, and the R/Python word beside the prompt switches language, as the one under the notebook form's new cell does. A click in the transcript puts the keyboard in the prompt. A Studio view saves its form with the page (props.form). A Notebook placed under a script by running one of its lines starts as a console (episode).
  • Explore in R or Python sits in the header of a table view (.csv, .tsv, also gzipped) and of an R or Python script, on the answer board's tables and on the file page. A table opens on the person's workspace with the page's Notebook beside it, or a Notebook placed in a pane right of the table, and loads into the session of that language as a new value named from the file (model_fit, then model_fit_2; a value the session has is never replaced). The cell is the person's, named for what it loads. A script opens the same way with a line that runs it (source() in R, exec with __file__ in Python) waiting in the Notebook to check and run, since running it again writes its outputs again. On the person's own page this happens in place; from a conversation's Studio, the Overview or the file page it opens the person's workspace. The file is read as it is on disk now, by its project path, also when the view shows an older kept version. Files of added source folders are outside the sessions' folder and have no Explore (episode).
  • A script's lines run in the live session of their language from the editor of an R or Python script on the person's own page: ⌘/Ctrl+Enter, or Run in the script's header, sends the selection, or the whole statement the cursor is in (a call over several lines, a pipe, a function, a Python block with its decorators and else/except parts), as the person's cell named for the script and its lines (analysis.R · lines 12–13). The cursor goes on to the next statement; a blank or comment line runs nothing. The text runs as it is in the editor, saved or not. A page without the Notebook gets one under the script; one in another pane comes forward there, and the script keeps the keyboard. Lines run in the order they were sent (episode).
  • Sessions, Variables and Plots are views of the live sessions of their own (rho.sessions, rho.variables, rho.plots), added from a group's +, an empty page or a link in another view of the sessions. Variables or Plots takes a column along the page's right side, the other above or below it there, so a script with its Notebook under it and these two make the four panes of a script, a console, an environment and plots; Sessions, Data flow and Servers are tabs beside Variables. Sessions is the R and Python processes: each one's version, state, where it runs (this machine and its name, or a place), the program, its process ID, who started it and when, its cells and waiting cells, what its values take as the session measures them, and the cell running now (which opens in the Notebook), with Interrupt, Restart and Stop (both ask first); one not running says how it ended and where the next starts, with Start. Sessions that ended earlier are listed under them. Variables is an environment pane of the session the newest cell ran in (or the one chosen): its state (opening Sessions), Find, and a table of Data (two-dimensional values: a data frame's observations and variables, a matrix's dimensions), Values (the value at a glance as the session prints it, with its length) and Functions, with type and size, sorted by name, type or size. A name opens the value; its arrow unfolds a table's columns with their first values, or a list's parts, and the cell that made it and those that read it, each opening in the Notebook. Under 440 px the type is left to the value's words. Plots shows the newest plot of the live sessions at the size of the view with the cell that drew it (Show the cell brings it forward in the Notebook), steps back through the 24 newest (arrows, or the strip below), and brings a new one forward as it is drawn, or the one a cell's picture asked for. Plots of an ended session stay with their cells in the Notebook.
  • Data flow (rho.flow) shows how the values of a live session were made, as a tab beside Variables (else in the right column). It is a graph of values: the project files and folders the session read at the top, the results at the bottom (the files it wrote and the plots it drew, else the values nothing reads), and the values between in rows. Each node is titled with the meaning its # means: comment gives (the Agent writes these above the statement that first makes the value; # means NAME: names one of several), with the name beneath, and shows the name alone without one. A bar names the results: choosing one draws what leads to it, and the first is chosen when every result at once would put more than six values in a row. Values that lead to no result are named below the graph, and choosing one draws what leads to it. A chosen value colors what it comes from and what comes of it; its panel gives its meaning, how and where it was made, what it uses and leads to, and which results it reaches. A value can be looked at, a file opened, and the cell that made it shown in the Notebook. A narrow view (under 640 px) puts the chosen value above the graph. Its values come from the kernel's records (below), each meaning from the code of the cell that made the value, and at most 80 values are drawn at once (episode).
  • How variables relate (episode). Under each Notebook cell, what it read and from which cell ("Read co from R 3"), and the later cells that read what it made ("ratio read in R 6"); a cell named there goes to that cell and marks it. A cell that makes at least three values offers "How its values came about", the same graph, under it. Variables names the cell that made each value as it is now and the cells that read it. An R or Python script's editor has a Data flow switch in its header, kept with the page: the script's flow, read from the text in the editor as it is typed (nothing runs), shows beside the code, or below it in a view under 640 px. Its nodes are titled by the same comments as the session's, and the flow line says how many values have a meaning written in the code. The code marks the lines that make the chosen value, those it comes from and those it leads to, in the colors of the key above the flow; choosing a value puts the cursor on the line that makes it, and a click on a line that makes a value chooses it.
  • Servers (rho.servers) shows where the live sessions run: this machine and each place, a folder on one of the person's servers, reached through serverctl when serverctl manages it and with ssh otherwise. A place shows its server and folder, how it is reached, what its last check saw (system, R and Python there, the machine's name, who checked and how long it took), its live sessions with the machine and process, and a session that lost its connection, with its process there not seen to end. "New sessions R / Python" marks where each language's next session starts. Add a server lists the servers serverctl manages (system, number of skills) and takes one of them or an ssh name, the folder, a name and setup lines, then checks it. A place on a server serverctl manages shows the skills bound to it ("How it is used"); pressing one reads it in place, without its header, with its file's path, in the form as on the card. A check that finds no R where the server has skills says they may say how to set it up. Files lists a folder there; opening a file copies it into remote/<place>/ and opens the copy, and a copy whose file has changed on the server says so. The Notebook's line has a chip beside the language naming where its next cell runs; session marks, rows, the console bar, Variables and Data flow name the place, and a file named in a server session's Data flow opens in Servers at its folder there. Explore in R or Python from a copy loads its original on the server; a file only on this machine is not sent there.
  • HTML pages (a knitted report, a saved widget, a page an Agent wrote) open as the page they make, with Page and Edit (Source) in the header over the same buffer as the editor. The page runs in a sandboxed frame of its own: its scripts run, it cannot reach Rho, and nothing loads from the web. The styles, scripts, images and fonts it names in the project are read and put into it; a note says how many web files it named and which project files could not be read. A link to a project file opens it in Rho; a link outside is named, not followed.
  • Values of the live sessions open as views of their own (rho.object). A variable's name in the Notebook, and each name a cell made or changed (listed under the cell while its session is live; removed names are struck through), opens it. On the person's page it opens there: in a pane right of the Notebook when both keep 360 px, otherwise as a tab of the pane next to the Notebook's, and later values join its tabs. From a conversation's Studio it opens on the person's workspace. The view says where in the value it is (a trail of parts back to the name), its kind, class and size, the session and the cell it was read after, and the code that reaches it, which Use in Notebook puts in the Notebook's line. A table shows its facts and a page of 50 rows with each column's type and summary; a column name sorts by it, again the other way, a third time back. A model shows its formula, fit statistics and coefficients, then its printed summary and its parts, folded; a vector its facts, counts when categorical, and values; a list its parts, each opening in place; a function its code; anything else as printed. The view reads the value again when the sessions change while it is shown, and when it is shown again; hidden behind another tab it reads nothing. While a cell runs, or after the value or its session is gone, the last reading stays, dimmed, with what it is and when it was read (episode).
  • Skills (listed while the Skills plugin is selected) holds how work is done in the project: the methods the person chose, the conventions they keep and the traps its work ran into, as SKILL.md files in .claude/skills/ that Claude Code loads by itself and other Agents read through Rho. The subtitle counts them and names the newest change. The list gives each skill's name, what it is for and who changed it last, or that it was written or changed outside Rho, or why Agents could not load it; removed skills fold under Removed. A skill opens on its newest change: its reason as the headline, who made it (an Agent's name opens its conversation) and when, its evidence (a Notebook cell opens the Notebook at that cell, a file opens the file, a note is quoted) and the lines it added and removed, with Undo this change (Bring it back after a removal, Put the change back after an undo). A change that writes or removes the whole file folds its text. An edit made outside Rho comes first, amber, with what changed since the last recorded version: Agents read it as it is, the next recorded change starts from it, and it is undone where it was made. Then the text as Agents read it (a first heading that repeats the name is left out), Edit the file, and the earlier changes, each opening to its evidence and lines. The skills serverctl binds to the project's servers are listed read only under From your servers. With no skills the page says what will appear and how, with two things to tell the Agent. Below 760 px of page one region shows at a time: the list, then a skill with All skills to go back. The Overview's side column shows the three newest changes, each opening its skill (episode).
  • The Agent page has two lists, each with its own way in: Conversations from "All N" under the sidebar's Agent row and from the panel's title, Agents from that row itself; its tabs switch between them. The bar above the work names the list on show. Conversations lists every session in the project folder by day, searchable and by Agent: Rho's conversations, Claude Code and Codex sessions read from the Agents' own records, and observed Harness conversations. Each row names where the session started (Terminal, VS Code, Codex app, Script…) and whether another window has it open now, and offers Continue, the terminal resume command, Markdown export and the trash (session continuity). Agents is one list of the project's Agents in one row design, whatever way each works here: the Agents this service can start (a radio for new conversations, the model and folded settings; one not found on this computer is greyed out), and the Agents connected from their own windows. A window sits under the Agent it belongs to, named by its MCP client's own name (clientInfo) or else by the session name the Agent chose; each window shows its name, a waiting, verified, refused or ended state, what its grant allows and its last call. Marks and Agent names come from the Agent icons plugin, by the words of the name an Agent gave; a name it does not know shows its initial. Below the list, one setup prompt is for the person's own local MCP client. The prompt names the project and gives one rho connect command, whose reply tells the Agent how to configure its own client. Reading or copying grants no access. Copy failure leaves selectable text; request failure offers retry. ACP observations and Host activity remain under a disclosure (connection episode). Conversation rows retain title, model, effort, messages, state, usage, cost and their files, commands and answers; the trash restores or deletes. Runs follow when present (Agents and conversations).
  • Project settings manages source folders and explicitly checks available tools.
  • Work from other windows feeds the same Graph, Console, answer board and session Studio through agent.sessions.read.
