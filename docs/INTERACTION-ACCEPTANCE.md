# S7 交互与表格反馈工程验收

日期：2026-10-24。范围：用户授权的六种行为、正式浏览器接入和表格提问闭环。
S6 的状态仍为 **真人可用性未验证**，不阻塞开发、修订或检查通过后的源码发布。
这里记录工程事实，不把自动化或模型试用写成真人研究。

## 规则、实现与所有者

[实施计划](INTERACTION-PLAN.md)和 [AGENTS.md](../AGENTS.md)记录自主实施范围。
设计参考是 [Paper「07 · 回放原型 · 行为（S7 评审）」](https://app.paper.design/file/01M5HG6R8RBC33N84S245J0YXT/p-B-0)。

| 行为 | 浏览器中的结果 | 主要证据 |
| --- | --- | --- |
| 跟随 | Agent 读对象时移动真实活动视图；缺少声明视图时使用已有组件的一个预览位 | 实际 MCP 读取与浏览器断言；预览/节流单元检查 |
| 工作时不打断 | 点击、选行、键盘或 IME 接管后，保留当前视图与输入 | Chrome 行选择及 CDP 组合输入 |
| 保留打开的版本 | 新产物和接受的新布局使用独立视图、精确资源版本及选区通道 | 原表仍为 2/4、新表为 4/8；旧行选择未迁移 |
| 离开后返回 | 按对象汇总变化；刷新恢复现场，不播放旧焦点、不重复执行 | JSON 检查点测试、浏览器离开/返回/刷新和分派计数 |
| 对对象提问 | 问题、取用、显式回复、新结果和旧来源可追查 | 原行锚点、上下文回执、replyTo 和产物引用检查 |
| 展开证据 | 从当前工作区打开实际活动；窗口外记录明确未知 | 浏览器展开、游标缺口与历史记录测试 |

Rho-plugins 的 Agent **0.4.4** 只补充文档、资源、布局和输出流身份元数据，
不保存完整工具参数/内容。Annotations **0.4.3** 复用 Documents 草稿、原有
Annotations 线程和 Agent context；回复新增可选 `resources`，由 Files 所有者
检查精确资源引用，最多 16 个。Rho 选择这些版本并重新生成协议/类型快照。
Rho-core 没有改动。未登记的原生适配器拒绝仍不可从 Rho 记录还原。
本轮组件源码提交为 `e1725196166f6edbdbf7612a9b76ed5b4ca17092`；应用记录这些
所选版本及生成契约。源码身份和浏览器构建清单分别保留，不代替安装包验收。
表格提问 UI 由所选 Annotations 入口贡献；仅选择 Documents 的独立构建不包含该

## 实际闭环

浏览器从表的当前视图选中 `001` 行，再输入中文问题。即使另一视图选择了 `002`，
原问题仍只锚定原表版本的 `001`，并保留提交时的草稿版本。第一次提交模拟服务器
已经提交而响应丢失；刷新后重试同一个请求，只保留一个问题，不生成第二次执行。

真实 Claude Code **2.1.310** 通过 MCP 取用原问题，修改并运行 R 分析，将两行
数值从 `2/4` 更新为 `4/8`，核验产物，再显式回复原消息并关联新表的精确引用。
该次试验 28 轮、132 秒，进程正常退出。没有要求或生成 Task Map，工作区仍可
观察执行、表格、问题及回复。回到浏览器后，打开回复中的新表，原表、原行选择和
原问题继续可查。随后一次真实 R 失败及一次恢复成功验证了失败不会被后续成功抹掉。

“Prepared”“Fetched by Agent”“Explicit Agent response”分别来自准备记录、
认证 Agent 的取用回执和显式 `replyTo`；普通操作者读取、后续运行或一句“完成”
都不构成回答。产物登记、字节核验、执行完成和领域判断仍是独立事实。
执行仅获接受而尚未观察时为 `unobserved`，不会推断为正在运行或填造退出码。

已配置业务会话的任务沿用 `feedback.submit` 的原会话投递；未指定会话的布局
只准备 context，并在界面上明确说明。验收为该 context 配置一个实际 MCP 消费者，
不把“准备完成”写成“已自动投递”，也不由浏览器另起未知会话。

  `complete-390.png` 和 `recorded-evidence.png` 保存浏览器观察。
- [自动化入口](../scripts/interaction-acceptance.mjs)记录每次执行的最终报告路径；
  `model: true` 才表示启用了实际模型。报告记录 Chrome 的实际版本；上述试验为
  **155.0.8059.84**。IME 使用 Chrome CDP，不等同于物理候选窗口的真人输入试验。

在已构建 Rho-plugins 和 Rho、且明确选择可用 Core/Rscript 的环境中运行：


该选项只控制同时启动的测试文件，不改变测试条件或超时。

`npm run prototype:replay` 继续用于离线历史回放，不是启动正式工作区的替代品。

## 失败、修复及范围限制

早期失败记录保留，没有以最终通过覆盖失败：

- `work/interaction-1792884474118` 的导航断言未适应视图数量文案，修正选择器。
- `work/interaction-1792884520557` 暴露资源锚点传入额外元数据，契约正确拒绝；
  发送端改为只传精确 `{id, version}`。
- `work/interaction-1792884680676` 暴露 Agent 活动的 SSE 通知只发给原 principal，
  浏览器无法跟随只读调用；现在发送项目范围内已有授权元数据的失效通知，新增真实
  SSE 消费测试。其他项目的授权边界不变。
- 未设置 `RHO_CORE_BINARY` 的一次全套检查因缺少本地可执行文件失败；显式选择后
  重新执行。没有把缺少依赖记成通过，也没有为本任务重建或修改 Core。
- 与浏览器同时运行的默认并发全套检查有一个 MCP 测试达到原有 30 秒上限；保留
  该次日志，并以 `--test-concurrency=4` 重跑全套，不放宽测试超时或删除断言。
- 原 U2 脚本仍假定选项目立即打开布局；按现有项目概览入口补上打开工作区的一步，
  资源页签选择兼容新增的版本标识，继续执行原有输入、撤销、筛选和重连检查。

注意力节流采用本地接收时钟，保留事实的原始时间；批量补到的历史时间不能绕过
8 秒节流。公共执行摘要最多 50 条，显示证据最多 256 条，本地视图最多 64 个，
恢复检查点最多 1 MiB，问题意图最多 16 KiB。超过限制保留已经取得的内容并说明
不能显示/恢复的范围；这些显示限制不删除所有者记录、不取消任务。
