# Rho 的方法提案：按科学目的组织人机共享工作界面

更新：2026-10-30。根据用户对 Rho 的明确补充，本版把方法的起点前移：Rho 能根据目的自主组织所需材料，形成布局合理的工作界面。**拟议贡献是：依据当前科学目的，从持续分析中选择材料、组织它们的关系并组合可操作的视图；这份组织同时成为人理解分析的界面和 Agent 继续工作的共享上下文，随人的操作与新进展持续更新。** 上一版把阅读版本与续接版本的协调放在主位，仍然缩小了研究对象；版本协调应服务这一整体。

以下用构造的单细胞场景说明具体机制，正面对照 InsightLens、WaitGPT、Mycelium，并补入生成式界面与可视化创作工作。“布局合理”在这里是需要说明的设计目标，不由自动生成或功能可用直接推出。本文不排实验，不制定未观察过的屏幕布局规范；实现与效果证据仍按 [Status](STATUS.md) 及具体记录理解。

## 1. 核心操作：按当前目的组织一个可共同工作的界面

研究者表达“我现在要判断什么”，Rho 从现有分析过程和材料中组织适合这项判断的工作界面。目的可以来自当前任务及明确的交互上下文，系统推断出的目的应可见、可修正；无需让人先指定每个文件、控件和位置。

这次组织包含四个相连的选择：需要什么材料，它们在当前判断中分别承担什么作用，适合用什么视图和操作呈现，以及怎样安排它们以支持阅读、比较或继续分析。已有组件可以承担表格、图、代码和运行状态；研究增量不要求每次从零生成界面代码。

例如，同一个单细胞项目，在判断生物学差异、检查计算为何未完成和准备结果说明时，需要组织的材料及其主次关系不同。Rho 所形成的界面表达的是“为这个目的，我们正在一起看这些对象、比较这些关系、处理这些未决事项”。这份表达保留材料引用、范围和操作含义，Agent 可以据此继续工作；它不是只能由人观看的截图。

> 当前科学目的 → 所需材料与关系 → 可操作的界面组织 → 人的理解与行动、Agent 的续接上下文 → 新进展或新目的驱动再组织。

其中，人的阅读位置、当前分析状态和 Agent 获得的上下文仍可能不同，需要保留各自的身份与范围。它们保障修订能落到正确对象上，但不单独承担论文主贡献。**候选贡献是一种把目的驱动的界面组织与共享分析状态结合的交互方法**，而非分别认领自动布局、记忆编辑或来源记录。

## 2. 单细胞场景：研究者究竟怎样判断与操作

### 2.1 先明确研究者需要理解什么

设有 6 名病例、6 名对照，每名供者贡献多个单核细胞，具有原始计数、注释和供者映射。问题是判断这些供者中，一组事先选定的干扰素反应相关基因是否存在疾病相关的表达差异；下文简称“干扰素表达差异”。以下数据、运行与版本标识均为说明机制的假设，没有实际效应量或用户观察。

研究者至少需要分清：图中的每个观测代表细胞还是供者；疾病分组属于哪一级；模型如何处理同一供者内的依赖；结果支持描述、供者层面的关联，还是更强的生物学解释。细胞数不能直接替代生物学重复数；忽略重复间变异会影响单细胞差异分析的推断。[R25](#r25)

即使计算完全合理，人的理解仍有工作要做。细胞级小提琴图可以展示表达分布，考虑供者依赖的模型可以评估关联；二者并非互斥，但回答的问题不同。“看到图”“知道模型名字”和“理解为何这项结果支持该解释”不是同一件事。

### 2.2 同一份分析，因目的不同而组织不同的界面

研究者说：“我想判断这项差异在供者之间是否一致，先不要只给我合并后的细胞图。”Rho 根据这一目的，寻找已存在的供者分组、细胞到供者的映射、相应表达材料、模型与结果，并把它们组织成支持这项判断的工作界面。研究者无需先知道它们分散在哪些文件、消息或运行里。

布局要表达判断所需的关系。例如，让细胞分布与供者层面的表达材料能够对照，使用明确一致的供者和基因标识；把当前统计解释与其模型依据联系起来；把长日志收进可展开的运行材料。选择某个供者时，相关材料可以沿明确映射定位到该供者，无法建立映射的视图则说明限制。这里描述的是交互关系，不是指定屏幕分栏、尺寸或视觉风格。

同一个项目的组织可以随目的改变：

| 当前目的 | Rho 需要组织的材料 | 布局与操作承担的作用 |
| --- | --- | --- |
| 判断细胞分布与供者层面推断是什么关系 | 相关表达图、供者映射、每个供者的材料、模型与结果 | 让需要比较的对象可共同阅读，沿同一供者或基因定位依据，区分描述与推断 |
| 理解为什么修正分析还没有新结果 | 对应任务、脚本与输入、运行状态、已有输出、环境信息及错误 | 把当前受阻的计算与其依赖放到阅读重点，明确代码已改与结果已生成的区别 |
| 为同一结果准备学术说明 | 当前图表、模型估计与不确定性、纳入范围、方法说明、可引用依据与尚未解决的限制 | 使主张及其依据可一起检查，保持方法和材料的追查入口；不因进入写作就把未决解释变成定论 |

若目的所需的供者层面材料尚不存在，界面表达“缺少什么、哪一步仍待完成”；在任务原有授权范围内，Agent 可以继续获取或计算，再补入材料。系统不能为了让界面看起来完整而填造数值，也不能把“未选入当前视图”解释成“项目中不存在”。学术依据同样需来自已取得并可识别的文献。

“自主组织”包括选择与重组，不等于频繁打乱人的阅读。研究者正在检查或明确保留的材料，应继续有稳定入口；新目的可重设主次，新结果可补充相关位置。布局是否合理，首先取决于它是否让这次判断所需的关系可见、比较对象可辨、操作对象明确。美观和无遮挡不足以证明人已理解。

### 2.3 第一次阅读：在组织好的界面中理解分析

假设 Agent 已生成细胞级表达图和一次把细胞视作独立观测的检验，并开始整理其他图表。Rho 围绕上面的判断目的组织界面，其中关联的一项分析记为 `A@1`。界面连接当前比较对象、图中的分布、检验使用的观测单位、输出所对应的运行，以及 Agent 对结果的解释。尚未核对的支持关系标为 Agent 的解释，不能由系统把它升级成科学事实。

研究者从“病例组干扰素表达更高”这句话进入依据。关键交互不是再展开全部聊天，而是沿着这句话所依赖的关系阅读：

| 研究者正在判断 | 需要连起来阅读的材料 | 这一步形成的认识 |
| --- | --- | --- |
| 图里很多细胞是否等于很多独立重复？ | 图使用的细胞集合 → 供者映射 → 每个供者的观测，而非只有合并后的病例/对照分布 | 分布现象与供者层面推断需要分别判断 |
| 这个显著性究竟来自哪种比较？ | 结果中的检验项 → 实际模型或调用 → 分组与重复单位 | 能定位统计依据，判断它是否回答原问题 |
| 我读的是修改后的结果吗？ | 解释所引输出 → 产生它的运行、脚本和输入版本；已知的环境信息与缺失项 | 新代码已写、进程已结束、当前解释已更新是不同事实 |

这里的图表、代码和运行仍可使用成熟组件。方法要求保留它们在这项解释中的关系，不要求所有研究者先读代码，也不要求把一个项目的所有来源图铺满屏幕。研究者可以停在 `A@1` 继续阅读，Agent 的新活动不会悄悄替换这段解释所引用的材料。InsightLens 的聚焦和证据导航、WaitGPT 的计算表示已经提供了这类阅读交互的基础；“可停留、可展开”本身不是新贡献。

### 2.4 人的判断：修改一项解释的适用范围

研究者发现这次独立细胞检验没有处理供者内依赖，于是在该检验与供者层面结论的关联处作出修订：

> 这次细胞级检验不能作为本项供者层面关联的统计支持。细胞分布图保留作描述；按供者汇总原始计数，核对当前设计并重新分析。新的关联判断等待新结果。

自然语言是输入方式；系统需要把修订落到已选中的问题、检验和材料上。适用范围来自选择与明确声明，缺失时再澄清，不能仅凭关键词推断“所有分析以后都用同一模型”。本例的汇总选择也不被推广成适合所有单细胞设计的定律。

修订后改变的是三处相互关联的内容：旧检验不再承担这一关联的统计支持；当前解释说明为何需要另做分析；后续任务带着这个理由和范围继续。旧检验跑过、生成过哪些结果，这些事实保留。描述图可在其原用途下继续存在，不因一次推断修订就被全部判废。

并非每次阅读都要产生修正。如果研究者沿相同关系确认现有模型确实处理了供者依赖，可以直接继续比较供者间差异、提出新的问题。单纯询问“为什么”只产生带归属的解释；只有明确改变分析选择或解释状态的操作才改写共享工作依据。阅读、询问、采用和修订不应混为自动同意。

### 2.5 人还在读，Agent 已经推进：修订必须找到当前落点

在研究者阅读 `A@1` 时，Agent 可能已补出另一张描述图，使该分析推进到 `A@2`。研究者的修订仍针对 `A@1`，系统不能用这份旧视图覆盖整个当前分析。它比较修订指向的对象与目前版本：

- 若新增内容只是另一张描述图，且本次修订依赖的细胞集合、供者映射和检验没有改变，则保留新增内容，把修订接入当前分析，形成 `A@3`。
- 若供者映射或正在采用的推断方法已改变，则并列呈现原指向与当前对应内容，保留修订为待确定的意见；先确定它现在针对哪项分析，再改变相应状态。不能假称旧修订已经适用于新范围。

这种比较首先依据资源身份、明确的字段和声明关系；它不自动证明两种科学解释语义等价。关系不完整时保留未知。每项分析和每个资源各有版本，不引入一个把整个科学项目视为同时更新的全局版本。

这一操作让人的理解可以按自己的速度形成，同时使干预落在仍在演化的工作上。它不是停止整个 Agent 等待逐条审批，也不是以“已经看过”推断研究者已理解。版本协调是已有技术；此处需要设计的是它怎样作用于一项科学解释及其后续用途。

### 2.6 同一项修订成为 Agent 续接的内容

在可以接收新上下文的下一次交互边界，Agent 获得 `A@3` 的简要内容及其材料入口。示意如下：

```text
当前目的：联系细胞分布与供者层面推断；界面按这一目的组织材料。
分析 A，版本 3：当前单核细胞集合内的病例/对照供者比较。
重复单位：供者；本次输入及供者映射沿各自的保留引用读取。
当前解释：旧细胞级检验不再支持供者层面关联；描述图保留。
理由：研究者指出该检验未处理供者内依赖，修订源于 A@1。
待做：按本次选择汇总原始计数，核对设计，运行并解释新分析。
尚未知：修正后的效应与不确定性；目前不能写作新的完成结果。
依据入口：原检验、运行、输出及研究者修订，各有自己的引用。
```

这份内容与人读到的 `A@3` 来自同一批有版本的声明和引用。人可以阅读更完整的解释，Agent 可以按需取回细节；双方不必读相同像素或相同长度的文本。人折叠代码也不等于 Agent 应当忘掉代码。

接入过程区分“已准备”“已提供”和在可观察条件下的“已读取”。不能用一个“已同步”掩盖这些差别。已有在途调用不会因界面编辑而被追溯改写；无法进入其内部上下文时，就显示此次修订尚待后续接入。原生 Agent 的压缩仍由其运行时管理，Rho 在受支持的入口重新供给当前外部状态，不宣称能控制所有模型的内部记忆。

压缩也有具体对象：可以省略重复日志、完整矩阵和旧分支细节，保留取回入口；不能把当前范围、仍有效的理由、被替代的解释和未完成事项压成一句“已发现干扰素上调”。若这些内容尚未被纳入实际提供的上下文，就展示缺口，不能把磁盘上存着的笔记当作已经起作用的记忆。提供内容仍不保证 Agent 遵守；后续动作与结果要另行观察。

### 2.7 新结果回来：更新同一项解释，而非再堆一组输出

修正分析结束后，输出按实际输入、代码、运行与环境信息关联回分析 `A`；缺失的运行事实仍标为未知。新计算完成形成新的状态，例如 `A@4`，并不自动表示结论已被研究者认可。

研究者回到先前打开的版本时，能围绕自己的判断看变化：哪些数据与描述保留，哪一种检验被替代，新结果是否已经产生，原解释中哪一部分仍待重写或核对。若新模型未支持先前的关联，系统应使研究者能够将“细胞分布看起来不同”与“当前供者层面证据不足”并置理解；不能用最后一句总结抹去二者的区别。这里是假设的解释分支，不是实际发现。

新结果怎样改变科学解释，仍可能需要人和 Agent 讨论。系统可以按已有声明标出新增、替换和待核对的支持关系；不能从“进程成功退出”直接推导“新结论正确”。研究者形成的新判断再进入同一对象，而不是重新在聊天、报告和记忆中分别维护三份意思相近的文字。

这个往返使三项目标相互作用：阅读组织让判断有入口；人的判断改变共享工作依据；后续计算以与判断相关的变化返回，支持更新理解。它同时适用于确认一个合理选择、细化解释和发现问题，不只是一种报错流程。

## 3. 方法的最小组成与操作语义

### 3.1 先形成可检查的组织方案，再呈现为界面

输入包括当前目的、可用材料及其已知关系、分析进展、研究者的当前关注和可用视图能力。系统据此形成一份简要的组织方案：选入哪些对象及其版本，为什么需要它们，哪些用于比较、支持解释或继续操作，哪些材料尚缺，以及视图间如何定位同一对象。已有材料不适合某个视图时，应换用合适表示或保留缺口。

目的先落实为这次需要阅读或比较的关系，再据此选择材料。例如，判断供者间一致性，需要联系细胞与供者、分组与观测、描述材料与统计结果；仅检索包含“干扰素”的文件不能完成这项组织。系统可提出这些关系，但依据仍来自元数据、实际分析和双方的明确声明。把材料并置前，还需让它们的观测单位、纳入范围与版本可辨；不适合直接比较的材料可以用于说明差异，而非被强行画成同一组结果。

这份方案承担语义与界面之间的连接。例如，“比较这些供者”落实为具体供者集合及所引材料，界面据此形成可对照的视图；“只查看这个供者”落实为有范围的显示选择。移动窗口只改变布局，查看某供者只改变关注范围，修改纳入条件才改变分析范围。系统不能把前两种操作暗中解释成第三种。

在实现上，组件组合与模型生成的说明可以共同完成呈现。来源身份、可用操作、视图绑定和已有状态应由对应能力承接；模型可以提出材料关联与组织方式，但这些提议保留归属并可修正。因而“生成界面”不仅生成屏幕外观，还产生可读取、可操作的对象关系。这里提出的是方法所需的表示，不规定新的协议或布局算法。

### 3.2 界面与续接上下文共用有依据的分析状态

一项工作界面可以组合多个分析单元及其材料；分析单元关联科学问题及范围、方法与理由、运行与产物、当前解释、待解决事项和修订历史。它不要求新造来源本体：PROV-DM 可承接身份与修订，EVI 可承接声明的支持和质疑关系。[R02](#r02)、[R05](#r05)

其内容必须区分三种来源：实际观察到的计算事实，Agent 给出的解释与关联，研究者明确写下的判断。系统可从消息和工具记录中提出分组与关系，再让人或 Agent 修订；自动提取失败、未捕获和无法确定的关系保留在表示中。领域语义来自明示内容和可核查材料，不由 UI 凭空制造。

人的简要阅读、详细依据与 Agent 上下文是同一分析单元的不同呈现。范围、状态、有效修订和引用从明确字段生成，保留在简要表示中；详细日志和材料可以折叠或按需取回。模型补写的科学解释保留作者、版本和依据，并允许质疑。这样，压缩不会仅凭一次自由摘要决定是否保留人的修订；至于原生 Agent 收到后怎样处理，仍按前述接入边界如实记录。**共同的对象和修订关系，不等于让一个模型摘要成为唯一真相。**

### 3.3 五个操作完成一次往返

| 操作 | 针对的输入 | 产生的变化 |
| --- | --- | --- |
| 按目的组织 | 当前判断目的、可用材料与视图、关注范围 | 选择材料，声明它们的用途与关联，形成可操作布局并显示缺口 |
| 阅读与探索 | 组织中的材料、比较关系及明确版本 | 展开、定位和比较；区分显示选择、关注变化与分析范围修改 |
| 修订目的或分析 | 所选对象、目的或判断的修改，以及适用范围 | 重选相关材料或更新分析解释，保留原运行事实与人的阅读入口 |
| 从共享状态续接 | 当前目的、材料关系、有效决定、待做事项和引用 | 形成可检查的 Agent 上下文供给，记录实际接入状态 |
| 随进展再组织 | 新结果、运行变化及其与当前目的的关系 | 补入相关内容、调整必要的主次关系，并说明相对所读状态的变化 |

其中，人读的版本、分析的当前版本与 Agent 最近收到的版本分别保留，为上述操作提供可辨认的依据。范围相同也不等于结果相同，收到修订也不等于已经重新计算。

### 3.4 界面组织怎样进入人的理解与 Agent 的记忆

对研究者，材料的选择与空间组织把“为了当前判断，需要联系哪些信息”外显出来，提供从整体进入依据、比较并继续操作的路径。它是否帮助理解仍需证据；系统也可能错误选材，漏掉反例，或把不适合比较的对象放在一起。因此组织理由和未决关系应可追查，人的修正也可以针对“这里还缺一类材料”，不必总是针对错误结论。

对 Agent，记忆保留的是当前目的、已选择的对象与关系、有效决定、缺口及取回入口，不要求记住窗口像素。界面暂时隐藏材料不等于从记忆删除，固定一幅图不等于认可其结论，关闭界面也不取消分析。重开或续接时，同一组织可以帮助恢复工作上下文；真正进入模型的内容仍受接入边界约束。

两者由组织方案及其修订连接：研究者改变“我们现在要看什么、为何要看、准备怎样继续”，Agent 获得相应上下文，后续产物又进入围绕该目的组织的界面。上一版的局部解释修订是其中一种操作，不能代表这一整体。已有系统可能通过扩展实现它，论文需要说明这种组合怎样改变实际协作，而非宣称各个部件都是首次出现。

## 4. 与 InsightLens、WaitGPT 和 Mycelium 的正面对照

以下按论文明确报告的机制比较，没有运行这些系统完成本例。“未报告这项操作”是文献边界，不是不可实现性的断言。

| 工作 | 在同一个单细胞场景中已经能帮到哪里 | 本方法增加的具体操作 |
| --- | --- | --- |
| InsightLens [R21](#r21) | 持续提取并修订洞见，关联关键代码、输出和图，按主题导航；可固定关注的洞见。提取 Agent 也使用历史洞见记忆 | 从当前判断目的出发选材、组合视图和操作，并保留这份组织供分析 Agent 续接。增量不在洞见整理本身，而在目的驱动的工作界面与后续分析之间的联系 |
| WaitGPT [R18](#r18) | 将代码组织成可读的操作链，展示运行状态；可改参数、局部追问、修改代码并重跑，也支持按人的节奏回看 | 围绕科学目的组织跨图、表、模型、运行及解释的工作界面，把其中的有效选择与理由延续到后续上下文。§5.3.3 的局部追问与主对话记忆隔离；这不等于其改代码或重跑结果永远不影响后续分析 |
| Mycelium [R38](#r38) | 通过有来源的科学上下文图连接观察、解释和假设，并路由给人和 Agent。补充图 6 已示范人的科学约束进入另一条后续分析，保留来历与局部分歧 | 将相关科学状态组织成适合当前目的的可操作界面，使人的探索和修订持续改变双方工作上下文。已读方法未规定这套材料—视图—操作的组合及随目的再组织机制；科学共享状态和约束传播本身已有 |

三个差别有不同落点。对 InsightLens，组织单位从已提取洞见扩展到当前目的所需的工作材料与操作；对 WaitGPT，工作界面的组织同时联系科学判断与计算活动；对 Mycelium，科学状态的相关性进一步转化为人可共同阅读和操作的界面。**不能简写成“InsightLens 只展示、WaitGPT 只看代码、Mycelium 只有后台”。** 扩展对象范围本身仍不足以证明新颖性，关键是本方法的组织与续接操作。

Mycelium 尤其接近，甚至可以承载本方法的存储和路由。因此 Rho 不应再主张发明科学共享记忆。区别在于怎样按目的形成工作界面，并使界面的组织和交互参与持续分析；若实现只是在其图上加摘要与浏览页面，这个差别就没有成立。

### 5.1 按目的生成布局与交互，也已有直接先例

| 工作 | 已有机制 | 对本提案的约束 |
| --- | --- | --- |
| DynaVis [R40](#r40) | 根据自然语言编辑意图生成可持续操作的控件，连接图表属性和数据变换；支持组合与反复编辑 | 不能认领“按意图生成操作界面”。本提案处理持续分析中的多类材料及它们对科学判断的作用，不能仅以控件更多作为区别 |
| DashChat [R41](#r41) | 从需求和对话上下文规划任务，生成 dashboard 的内容、布局和样式，支持迭代与历史回看 | “按目的选视图并自动布局”已有先例。所读稿明确聚焦静态设计原型、排除视图间交互联动；本提案需具体处理真实分析材料、运行事实与可续接的操作 |

这些工作说明，生成式界面应进入核心对照，而非只放在外围。Rho 的候选方法需要把实际分析中的材料选择、科学关系、布局、操作与持续上下文一起说明；尚不能据定向检索宣称这个组合首次出现。

### 5.2 修订、共享记忆与科学约束的边界

SEMV 更直接覆盖“人的修订改变计算和记忆”：它将质疑定位到声明与证据，按受影响范围重算，保留前后报告，并将经核验的经历整合为后续可检索记忆。[R39](#r39) 因而“可质疑解释”“保留旧结果”“局部修正”“修正进入记忆”均不能作为 Rho 首创。其 §4.5–4.6 以核查案例的质疑及定稿后记忆整合为中心；本提案讨论的目的驱动工作界面不是由这些机制自动提供的。

Memory Sandbox 已提供可查看、编辑、摘要及返回原文的记忆；cotomi Act 已将过程整理成双方可编辑、Agent 可检索的工作区；MemGPT 已把外部记忆纳入 Agent 的工作循环。[R36](#r36)、[R37](#r37)、[R34](#r34) 共享文件、可编辑记忆和摘要回流都不是差别。

同样，AI Chains、任务分解和 Treadstone 已让人检查中间状态、调整并继续分析；Loops 已支持分析历史的比较与重访，分析来源服务意义恢复也有长期研究基础。[R35](#r35)、[R19](#r19)、[R22](#r22)、[R15](#r15)、[R01](#r01) 这些能力与版本协调共同支持持续工作，但不能替代对按目的组织界面的论证。

THREAD-Bio 则已经给出生信主张强度、重复单位和变化后持续复核的科学约束；Tisane/rTisane 已支持领域关系与统计模型的交互澄清。[R24](#r24)、[R31](#r31)、[R32](#r32) 本例的贡献不是发现伪重复、自动选对统计模型，或再次提出“主张需要证据”。这些工作帮助确定读者必须理解的内容；Rho 的方法处理这些判断在持续阅读与继续分析之间怎样发挥作用。

## 6. 为什么这个增量值得研究，以及它目前是什么

生信分析的困难在本例中体现为关系：细胞与供者、描述与推断、脚本与运行、输出与结论，以及当前选择与历史分支。不同目的需要不同的关系成为阅读重点。只压缩字数可能删掉决定解释的条件，只按时间排列产物又要求研究者自己寻找并组织依据。为当前目的选材、建立可比较关系并给出可继续操作的界面，具有实质的分析工作内容。

本方法增加的能力可由一个具体动作辨认：**研究者提出当前要判断或完成的事，Rho 从已有过程组织所需材料与操作；研究者在形成的工作界面中探索、改变目的或修订解释，Agent 从这份有对象、有范围的共同状态继续，新进展再进入相应界面。** 人不必先充当材料管理员和界面设计者，再另写一份提示词重述正在做什么。

代价也具体：系统可能误解目的、错选材料或掩盖反例；布局变化可能打断阅读；科学关系提取与范围维护会增加负担；人易读的组织未必是 Agent 最合适的上下文；运行时也未必提供可观察的接入位置。方法需要让选材、缺口和更新可检查，不能以自动生成消除这些问题。科学理解的改善仍是需要证据的效果。

**当前判断：主贡献应放在“按科学目的组织可操作、可续接的人机共享工作界面”；版本协调和解释修订是其中的支撑机制。** 这个定位比上一版更完整地解释了 Rho 的自主组织作用，也给出了可单独讨论的方法对象。新颖性仍要面对生成式界面、可视化创作与科学共享上下文的共同约束，不能仅凭这三类能力的并列存在就宣布成立。

若方法只做到自动笔记、生成 dashboard 或向模型追加摘要，已有工作足以覆盖，独立贡献不成立。候选增量必须体现在：当前目的怎样决定真实材料的选取和组织，生成的界面怎样支持有明确含义的科学操作，以及这些操作怎样通过共同状态进入继续分析。这是本版给出的具体论证方向，不是已证实的效果，也不等于解释模型内部推理或发现生物学因果机制。
