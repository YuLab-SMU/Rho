## 0. 三条判断（先给结论）

| # | 判断 | 依据 |
|---|---|---|
| 1 | **今天能写的不是「系统论文」，而是「记录模型 + 一次自我实验」。** 功能已经够多（258/258 测试、125/125 组件测试、114 个协议操作、7 套浏览器验收），但**没有任何人为证据**，也**没有与任何替代方案的对照**。 | `STATUS.md` 明确写「No independent researcher trial … has yet established ease of use」 |

## 1. 论文的主发现：完备 ≠ 可读

这是 Rho 手里最有价值、也最不像「又一个 Agent 工具」的东西，而且它是**意外**得来的。

2026-10-25 那次真实运行里，能查到的东西相当完整：Agent 读了冻结的上下文，只改了纳入规则和它的注释，R 只跑了一次，两个输出都被链接，重连后观测到同一个请求、**恰好两次原生提交**（`BASE-R-EPISODE.md:96-99`）。科学答案也是对的，且由独立表达式核对过：

> 这里的「完整」只指**文档记录显示两个输出都被链接并绑定到版本**，不是 §4.2 那个可判定的完备性 P——后者要用 E1 去测。这一句先别把话说满。

| Month | 完整案例 n | 完整案例均值 | 仅去缺失臭氧 n | 仅去缺失臭氧均值 |
|---|---:|---:|---:|---:|
| May | 24 | 24.125000 | 26 | 23.615385 |
| August | 23 | 60.000000 | 26 | 59.961538 |

**而人在屏幕上读不出来。**

- 「*The answer is not on any screen.*」——May 从 n 24 变 26、August 从 23 变 26，只能靠逐格比较两张表得到（`BASE-R-EPISODE.md:106-110`）。
- 两张表「headers and first rows are 48 px apart」，没有任何单元格被标记为变化（`BASE-R-EPISODE.md:111-114`）。
- 实现事实抢在前面：九行描述一个问题，「retained」出现五次，第一行是浏览器原文 `Failed to fetch`（`BASE-R-EPISODE.md:115-120`）。
- 数据行从 900 px 窗口的将近 400 px 处才开始（`BASE-R-EPISODE.md:121-124`）。
- 390 px 下两个版本变成两个标签页，「recall instead of recognition」（`BASE-R-EPISODE.md:125-127`）。

这就是论文的核心：

> **记录的完备性（completeness）与答案的可读性（readability）是两个独立维度，前者不蕴含后者。**
> 今天的 Agent 工具把这两件事都漏掉了：记录留在对话里，答案交给 Agent 自己复述。

同一现象在后面几轮里反复出现，而且**越是 Agent 干得多，越是漏得厉害**：

| 现象 | 数字 | 出处 |
|---|---|---|
| 110 步之后，Graph 变成一列几乎相同的卡片，问题和结果都出了屏幕 | 110 steps | `SIMULATED-PROJECT-EPISODE.md:36-38` |
| 第九个视图撞上布局上限，最新的那个（答案文件）显示「reached its view limit」 | 8-view budget | `SIMULATED-PROJECT-EPISODE.md:32-33` |
| 捕获预算被重复读耗尽，2,024 次捕获被省略，于是决定里那些结果显示「Not covered」 | 64 记录/轮 | `SIMULATED-PROJECT-EPISODE.md:194-198` |
| 模型把「已取消」的命令说成「执行前就被拒绝」，而 gate 的入口标记与 PID 证明它已经启动 | 一次真实事件 | `ACP-EPISODE.md:184-187` |
| 模型把一列表头读成「circumference」，把 mean ± SD 面板读成「bubble charts」 | 两次 | `SIMULATED-PROJECT-EPISODE.md:649-651,753-754` |

两个模型事件合起来说明同一件事，而 Rho 自己的文档已经写出了结论：

> **model prose is not execution evidence**（`ACP-EPISODE.md:187-188`）

于是论文的第二条主张有了形式：

> **呈现必须由记录派生（derived），而不是由 Agent 复述（narrated）；叙述必须被标注为叙述。**

Rho 的 Graph 已经在这么做：边的依据只有「Agent 报告 / 命令提到 / 观测到同时变化」三种，且明确「none infers production」（`GRAPH-EPISODE.md:65-72`）。这是一个可以被检验的设计原则，而不是一句口号。

## 2. 一句话主张与对比对象

按第二份笔记的检验法，把贡献写成「在 __ 场景下，做 __ 比做 __ 更好」。三个候选，只有一个能用现有的证据路线兑现：

| 候选 | 句子 | 能否兑现 | 判决 |
|---|---|---|---|
| A（交互） | 在人与 Agent 共同分析时，把工作组织成「答案 + 保留版本」，比按文件/标签页组织，更容易让人说出「什么变了」 | 需要人研究（现在为 0） | 独立成立，但今天写不了 |
| B（记录） | Agent 参与的分析应保存为**可离线核查的记录**：每条被引用的结果能解析到保留版本与运行事实，缺失必须显式声明 | 可用现有证据包机械测量 | **作为论文主体的骨架** |
| C（观点） | 呈现必须由记录派生，不能由 Agent 复述 | 需要一个反例 + 一个小测题 | 作为**机制解释**，不单独当主张 |

**推荐的主句**（B 为主体，A 作为验证，C 作为机制）：

> 在「人 + 外部 Agent 共同完成一次数据分析」的场景下，**把一次回答保存为可离线核查的记录、并让呈现从该记录派生**，比**把工作留在对话记录与工作目录里**，更能让人在不重跑分析的情况下说清「什么变了、为什么变、能不能信」。

对比对象（必须点名，不能含糊）：**transcript + working directory**，即 Claude Code / Codex 的原生体验，加上 git 或文件时间戳。这是真正的对手，不是稻草人。

三条消融基线由这句话直接长出来，不需要额外设计：

| 基线 | 是什么 | 从主句的哪半句掉下来 |
|---|---|---|
| T | 只有对话记录 | 去掉「保留版本」 |
| G | 只有工作目录 + git | 去掉「哪一次回答」 |
| TG | 记录 + 版本（最现实的替代方案） | 去掉「事实分离」与「缺口声明」 |
| R | Rho 的记录 | 完整 |

**没有一个对比对象的句子不是主张。** 这也是为什么 T/G/TG 必须出现在摘要和引言里——它们是那句话的另一半。

## 3. 被修补的公共瓶颈

必须是**公共的**（别人也疼）且**可验证的**（不是修辞）。三条，每条都能用一个已有事件演示：

| # | 瓶颈 | 现有做法的失败 | Rho 里的可验证演示 |
|---|---|---|---|
| 1 | **引用与字节脱钩**：Agent 说「图在 figure.png」，而 figure.png 已经被重写三次 | 对话记录只剩文字，工作目录只剩最后一版 | 一次 13 分钟的 run 里脚本被保留 26 次、图 2 次（`SIMULATED-PROJECT-EPISODE.md:350-354`）；figure 被重写两次并两次作为图像送出（`SIMULATED-PROJECT-EPISODE.md:749-752`） |
| 2 | **「完成」被当成「正确」**：完成 / 字节完整 / 领域检查 / 模型解释被压成一个绿灯 | 客户端读到 `more_retained` 就以为日志完整，实际 `truncated true`（`CORE-VALUE-EPISODE.md:41-44`）；模型把取消说成拒绝（`ACP-EPISODE.md:184-187`） | Rho 把四类事实分开，视图副标题写「completed · bytes verified · no domain check」（`BASE-R-EPISODE.md:115-120`） |
| 3 | **未知被当成失败**：丢了 ack 就重发，重发就换身份 | 通用工具普遍会重试；重试让「同一件事」变成两件 | Reconnect 观测同一请求摘要，**恰好两次原生提交**（`BASE-R-EPISODE.md:76-79`）；消息读作 unknown 且**永不重发**（`ACP-EPISODE.md:37`） |

**为什么这不是 UI 问题**（论文必须主动说，否则会被当成界面工作）：

- 瓶颈 1 的修复是**数据模型**：保留版本是内容寻址的、绑定到消息的，而不是路径 + 时间戳；
- 瓶颈 2 的修复是**协议**：unknown ≠ failure，决定 ≠ 授权，完整性 ≠ 正确性；
- 瓶颈 3 的修复是**执行身份**：原始请求身份优先于「再跑一次」；
- 界面只是**三个消费者之一**：人看、Agent 写、第三方离线核查。三者共用一份记录——这才是「接口」，不是「皮肤」。

## 4. 形式化：记录模型与它的消融轴

形式化的产出不是漂亮定义，是**一组合法的减法**。

### 4.1 记录模型（四类事实 × 三种绑定 × 一个声明）

| 成分 | 内容 | 今天的实现 |
|---|---|---|
| **四类事实** | 执行完成 / 字节完整 / 领域检查 / 模型判断 | 分开报告，不合并（`ARCHITECTURE.md` 执行连续性；`STATUS.md`） |
| **绑定 1**：消息 ↔ 版本 | 哪一次回答保留了哪些字节（内容寻址） | Files 捕获 + 会话记录（`REVIEW-EVIDENCE-EPISODE.md:20-27`） |
| **绑定 2**：决定 ↔ 版本 | 人的接受/要改绑定到具体版本；被新版本取代而不删除 | `conversation.decide`，append-only（`SIMULATED-PROJECT-EPISODE.md:173-176`） |
| **绑定 3**：视图 ↔ 版本 | 每个视图命名它显示的那个保留版本，而不是「当前文件」 | Studio 文件视图、答案板、检查器 |
| **缺口声明** | 预算耗尽、legacy、unavailable、limited 都必须被**命名** | 「Exhaustion preserves earlier evidence」（`STATUS.md`）；Graph 显式标缺口 |

### 4.2 一个可判定的性质 P

这是全文的技术核心，也是「先造裁判」那一步的产物：

> **P**：对回答中的每一个结果引用 r，记录里存在 (消息 m, 保留版本 v, 运行事实 f)，使得 v 的摘要与 f 当时观测到的字节一致；**若不存在，记录中必须有一条显式缺口条目**。

P 的三个好处，正是 Rho 相对其他 Agent 工具的结构性优势：

1. **可离线判定**——不需要服务、不需要原项目，`rho --verify-evidence` 已经在做摘要与清单核对（`REVIEW-EVIDENCE-EPISODE.md:112-119`）；
2. **可对历史判定**——旧记录按旧规则读，缺口如实显示，不追溯补写（`REVIEW-EVIDENCE-EPISODE.md:95-96`：later capture cannot supply bytes at an earlier time）；
3. **可被第三方判定**——导出包是静态 HTML + 原始字节 + 最后写入的 `evidence.json`，一次试验里关闭 Rho、移动项目、离线打开，并检测到被改动的字节（`REVIEW-EVIDENCE-EPISODE.md:104-119`）。

注意边界，写论文时一个字都不能省：**完整性不建立科学正确性，也不建立作者身份**（`REVIEW-EVIDENCE-EPISODE.md:116`）。

### 4.3 五条消融（每条都要一种**特定失败方式**，不能只是变差）

| 减法 | 被拿掉的东西 | 预期失败模式（这才是结论） | 对应错误信念 |
|---|---|---|---|
| A1 | 保留版本 | 重跑之后，人把**今天的文件**当作当时的证据 | 历史误认 |
| A2 | 消息绑定 | 知道「变了」，但说不出「谁改的、为什么改」 | 归因错误 |
| A3 | 事实分离 | 把「字节校验通过」读成「结果正确」 | 过度信任 |
| A4 | 决定绑定 | 把「我说过可以」扩到之后的版本 | 作用域错误 |
| A5 | 离线包 | 第三方只能重跑，而重跑改变证据本身 | 不可核查 |

A1–A5 每一种都对应一类**可测量的错误信念**，而不是一个更低的分数。这是从 Reflexion 的 2×2 表学来的写法：两个消融的失败方式不同，才能说出「测试负责发现问题，反思负责把问题变成改法」；这里要说出的是「版本负责可追溯，事实负责可信任」。

**工程上的关键取巧**：A3、A4、A5 可以**用同一份记录渲染受限视图**来消融，不需要重造三个系统；A1、A2 用「当前文件 + 时间戳」这类替代材料近似。这让消融的成本从「几个月」降到「几天」，同时消除了实现差异这个混淆变量。

## 5. 裁判：三层，只有前两层能进正文

第一份笔记里最反直觉的一条：**评估先于方法**。Rho 的处境特殊——六个工作里一半花在造裁判上，而 Rho 已经把裁判造好了，只是没用来评自己。

| 层 | 裁判 | 可扩展到什么规模 | 结论能否进正文 |
|---|---|---|---|
| **J1 机械** | 性质 P 的检查器：对某个证据包，算「可解析引用比例」与「缺口声明率」 | 几千次运行，离线，零人力 | ✅ 主指标 |
| **J2 人因（有 oracle）** | 四类测题，答案由**独立 oracle** 判定：定位（哪个参数变了）/ 归因（因为什么规则变了）/ 信任边界（通过了什么检查、没通过什么）/ 作用域（你的决定覆盖哪些版本） | 小样本即可（N=5 一轮，N=12 交叉） | ✅ 主指标 |
| J3 主观 | 信任/偏好量表 | 便宜 | ⚠️ 只做附录，不能单独支撑任何主张 |

**J2 为什么比常见的 HCI 评估强**：大多数 Agent 界面评估只能测「主观信任」，因为任务没有客观答案；Rho 的任务有独立 oracle——`airquality` 的五个聚合值由独立 base-R 表达式算出，胶囊题有 gold answer，Iris 试点有 subset-sum DP。**因此 Rho 可以测「理解得对不对」，而不只是「感觉好不好」。** 这一点应该写进 contribution，它同时回答了「你凭什么说你更好」和「你怎么不自己评自己」。

三条预先写死的判据（照抄 `work/core-comparison-20261029/PROTOCOL.md` 的传统：让答案无法在数字出来之后才被决定）：

1. **呈现的失败判据**（仓库里已有原文）：若人仍然需要比较两张表才能找到变化，呈现就是错的，而不是不够精致（`BASE-R-EPISODE.md:147-148`）。
2. **记录的失败判据**：若 transcript+git 也能解析 ≥80% 的引用，则「记录」不是主要瓶颈。
3. **人的失败判据**：若答案板在「定位 / 归因」两项上没有跑赢 TG，则设计主张不成立，改设计，不写论文。

## 6. 实验计划 E1–E6

按成本从低到高排。E1 不需要任何新的 Agent 运行。

### E1 · 记录完备性（无新运行，**先做这个**）

- **问题**：给定「最终回答引用了哪些结果」，四种材料各能解析出多少？
- **臂**：T（transcript）/ G（git）/ TG / R（Rho 证据包）。同一组引用，同一次运行。
- **材料**：`work/` 下已有的证据包——base-R、review-evidence、report-evidence、bix-18/bix-41 的各次副本、graph acceptance。
- **指标**：解析率；**错误解析率**（解析到错误版本）；缺口声明率；按步数分档画退化曲线（已观测到 39 与 110 steps 两档）。
- **成本**：写一个 checker（输入 evidence package），约 1–2 周。
- **产出**：Table 1 + 一张「解析率 vs 步数」的图。**这是全文最便宜、最有说服力的证据。**

### E2 · 呈现消融（受限视图）

- **臂**：完整 / A3 / A4 / A5 四种受限视图（同一记录）。
- **指标**：四类测题的正确率 + 错误类型分布。
- **成本**：低（渲染层过滤）。可与 E3 合并在一轮里做。

### E3 · 人的理解（交叉设计）

- **先 N=5 一轮**（Nielsen 的小样本重复轮次，`DEVELOPMENT.md` 已引用），修一轮，再 N=12。
- **设计**：同一任务、同一模型、同一提问；人在两个臂之间交叉；测题按字段二元打分；记录时间、卡住的位置、求助。
- **这是 DEVELOPMENT 的第 3 阶段**（「一个没造它的人能不能不用帮助完成」）——仓库里反复写着「No independent researcher has used these screens」，这是唯一能消掉那句话的实验。

### E4 · 失败路径矩阵（现成数据，整理即可）

| 故障 | 注入后人员能得出什么结论 | 出处 |
|---|---|---|
| 丢失应答 | 同一请求，两次提交，不重发 | `BASE-R-EPISODE.md:68-79` |
| 浏览器离线中运行 | 重连观测同一 digest | 同上 |
| 原生 kill -9 | `Gone{MainPidAbsent}`，保留记录，不重新派发 | `CORE-VALUE-EPISODE.md:49-51` |
| 输出截断 | 报告缺口，但「只读 more_retained 会误读为完整」 | `CORE-VALUE-EPISODE.md:41-44` |
| 预算耗尽 | 保留先前证据，结果标为 Not covered | `SIMULATED-PROJECT-EPISODE.md:194-198` |
| 磁盘/缓冲分叉 | 磁盘有 Agent 的行，缓冲有人的行，手工和解 | `DOCUMENTS-EPISODE.md:28-34` |

**这张表本身就是论文的系统贡献**：多数 Agent 工具在这些情况下什么都不说，而 Rho 有一份「能得出什么结论」的清单。

### E5 · 移植性与第三方

- 篡改检测（已有：检测到被改动的字节）；

### E6 · 跨域与跨模型

- DESeq2 真分析（roadmap 第 3 项）+ 一个第二领域；

## 8. 断言强度账本

第二份笔记里最伤人的一条：**断言强度必须匹配证据强度，说过头一次，整篇打折。** 下面是 Rho 的账。左边是想写的话，中间是今天的证据，右边是今天**能写成的样子**。

| 想写的句子 | 今天的证据 | 缺什么 | 今天能这么写 |
|---|---|---|---|
| Rho 让 Agent 工作可审计 | 机制 + 单例 | E1 的解析率 | 「每条引用被绑定到保留版本；缺失被声明；在 N 次运行中 X% 可离线解析」 |
| 记录完备但答案不可读 | 有（一次运行、五条观察） | 重复与第二个人 | 「in one run」的定性发现 + E3 验证 |
| 人更容易理解 | **无** | E3 | 不写；或写「我们未验证主观可读性」 |
| 未知不会被重跑 | 有（故障矩阵、两次提交） | 更多故障类型 | 直接写，附矩阵 |
| Core 更慢 / 更贵 | 有（一次、单模型、已修正因果） | 重复 | 「these runs」+ 机制，不写「Core 无价值」 |
| 结果可复现 | 有 manifest/digest/ledger/verifier | —— | 「记录可被第三方核查」；**不写**「科学结论可复现」 |
| 跨平台 / 跨模型通用 | **无** | E6 + 平台验收 | 不写 |
| 提升科研效率 | **无** | —— | 不写 |

配套的「断言 ↔ 最低证据」对照（把第二份笔记那张表填成 Rho 版）：

| 想说的话 | 需要的最低证据 | Rho 现在 |
|---|---|---|
| 我们观察到 | 一次清晰演示 | ✅ 有很多 |
| X 优于 Y | 同预算、多次重复、报 avg | ❌ |
| 收益来自部件 Z | 去掉 Z 显著退化 | ❌（E2 未做） |
| Z 是必要的 | 去掉 Z 出现**特定失败模式** | ❌（E2 的设计已给出失败模式） |
| X 能泛化 | 跨任务 + 跨域 + 迁移 | ❌ |
| X 改变了这个领域 | 他人复用 | ❌ |

今天这张表的右列几乎全是 ❌——这就是「先跑实验再动笔」的全部理由。

## 12. Critical path：按成本排的下一步

顺序遵循「先找裁判 → 最窄配置 → 再加规模」。

|---|---|---|---|
| **0（本周）** | **冻结证据快照**：把 `work/` 下要用的证据包复制成只读，记录 digest；修掉文档内部不一致 | 一份 `evidence-index` + digest | 若证据包本身缺关键文件 → 先补记录 |
