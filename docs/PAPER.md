# Rho 的研究定位：共同维护科学分析的工作状态

更新：2026-10-30。本版修正研究对象：Rho 持续整理 Agent 的工作过程，形成双方可查看、可操作的呈现；这些材料也可以成为 Agent 的外部上下文与记忆，参与下一步工作。上一版只分析“研究者如何审阅一项科学结论”，不足以判断这个整体。**目前值得继续论证的是人和 Agent 如何共同维护正在进行的分析状态；“共享 UI + 记忆”本身已有直接先例，独立贡献仍须落到具体方法。** 本文不排实验，不规定未观察过的界面，也不从现有功能反推新颖性。当前实现以 [Status](STATUS.md) 为准。

## 1. 研究单位是一段持续协作，而非一次答案审阅

研究者提出问题，Agent 读数据、修改脚本、运行计算并解释结果。Rho 将可观察的动作、文件变化、运行事实以及双方写下的说明组织起来。研究者据此判断进展、查材料、修正方向；Agent 也可以读取这些材料来继续分析、恢复上下文或接受修正。新的行动又改变工作状态。

> 分析行动 → 持续整理的工作状态 → 人的查看与修正、Agent 的上下文与记忆 → 下一步分析行动。

这才是需要研究的完整关系。界面里的选择、说明和结果，如果会进入下一步分析所依据的上下文，就已经参与了计算过程。Rho 的作用不能仅用“完成后是否更好读”来描述。

这里的“工作状态”包括当前问题、正在采用的方法及理由、材料与版本、已经取得的结果、仍未完成的计算、待查的疑问，以及已被替代的选择。它不是只有成功结果的总结，也不是所有历史的堆积。

“共享”也有具体含义：双方能够指向同一个问题、决定、结果或运行，并据此交流和操作。人可以通过图、表和笔记理解，Agent 可以通过文件、结构化数据和工具读取。两者不必消费相同像素，但不能在关键对象和状态上各说各话。共同可访问尚不等于双方都已读取，更不等于已经理解。

“实时整理”指随工作推进逐步更新，不意味着零延迟、完整捕获或自动正确。可研究的过程是公开消息、工具活动、产物和明确表达的理由；不能把它说成读取了模型完整的内部推理。

## 2. 沿同一次单细胞分析，看工作状态如何进入行动

以下是用于推敲机制的构造场景，没有实际效应量、用户观察或压缩失败记录。仍采用 6 名病例、6 名对照，每名供者贡献多个单核细胞。原始计数、细胞注释和供者映射均可获得。目标是判断这些供者中是否存在疾病相关的干扰素表达差异。

### 2.1 开始分析：双方要保留的不是一句任务标题

研究者知道疾病分组属于供者，不能把同一供者的多个细胞直接当成独立生物学重复。这个前提会约束模型和不确定性解释；相关方法学后果已有证据。[R25](#r25)

Agent 同时要处理细胞选择、计数层、设计信息、包与运行环境、脚本及输出。研究者未必逐条读它的命令，Agent 的上下文也不适合永远包含所有日志。双方需要在工作推进中反复使用的，是“本次比较针对供者；这些细胞怎样对应供者；当前分析怎样处理这种依赖；依据在哪里”。

这不是要求 UI 自动作出统计判断。研究者提供或核对科学前提，实际代码和输入说明做了什么，运行结果说明哪些计算已经完成。三者不能由一段流畅的总结相互替代。

### 2.2 分析中途：修正应改变双方接下来依据的状态

假设 Agent 为了快速出结果，使用了没有处理供者内依赖的独立细胞检验。研究者从方法与结果的联系中发现问题，指出：“这项检验不能支持所要求的供者层面关联，改用适合当前设计的分析。”

上一版停在研究者怎样作出这一判断。现在继续追问：这次修正之后，双方各自认为当前任务处于什么状态？

| 需要共同维护的内容 | 在本例中的具体含义 |
| --- | --- |
| 当前问题与前提 | 仍在判断供者层面的关联；供者内依赖需要处理 |
| 已被替代的分析 | 原独立细胞检验及其文件仍是历史材料，其显著性不再承担该关联的统计支持 |
| 当前行动 | 正在准备或运行修正分析；写完脚本、提交计算、得到结果是不同状态 |
| 修正理由与范围 | 修改的是这项推断的分析依据，不是宣布原始计数全部错误，也不是宣布疾病关联不存在 |
| 仍不知道的内容 | 修正后效应和不确定性是否保留，需要等待并检查结果 |

这张表表达任务中的信息关系，不是拟定五个新控件。研究者不应只在聊天里留下纠正句子，随后仍面对一份把旧结论列为当前发现的摘要；Agent 也不应只收到“重新运行”而丢掉为什么要改、哪种解释暂不能用。

### 2.3 压缩或续接：存过什么与正在依据什么可能分离

设想工作跨越上下文压缩、会话续接或 Agent 更换。某份摘要只留下“已完成单核细胞差异分析，发现干扰素上调”，遗漏了后来对重复单位的修正。旧脚本、聊天和笔记其实都在，但下一步生成报告时仍可能沿用旧结论。这是待考察的失配情形，不能冒充已在 Rho 观察到的故障。

此时需要处理的不仅是找回历史。研究者要能看清并修正**接下来被作为工作依据的内容**：旧发现为什么退为历史结果，当前分析采用什么条件，新的计算是否已经结束。Agent 则需要在有关行动发生时获得适用的版本，并能沿简要记录找回原始材料。

把全部历史重新塞入模型、把所有日志铺在屏幕上，都没有替双方完成当前与过往、事实与解释、已做与待做的区分。相反，一份更短但混淆这些关系的摘要，会把错误带入后续工作。

### 2.4 继续分析：人的局部修正不能被误当成全局真理

研究者下一步可能比较另一种细胞类型，或更换目标问题。先前决定是否仍适用，要看它所针对的设计、数据与推断；不能把“这次需要处理供者依赖”压成“所有分析必须使用某个固定软件或模型”。

同样，Agent 生成的新解释可能与研究者的判断不同。共享状态应允许看到这种差别，而非把二者自动合并成一段无署名的共识。研究者的科学意见、运行事实和模型推测具有不同依据；共同编辑不消除这种区别。

这个场景因此从“发现一次错误”扩展为“维持一次修正对后续工作的实际作用”。计算环境也在其中：脚本已修改但旧进程仍在运行、输出已经产生但报告还引用旧版本，都会使“当前进展”不能只由计划或叙述决定。这里列的是同一协作过程可能遇到的状态关系，并未声称 Rho 已解决所有关系。

## 3. 为什么生信复杂度在这里有实质作用

单细胞工作同时涉及生物实体、统计单位、计算对象和学术主张。“sample”可能指供者、组织样本或文库；“完成”可能指代码生成、进程退出、产物出现或解释已核对。这些词在摘要中看似简洁，丢掉关系后却会改变下一步行动。

科学理由还可能比结果本身更需要持续保留：为什么不采用一个检验、某个结果只支持哪一级解释、哪些细胞或供者被纳入。失败和被放弃的选择也会约束未来工作，不宜因“没有产出最终结果”而被摘要删去。

因此，高信息密度不是多展示几个面板的理由。它提出了两个并存的要求：人需要足够简洁的组织来掌握工作，Agent 也需要选择性上下文来行动；被省略的细节又可能恰好决定某个科学判断是否适用。**值得研究的是这种压缩与继续使用之间的关系，而不是把生信复杂性本身称为贡献。**

已有领域知识不能由整理过程补造。元数据缺失时仍需查明；统计判断错误时仍需专业修正；运行情况不可观察时仍是未知。共享工作状态的价值若成立，应体现在双方怎样利用和修正已有材料，而非宣称它会自动保证科学正确。

## 4. 原来的相关工作仍重要，但不足以覆盖新的分析单位

以下只比较已读材料报告的机制。没有运行这些系统完成本例；“未报告”不等于技术上不能扩展。

### 4.1 InsightLens：已经是过程中整理，不能归成事后展示

InsightLens 随对话提取并修订洞见，关联关键代码、输出、图表和解释。其洞见提取 Agent 本身保留过去的洞见作为记忆，以支持一致提取与修订。[R21](#r21)

它能帮助人找到上例的发现和依据，也能反映对话中的修正。因此，“实时整理”“压缩解释”“有来源的洞见”都不是有效差别。需要进一步区分的是：组织洞见所用的记忆，与执行下一项科学分析所依据的上下文，是否是同一套可由双方修正、且有明确使用边界的工作状态。已读机制不能直接证明后一关系，亦不能据此断言它绝对无法支持。

### 4.2 Loops：恢复、比较和继续分析已有扎实基础

Loops 记录 notebook 演化并比较代码与多类输出，论文还包含跨周工作及肺癌数据处理改变解释的案例。[R15](#r15) 它能帮助研究者重新进入分析、看出模型变化并比较修正结果，不能被贬为静态档案。

新问题不在“可否回看”，而在回看所得的决定怎样进入 Agent 接下来使用的上下文，并在后续整理中保持适用范围。给 Loops 接上 Agent 或笔记并非不可行；若这些已有机制已经足够，则没有理由另称一种新方法。

### 4.3 EVI：表达支持与质疑，不负责全部状态使用

EVI 可表达主张、支持和质疑，并沿声明的支持关系传播质疑；质疑不等于判错。[R05](#r05) 这足以承接“旧检验不能再支持该关联”以及它影响的解释。

它作为本体并不规定界面怎样压缩任务、模型何时读取哪些内容，或双方如何修正正在使用的上下文。这里是表达模型与协作机制的层次区别，不是 EVI 的缺陷，也不能把补一个操作界面直接当作研究创新。

### 4.4 THREAD-Bio：科学约束高度重叠，时间维度也不是空白

THREAD-Bio 已明确区分不同强度的主张，直接讨论单细胞的生物学重复，并要求在有科学后果的变化后持续复核；其讨论还承认维护与审阅负担。[R24](#r24) 不能把它说成只关心最后报告，也不能认领“主张—前提—证据”或“变化后重查”的原则。

新的分析单位是这些条件怎样成为双方正在使用、可持续修正的工作状态，尤其怎样穿过上下文压缩和续接。THREAD-Bio 的相关章节没有提供这一完整交互方法，但这一差别只说明需要比较另一组文献，不能单凭概念框架未实现某界面就宣布方法空白。

原先“核对意图与实际模型”的路线也仍受 Tisane/rTisane 约束：声明单位、层级和领域假设，再通过交互澄清并推导模型，已有明确方法。[R31](#r31)、[R32](#r32) 新定位不重新认领这些贡献。

## 5. 必须正面对照的共享上下文与记忆工作

补充检索改变了最接近的先例。不能继续只围绕 InsightLens、Loops、EVI 或普通聊天找差别。

| 工作 | 已有机制 | 对 Rho 候选贡献的直接约束 |
| --- | --- | --- |
| Memory Sandbox [R36](#r36) | 将对话记忆变成可查看、编辑、隐藏、排序、摘要及跨会话共享的对象；摘要可返回原文 | “人能看见并修改 Agent 的记忆”和“压缩后可展开”早有直接交互先例 |
| MemGPT [R34](#r34) | 分层上下文、自主读写与检索记忆、容量提示及事件驱动的继续运行 | 外部存储参与 Agent 的认知与控制循环，不是 Rho 首创 |
| AI Chains [R35](#r35)；WaitGPT 与任务分解 [R18](#r18)、[R19](#r19) | 暴露中间状态，支持修改及后续生成；监控和引导分析过程 | “UI 中改一处，改变 Agent 下一步”已有方法；任务分解研究还报告修改被忽略、下游编辑被覆盖的问题 |
| Treadstone [R22](#r22) | 人和多个 Agent 在共享讨论中分析，持续组织语义与关联并主动提出方向 | 同时整理过程、呈现关系和影响后续分析，也已有接近的分析系统 |
| cotomi Act [R37](#r37) | 从活动整理任务、时间线和 wiki，双方可编辑；Agent 在行动中按需检索工作区 | “过程自动整理 → 共享 UI → 人的修订 → Agent 后续使用”的整体循环已有实现，不能只凭把几部分连起来主张新颖性 |
| Mycelium [R38](#r38) | 科学共享上下文图保留来源与跨会话假设，向相关人和 Agent 路由上下文；报告生物多组学部署 | 不能再把“共同科学状态进入后续决策”或“用于生信”作为尚无人研究的组合 |

Memory Sandbox 是设计探针，其论文将人的效果研究留作后续；这限制效果证据，不消除机制先例。cotomi Act 的行为知识测量使用成功 Agent 轨迹作为用户行为代理，不能写成长期真实用户协作已被充分验证。Mycelium 本文采用的是 2026 年预印本，报告的部署也不代表所有科学场景。这些证据范围需如实保留，但不能用来回避它们对新颖性的约束。

分析来源支持意义恢复本身也早有研究议程。[R01](#r01) 因而 Rho 不能仅通过把“审阅”改名为“共同认知”来获得贡献。

## 6. 候选方法需要讲清哪一个具体操作

目前更准确的问题是：

> 在持续推进的科学分析中，如何把不断变化的过程整理为双方共同维护的工作状态，使研究者对方法、材料和解释的修正，能在 Agent 的上下文选择、压缩与续接之后，仍以适用的范围进入下一步行动？

这比“让人理解 Agent”具体，但仍是研究问题。一个可讨论的方法草图，是围绕**同一个可定位的分析决定，连接人的修正、当前摘要、原始依据和 Agent 的实际上下文入口**。在单细胞例子里，它要解释下面这一次操作怎样完成：

1. 研究者修正的是“这项供者层面比较怎样处理重复”，并指明相关分析，而不是只新增一条游离聊天。
2. 整理后的当前状态体现修正，保留被替代结果的历史身份、原始材料和理由；不能把仍在运行的修正分析写成已有新结论。
3. Agent 在继续相关工作时获得这一状态及其来源入口。提供了内容、实际取到了内容、生成动作符合修正，是三件不同的事。
4. 后续摘要可以省略无关日志，但若省略了这次决定的理由或范围，双方能够定位并修复这个压缩结果；恢复细节不要求人工重讲整段经历。
5. 新行动及其结果再进入同一过程，表明修正分析做到了哪一步。若研究目标、数据或适用条件改变，就重新判断这项决定，而非永久套用。

这些步骤是用于比较方法的任务链，不是已经实现的交互，也不是产品验收清单。PROV-DM 等已有来源表达可以承接对象身份、修订和归属，没必要先发明一套新本体。[R02](#r02) Memory Sandbox、共享 wiki 和带来源的上下文图已经覆盖其中不少操作。

**剩下可能值得研究的，是这条任务链在不同表示之间怎样保持联系、如何暴露断裂，以及怎样用一次有范围的修正恢复后续工作。** 人看到的当前决定、Agent 获得的摘要和计算实际使用的材料不一定同步；修复其中一处，也可能留下其他两处不变。一个具体方法需要说明如何处理这种分离，而不能以“LLM 会整理并理解”带过。

科学场景使断裂的后果具体，但没有自动提供解决方法。当前文献核查不能证明所有已有方法都解决不了这条任务链；已有方法的组合或扩展可能足够。若最终方法只是自动更新笔记、手工编辑摘要或向模型追加上下文，应承认它仍主要是已有机制的应用。若能给出不同于这些先例的表示与修正机制，才有独立贡献可讨论。

独立贡献不要求每个部件都是新发明，也不以新算法为唯一门槛。已有技术的整合可以形成新的协作机制，或揭示可迁移的设计认识。判断单位应是整段工作怎样因此改变，以及这种改变如何产生。上一版逐项指出已有先例，却没有充分分析部件之间的联系，也不足以否定系统研究；同样，列出多个部件并说“形成闭环”，仍没有完成这个论证。

## 7. 现有 Rho 与这一定位的关系

以下仅核对产品事实，避免把研究设想写成现成能力。

| 已有机制及依据 | 可以作出的判断 | 尚不能作出的判断 |
| --- | --- | --- |
| [共享笔记指令](../src/project-notes.ts) 与 [会话接入](../src/conversations.ts) | Rho 把共享文件及持续更新要求交给所启动的 Agent；人和会话可使用同一笔记 | 所有会话已读取最新内容，或原生压缩一定保留了每项修正 |
| [Project notes](SIMULATED-PROJECT-EPISODE.md#project-notes)、[meaning layer](SIMULATED-PROJECT-EPISODE.md#meaning-layer) | 笔记参与界面组织，语句可联系保留的文件与过程；它不只是最终报告附件 | 每段总结科学上正确、更新必然及时，或所有生成描述都已回流到 Agent |
| [上下文与反馈](COLLABORATION.md#feedback-and-explicit-response) | 准备、读取与显式回复具有不同记录；可把有来源的内容交回 Agent | 读取即理解，回复即执行，或界面中可见即已进入模型上下文 |
| [架构中的状态归属](ARCHITECTURE.md#state-and-lifecycle-ownership) | Rho 可以参与外部工作记忆和上下文供给；模型上下文仍由 Agent runtime 持有 | Rho 已接管所有原生 Agent 的压缩算法或内部记忆 |
| [保留证据](REVIEW-EVIDENCE-EPISODE.md#capture-and-review) 与 [原生工具边界](NATIVE-TOOLS-EPISODE.md) | 能区分保留内容、观察范围与未知情况 | 所有关系都是完整运行来源，或记录、呈现、真实执行已自动一致 |

因此，“Rho 本身是 Agent 记忆的一部分”可以作为系统定位：它保留并提供后续可用的外部状态。它不要求 Rho 接管模型内部上下文，也不应把可供读取误写成已被使用。当前记录还明确保留了 Agent 延迟到结束才写描述的现象，不能把“指令要求持续整理”说成已经保证实时更新。

已有功能、运行记录和负面案例帮助判断探索条件，不证明人的普遍困难或新方法有效。协议数、通过率、独立数值 oracle 与证据包摘要校验，都不能替代对这段协作关系的论证。本文没有新增产品要求或批准步骤。

## 8. 当前判断与检索边界

应撤回的是上一版从一个狭窄审阅场景推到整个 Rho 的否定。仍应保留的是：供者重复检查、主张与证据关联、历史比较及领域前提澄清，不能单独承担新贡献。

本版确认了更恰当的研究单位，也找到了更直接的竞争工作。**这条共享工作状态的路线值得继续分析，但目前还不是已成立的论文贡献。** 广义循环已有先例；潜在增量要在过程的持续整理、双方面向任务的使用，以及有范围修正如何穿过压缩和续接之间找到具体机制。不能先宣布一个大系统贡献，再把未解决部分写成未来实验。

检索截止 2026-10-30，采用原论文、作者稿、规范和官方文档，属于定向检索与引文追溯。本轮补查记忆交互、共享知识工作区和科学上下文路由，重核 InsightLens 的记忆用途以及本地笔记、反馈和模型上下文的边界。没有安装复现比较系统，没有独立验证论文效果，也没有以文献未报告某能力证明其不可能实现。
