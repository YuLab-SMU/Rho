# Rho 的方法提案：从共同阅读分析到共同续接分析

更新：2026-10-30。本版给出一项具体交互方法，取代只描述“可阅读性、理解与共享记忆”的研究问题。**拟议贡献是：让研究者正在阅读的分析解释成为可修订、可续接的工作对象；一次针对解释的局部修订，同时改变可见的分析状态和供 Agent 续接的上下文，新结果再回到同一对象，说明相对研究者所读版本发生了什么变化。** 方法必须处理人读得慢、Agent 仍在推进、双方依据的版本可能不同这一情况。

这是一项方法提案，不是现有 Rho 已完成或已证明有效的能力。以下用构造的单细胞场景说明对象、操作和状态变化，正面对照 InsightLens、WaitGPT、Mycelium 及更接近的反例。不排实验，不给未观察过的屏幕制定布局或验收规范；当前产品事实仍以 [Status](STATUS.md) 为准。

## 1. 独立贡献落在一个操作上

这项操作可以直接说成：**研究者在自己正在读的那一版分析上修改解释或选择，系统保留修改的对象与范围，将它接入当前分析和 Agent 的后续上下文，再把后续结果作为这项分析的更新返回。**

研究者操作的单位是“一项科学问题及其分析依据”，例如“这些供者的单核细胞是否存在疾病相关干扰素表达差异”。它跨越自然语言、细胞与供者、代码、计算、图表及结论。人可以先读简要解释，再沿其中的关系进入细节；同一个单位也可以成为 Agent 按需恢复上下文的入口。

这里必须分别记录三件事：**研究者当前打开哪一版解释，分析目前发展到哪一版，以及哪一版内容已经交给 Agent 续接。** 打开不代表理解，提供上下文不代表模型采用，修改解释也不代表计算已经改变。这三者可以暂时不同，但差别应可见，后续操作应有明确落点。

单独的折叠、回放、版本比较、记忆编辑或来源链接都已有先例。拟议增量是把上述操作连成一个可往返的交互：人的阅读位置不仅用于导航，也界定这次修订所依据的状态；修订不仅更新一段说明，也改变后续工作的上下文；新结果不仅增加一条消息，也回应这次修订。**这是一项交互贡献，不能拆成“新 UI”“新记忆系统”“新科学解释算法”三项来报。**

## 2. 单细胞场景：研究者究竟怎样判断与操作

### 2.1 先明确研究者需要理解什么

设有 6 名病例、6 名对照，每名供者贡献多个单核细胞，具有原始计数、注释和供者映射。问题是判断这些供者中，一组事先选定的干扰素反应相关基因是否存在疾病相关的表达差异；下文简称“干扰素表达差异”。以下数据、运行与版本标识均为说明机制的假设，没有实际效应量或用户观察。

研究者至少需要分清：图中的每个观测代表细胞还是供者；疾病分组属于哪一级；模型如何处理同一供者内的依赖；结果支持描述、供者层面的关联，还是更强的生物学解释。细胞数不能直接替代生物学重复数；忽略重复间变异会影响单细胞差异分析的推断。[R25](#r25)

即使计算完全合理，人的理解仍有工作要做。细胞级小提琴图可以展示表达分布，考虑供者依赖的模型可以评估关联；二者并非互斥，但回答的问题不同。“看到图”“知道模型名字”和“理解为何这项结果支持该解释”不是同一件事。

### 2.2 第一次阅读：围绕问题打开一项分析

假设 Agent 已生成细胞级表达图和一次把细胞视作独立观测的检验，并开始整理其他图表。研究者打开分析单元 `A@1`。它把以下内容放在同一段可追查的解释中：当前比较对象、图中的分布、检验使用的观测单位、输出所对应的运行，以及 Agent 对结果的解释。尚未核对的支持关系标为 Agent 的解释，不能由系统把它升级成科学事实。

研究者从“病例组干扰素表达更高”这句话进入依据。关键交互不是再展开全部聊天，而是沿着这句话所依赖的关系阅读：

| 研究者正在判断 | 需要连起来阅读的材料 | 这一步形成的认识 |
| --- | --- | --- |
| 图里很多细胞是否等于很多独立重复？ | 图使用的细胞集合 → 供者映射 → 每个供者的观测，而非只有合并后的病例/对照分布 | 分布现象与供者层面推断需要分别判断 |
| 这个显著性究竟来自哪种比较？ | 结果中的检验项 → 实际模型或调用 → 分组与重复单位 | 能定位统计依据，判断它是否回答原问题 |
| 我读的是修改后的结果吗？ | 解释所引输出 → 产生它的运行、脚本和输入版本；已知的环境信息与缺失项 | 新代码已写、进程已结束、当前解释已更新是不同事实 |

这里的图表、代码和运行仍可使用成熟组件。方法要求保留它们在这项解释中的关系，不要求所有研究者先读代码，也不要求把一个项目的所有来源图铺满屏幕。研究者可以停在 `A@1` 继续阅读，Agent 的新活动不会悄悄替换这段解释所引用的材料。InsightLens 的聚焦和证据导航、WaitGPT 的计算表示已经提供了这类阅读交互的基础；“可停留、可展开”本身不是新贡献。

### 2.3 人的判断：修改一项解释的适用范围

研究者发现这次独立细胞检验没有处理供者内依赖，于是在该检验与供者层面结论的关联处作出修订：

> 这次细胞级检验不能作为本项供者层面关联的统计支持。细胞分布图保留作描述；按供者汇总原始计数，核对当前设计并重新分析。新的关联判断等待新结果。

自然语言是输入方式；系统需要把修订落到已选中的问题、检验和材料上。适用范围来自选择与明确声明，缺失时再澄清，不能仅凭关键词推断“所有分析以后都用同一模型”。本例的汇总选择也不被推广成适合所有单细胞设计的定律。

修订后改变的是三处相互关联的内容：旧检验不再承担这一关联的统计支持；当前解释说明为何需要另做分析；后续任务带着这个理由和范围继续。旧检验跑过、生成过哪些结果，这些事实保留。描述图可在其原用途下继续存在，不因一次推断修订就被全部判废。

并非每次阅读都要产生修正。如果研究者沿相同关系确认现有模型确实处理了供者依赖，可以直接继续比较供者间差异、提出新的问题。单纯询问“为什么”只产生带归属的解释；只有明确改变分析选择或解释状态的操作才改写共享工作依据。阅读、询问、采用和修订不应混为自动同意。

### 2.4 人还在读，Agent 已经推进：修订必须找到当前落点

在研究者阅读 `A@1` 时，Agent 可能已补出另一张描述图，使该分析推进到 `A@2`。研究者的修订仍针对 `A@1`，系统不能用这份旧视图覆盖整个当前分析。它比较修订指向的对象与目前版本：

- 若新增内容只是另一张描述图，且本次修订依赖的细胞集合、供者映射和检验没有改变，则保留新增内容，把修订接入当前分析，形成 `A@3`。
- 若供者映射或正在采用的推断方法已改变，则并列呈现原指向与当前对应内容，保留修订为待确定的意见；先确定它现在针对哪项分析，再改变相应状态。不能假称旧修订已经适用于新范围。

这种比较首先依据资源身份、明确的字段和声明关系；它不自动证明两种科学解释语义等价。关系不完整时保留未知。每项分析和每个资源各有版本，不引入一个把整个科学项目视为同时更新的全局版本。

这一操作让人的理解可以按自己的速度形成，同时使干预落在仍在演化的工作上。它不是停止整个 Agent 等待逐条审批，也不是以“已经看过”推断研究者已理解。版本协调是已有技术；此处需要设计的是它怎样作用于一项科学解释及其后续用途。

### 2.5 同一项修订成为 Agent 续接的内容

在可以接收新上下文的下一次交互边界，Agent 获得 `A@3` 的简要内容及其材料入口。示意如下：

```text
分析 A，版本 3：当前单核细胞集合内的病例/对照供者比较。
重复单位：供者；本次输入及供者映射沿各自的保留引用读取。
当前解释：旧细胞级检验不再支持供者层面关联；描述图保留。
理由：研究者指出该检验未处理供者内依赖，修订源于 A@1。
待做：按本次选择汇总原始计数，核对设计，运行并解释新分析。
尚未知：修正后的效应与不确定性；目前不能写作新的完成结果。
依据入口：原检验、运行、输出及研究者修订，各有自己的引用。
```

这份内容与人读到的 `A@3` 来自同一批有版本的声明和引用。人可以阅读更完整的解释，Agent 可以按需取回细节；双方不必读相同像素或相同长度的文本。人折叠代码也不等于 Agent 应当忘掉代码。

接入过程区分“已准备”“已提供”和在可观察条件下的“已读取”。不能用一个“已同步”掩盖这些差别。已有在途调用不会因界面编辑而被追溯改写；无法进入其内部上下文时，就显示此次修订尚待后续接入。原生 Agent 的压缩仍由其运行时管理，Rho 在受支持的入口重新供给当前外部状态，不宣称能控制所有模型的内部记忆。

压缩也有具体对象：可以省略重复日志、完整矩阵和旧分支细节，保留取回入口；不能把当前范围、仍有效的理由、被替代的解释和未完成事项压成一句“已发现干扰素上调”。若这些内容尚未被纳入实际提供的上下文，就展示缺口，不能把磁盘上存着的笔记当作已经起作用的记忆。提供内容仍不保证 Agent 遵守；后续动作与结果要另行观察。

### 2.6 新结果回来：更新同一项解释，而非再堆一组输出

修正分析结束后，输出按实际输入、代码、运行与环境信息关联回分析 `A`；缺失的运行事实仍标为未知。新计算完成形成新的状态，例如 `A@4`，并不自动表示结论已被研究者认可。

研究者回到先前打开的版本时，能围绕自己的判断看变化：哪些数据与描述保留，哪一种检验被替代，新结果是否已经产生，原解释中哪一部分仍待重写或核对。若新模型未支持先前的关联，系统应使研究者能够将“细胞分布看起来不同”与“当前供者层面证据不足”并置理解；不能用最后一句总结抹去二者的区别。这里是假设的解释分支，不是实际发现。

新结果怎样改变科学解释，仍可能需要人和 Agent 讨论。系统可以按已有声明标出新增、替换和待核对的支持关系；不能从“进程成功退出”直接推导“新结论正确”。研究者形成的新判断再进入同一对象，而不是重新在聊天、报告和记忆中分别维护三份意思相近的文字。

这个往返使三项目标相互作用：阅读组织让判断有入口；人的判断改变共享工作依据；后续计算以与判断相关的变化返回，支持更新理解。它同时适用于确认一个合理选择、细化解释和发现问题，不只是一种报错流程。

## 3. 方法的最小组成与操作语义

### 3.1 一个分析单位，多种表示，分别记录依据与意见

分析单元关联科学问题及范围、方法与理由、运行与产物、当前解释、待解决事项和修订历史。它不要求新造来源本体：PROV-DM 可承接身份与修订，EVI 可承接声明的支持和质疑关系。[R02](#r02)、[R05](#r05)

其内容必须区分三种来源：实际观察到的计算事实，Agent 给出的解释与关联，研究者明确写下的判断。系统可从消息和工具记录中提出分组与关系，再让人或 Agent 修订；自动提取失败、未捕获和无法确定的关系保留在表示中。领域语义来自明示内容和可核查材料，不由 UI 凭空制造。

人的简要阅读、详细依据与 Agent 上下文是同一分析单元的不同呈现。范围、状态、有效修订和引用从明确字段生成，保留在简要表示中；详细日志和材料可以折叠或按需取回。模型补写的科学解释保留作者、版本和依据，并允许质疑。这样，压缩不会仅凭一次自由摘要决定是否保留人的修订；至于原生 Agent 收到后怎样处理，仍按前述接入边界如实记录。**共同的对象和修订关系，不等于让一个模型摘要成为唯一真相。**

### 3.2 四个操作完成一次往返

| 操作 | 针对的输入 | 产生的变化 |
| --- | --- | --- |
| 阅读与展开 | 某项分析的明确版本及其中一项解释关系 | 沿同版本依据进入细节，保留阅读位置；不自动改变科学判断或 Agent 上下文 |
| 局部修订 | 所读版本、选中的声明或关系、修改内容及适用范围 | 与当前相关对象核对，生成有归属的替代或待确定意见；原运行事实不改写 |
| 从该状态续接 | 当前适用的分析内容、待做事项及材料引用 | 产生可检查的上下文供给，记录实际接入状态；不冒充已执行或已理解 |
| 带回新进展 | 新动作、运行与产物，以及原分析和修订引用 | 更新同一分析，按研究者所读版本组织变化，区分事实变化与待判断的解释变化 |

其中，人读的版本、分析的当前版本与 Agent 最近收到的版本分别保留。它们的关系贯穿四个操作，不能只在某个历史面板里查到。范围相同也不等于结果相同，收到修订也不等于已经重新计算。

### 3.3 为什么不是把三个已有工具摆在一起

把洞见导航、计算图和共享记忆并排放置，仍可能出现：人对旧解释提出修订，另一张图继续展示新结果，Agent 却从摘要取回旧主张。即使三份内容各自可追溯，研究者仍需手工重建“我改的是哪一版，改动现在适用于哪里，Agent 从哪里继续，结果回应了什么”。

本方法把这项重建变成上述操作本身的一部分。读的位置界定修订基线，范围决定修订如何接入当前分析，上下文引用标明实际供给，返回的进展回应原修订。这是需要实现的联系，不是多加一个“共享”标签。已有工具完全可能通过扩展实现它；独立贡献不要求别人技术上做不到。

## 4. 与 InsightLens、WaitGPT 和 Mycelium 的正面对照

以下按论文明确报告的机制比较，没有运行这些系统完成本例。“未报告这项操作”是文献边界，不是不可实现性的断言。

| 工作 | 在同一个单细胞场景中已经能帮到哪里 | 本方法增加的具体操作 |
| --- | --- | --- |
| InsightLens [R21](#r21) | 持续提取并修订洞见，关联关键代码、输出和图，按主题导航；可固定关注的洞见。它已有阅读、重访与组织机制，提取 Agent 也使用历史洞见记忆 | 将读到的某版解释作为修订基线，使修订在当前分析中的落点与分析 Agent 的续接版本可见，再按该阅读基线呈现新进展。论文没有把洞见提取记忆等同于这种可操作的执行上下文 |
| WaitGPT [R18](#r18) | 将代码组织成可读的操作链，展示运行状态；可改参数、局部追问、修改代码并重跑。它也支持按人的节奏回看，不能把“看懂并干预过程”认领为新颖性 | 让局部判断连同科学适用范围留在可继续使用的分析解释中，并把阅读、当前分析与后续上下文的差异纳入同一操作。§5.3.3 明确将局部追问与主对话隔离、不影响 Agent 记忆；这不等于其改代码或重跑结果永远不影响后续分析 |
| Mycelium [R38](#r38) | 通过有来源的科学上下文图连接观察、解释和假设，并路由给人和 Agent。其补充图 6 已示范人的科学约束进入另一条后续分析，保留来历与局部分歧 | 将这种可行动的科学上下文具体化为人能持续阅读、就所读版本局部修订、检查接入并读回变化的交互。已读方法没有规定如何协调同一分析中人的阅读基线、当前状态与 Agent 续接版本；“人的判断进入后续行动”本身已经属于它的能力 |

三个差别有不同落点。对 InsightLens，增量是使阅读中的修订成为后续工作状态；对 WaitGPT，是使局部干预的科学理由与范围持续存在，并与后续上下文关联；对 Mycelium，是把可路由的科学状态变成可往返操作的阅读对象。**不能简写成“InsightLens 只展示、WaitGPT 只看代码、Mycelium 只有后台”。**

Mycelium 尤其接近，甚至可以承载本方法的存储和路由。因此 Rho 不应再主张发明科学共享记忆。区别只在本章具体展开的交互语义；若实现只是在它的图上加摘要和浏览页面，这个差别就没有成立。

## 5. 更强的反例进一步限定贡献

SEMV 比上述三项更直接覆盖“人的修订改变计算和记忆”：它将质疑定位到声明与证据，按受影响范围重算，保留前后报告，并将经核验的经历整合为后续可检索记忆。[R39](#r39) 因而“可质疑解释”“保留旧结果”“局部修正”“修正进入记忆”均不能作为 Rho 首创。其 §4.5–4.6 以核查案例的质疑及定稿后记忆整合为中心，未给出本提案中持续分析的阅读基线与续接状态协调；这才是剩下需要比较的边界。

Memory Sandbox 已提供可查看、编辑、摘要及返回原文的记忆；cotomi Act 已将过程整理成双方可编辑、Agent 可检索的工作区；MemGPT 已把外部记忆纳入 Agent 的工作循环。[R36](#r36)、[R37](#r37)、[R34](#r34) 共享文件、可编辑记忆和摘要回流都不是差别。

同样，AI Chains、任务分解和 Treadstone 已让人检查中间状态、调整并继续分析；Loops 已支持分析历史的比较与重访，分析来源服务意义恢复也有长期研究基础。[R35](#r35)、[R19](#r19)、[R22](#r22)、[R15](#r15)、[R01](#r01) 本文没有另行认领这些部件；读者若移除三种版本的协调与修订往返，余下的大部分能力都应归还这些先例。

THREAD-Bio 则已经给出生信主张强度、重复单位和变化后持续复核的科学约束；Tisane/rTisane 已支持领域关系与统计模型的交互澄清。[R24](#r24)、[R31](#r31)、[R32](#r32) 本例的贡献不是发现伪重复、自动选对统计模型，或再次提出“主张需要证据”。这些工作帮助确定读者必须理解的内容；Rho 的方法处理这些判断在持续阅读与继续分析之间怎样发挥作用。

## 6. 为什么这个增量值得研究，以及它目前是什么

生信分析的困难在本例中体现为关系：细胞与供者、描述与推断、脚本与运行、输出与结论，以及当前选择与历史分支。只压缩字数可能恰好删掉决定解释的条件；只展示全部细节又把关系重建留给人。Agent 还会在研究者阅读时继续工作，使一份“最新摘要”不足以表示双方正在依据什么。

本方法试图让研究者理解的是一项可追查、可修改、还能继续发展的分析，而不是暂时读懂一句孤立解释。它增加的能力可由一个具体动作辨认：**研究者在自己所读的依据上修订解释，不必另外去更新另一份记忆、重讲整段上下文，再手工寻找哪批新输出回应了这次判断。** 把这些动作可靠地联系起来，具有独立的交互设计内容。

代价也具体：科学关系提取可能出错；显式范围和版本增加维护负担；过细的分析单元会打碎上下文，过粗又难以局部修改；人可理解的摘要未必是 Agent 最有用的上下文；并非所有运行时都提供可观察的接入位置。方法需要暴露这些边界，不能靠声称“全自动整理”消除它们。

**当前判断：这个整体可以形成一项范围明确的交互方法贡献；现在已有的是上述方法提案，尚不是已实现、已证明新颖且有效的系统贡献。** 这一判断比“值得继续找问题”更具体，也比“Rho 已解决人机共同认知”更窄。过程可阅读性提供理解入口，人的判断成为共享状态中的修订，Agent 的记忆支持从该状态继续；三者通过同一操作相互作用，而不是三个并列卖点。

如果最终产品只做到自动笔记、关联图表和向模型追加摘要，已有工作足以覆盖，独立贡献不成立。如果实际方法实现了所读版本上的局部修订、与当前分析的协调、可见的上下文接入，以及按该阅读基线读回变化，就有一项可以独立描述、与上述工作直接比较的交互贡献。本文不把界面存在等同于人的理解提升，也不把过程解释等同于模型内部推理解释或生物学因果机制发现。
