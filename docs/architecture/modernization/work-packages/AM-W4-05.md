## Acceptance boundary

Add `begin_broker_call`, `resume_broker_call`, contribution-sized variants and
`cancel_broker_call` to `ComponentPluginHost` with the same public `GuestStep`
model and byte/step/cumulative-result budgets as core-v2. Convert generated WIT
records into the existing host-owned step type, parse only the explicitly typed
JSON value fields, and run the same handle, permission, operation, call-id and
payload validation before a step can leave the Store.

At most one call is active. The guest must fully return a typed step before the
caller may perform broker I/O; no broker, filesystem, network or Workspace work
runs while the Component Store is borrowed. Resume and cancel require the exact
active request identity. Reordered, repeated, malformed, oversized or over-step
transitions quarantine only that host.

Add an exact-request cancellation handle using the per-plugin Engine epoch.
Pending cancellation prevents dispatch; in-flight interruption reports
`cancelled`, clears the route and quarantines the exact host while a sibling
project remains usable. Tests cover immediate completion, yield/resume,
guest-cancel, invalid typed steps, wrong request identity, budgets, in-flight
epoch cancellation and two-project isolation. Desktop routing, grant execution
and durable recovery do not change in this slice.
