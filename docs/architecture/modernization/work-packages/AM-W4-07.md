## Acceptance boundary

Replace the desktop `ActivePlugin` concrete core host with `PluginGuestHost`.
Activation constructs exactly the ABI returned by
`WorkspacePluginManifest::runtime_abi()`; it never probes bytes, retries through
the other parser or derives ABI from exports. V1–V3 therefore continue to use
core-v2, while V4 uses its mandatory explicit ABI.

Both variants must continue through the existing durable generation,
permission grant, contribution publication, broker dispatch, crash,
disable/update/rollback and restart-reconstruction paths. Permission-bearing
and contributing packages require `supports_guest_calls()` rather than a
core-specific numeric ABI check. No second grant store, route map, recovery
branch or plugin identity is introduced.

Focused tests cover V4 component activation, typed lifecycle and broker yield
through the real desktop permission lane, restart with a fresh host generation,
failure containment and two-project isolation. Existing V1–V3/core-v2 tests
remain unchanged and passing. Only after those behaviors verify does this
package synchronize application version `0.4.1-dev.17` and NEWS; it does not
build, sign, install, publish or remove core-v2.

## Verification calibration

The initial broad Clippy command reached unchanged `rho-store` code and failed
on eight pre-existing style lints. A second `--no-deps` run still scanned all
unchanged desktop modules and reported 29 existing lints. Neither result
identified a diagnostic in this package's changed files. Under the
risk-weighted policy established by `AM-W1-25`/`AM-F-0033`, rewriting unrelated
Store, Agent, Git and Runtime modules is not acceptance evidence for this
desktop routing change. The accepted compile check is therefore `cargo check`
for all desktop targets; the 74-test workspace-plugin matrix owns behavioral
regression detection. Both Clippy attempts remain truthful non-passing
telemetry. This calibration does not weaken any runtime, identity, grant,
recovery or project-isolation check.
