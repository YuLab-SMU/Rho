## Acceptance boundary

Extend the admitted artifact into a crate-owned `ComponentPluginHost` that uses
the generated `rho:plugin@1.0.0` bindings and an empty Component linker. The host
owns the same exact `WasmHostIdentity` dimensions and implements the existing
Hello/Activate/Echo/Heartbeat/Quiesce/Dispose state machine without changing
serialized host frames or core-v2 behavior.

Instantiation and every guest call run with deterministic fuel, epoch deadline
and StoreLimits for memory, tables, instances, tables and memories. A missing or
wrong typed export fails before publication. Guest-returned lifecycle errors map
to the stable `guest_rejected` code. Trap, fuel exhaustion, timeout/resource
failure and panic tear down only the exact Component runtime and leave it
quarantined; a sibling project host remains usable. Dispose failure is truthful
and non-routable.

Tests generate an interface-complete Component from repository WIT at runtime
using version-matched `wit-component` development tooling; they do not require a
separately installed Rust target or checked-in opaque binary. They cover the
successful lifecycle, typed-export mismatch, trap/fuel containment, memory
limits and two-project isolation. No desktop activation route changes in this
slice, and `begin`/`resume`/`cancel`, broker grants, durable recovery and desktop
dual-ABI selection remain later `AM-F-0006` work.
