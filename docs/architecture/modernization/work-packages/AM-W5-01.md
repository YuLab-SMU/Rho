## Acceptance boundary

Work-package records remain the only worktree registry: ID, base commit, owned
paths and integration dependencies are validated at start and again before
integration. Path overlap is a real collision failure; planned wave order,
file size and untouched-package status are not merge vetoes.

Feature worktrees record user-visible notes as independent strict-JSON Markdown
fragments under `.changes/`. Validation checks identity, category, package
ownership and deterministic ordering. Only the integration lane composes
reviewed fragments into NEWS; feature worktrees do not contend on NEWS.

`desktop/dist` becomes reproducible build output rather than reviewed source.
It is ignored and removed from the index, while the existing source build,
asset manifest, licenses, build identity and Tauri cutover checks prove that a
clean candidate regenerates the required tree. A temporary Git fixture creates
Runtime and Agent branches from one baseline and requires `git merge-tree` to
merge their disjoint source changes; a declared overlap must fail before work.

This package does not authorize merging repository branches, pushing, opening
a PR, packaging, signing, installing, publishing or releasing.
