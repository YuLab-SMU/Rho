## Boundary

Run proposal/ledger reads and every mutation event on the existing single Store
worker. No Store handle may cross the disk mutation or Workspace identity await.
The project-transition gate still captures root and registers the mutation
claim atomically; the exact per-project-path lane still serializes disk access;
the durable `mutation_started` record still precedes disk mutation; Workspace
identity still advances before `applied`/`undone` becomes durable.

Failure classification continues to observe the bounded project file outside
the Store worker, then records `mutation_failed` or `outcome_uncertain` through
the worker. A persistence failure must not be reported as a clean file failure,
and restart reconciliation remains the final authority for incomplete ledgers.
