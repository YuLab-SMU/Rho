## Boundary

Add `ArkSession::execute_async` backed by an async variant of the existing event
loop. Existing synchronous callback APIs remain compatible wrappers. Extend
`RuntimeOutputRepository` with execution create/start/link/append/finish
operations; append reads the current capture policy and commits the journal in
one Store-worker closure.

The existing local `rho-server probe-ark` diagnostic uses the async callback
path so a real Ark process validates ordered event delivery rather than leaving
the new boundary covered only by compilation.

Migrate Runtime admission and supervised execution to those operations. The
Ark listener awaits each append before receiving the next event, preserving
ordered backpressure with no queue, dropped event or unbounded memory. Runtime
descriptor state, project-transition gates, Workspace execution, follow
notifications and terminal classification remain in the Registry owner.
