## Result and review

`ComponentPluginHost` now exposes the same begin/resume/contribution/cancel API
shape and host-owned `GuestStep` values as core-v2. WIT records are converted
only after pre-parse string bounds, JSON value parsing and the shared core-v2
handle, permission, operation, call-id and payload validator. Broker work still
cannot execute while the guest Store is borrowed: every API returns a complete
typed step first.

The host enforces one active call, exact request identity, eight steps, 64-KiB
broker steps, contribution terminal bounds, one-MiB cumulative raw broker
results and bounded resume framing. Focused tests cover immediate completion,
yield/resume, guest cancel, invalid handles, wrong request, repeated steps,
result budgets, pending cancellation, active-call cancellation and sibling
project survival.

`a3723e1` adds a deterministic instruction-stream test: after Store fuel/epoch
preparation but immediately before an infinite guest `begin`, the exact
cancellation handle advances only that Engine epoch. Wasmtime interrupts the
executing component, the host reports `cancelled`, quarantines only that host,
and a sibling project remains active. The complete extension runtime passes 234
tests; plugin authoring passes 13 and focused desktop plugin integration passes
71. The 916-line host module is recorded as LOC telemetry, not a correctness
failure or a reason to split the state machine across artificial boundaries.
