## Result and review

Agent-file restart recovery now reads owned pending ledgers in one Store-worker
operation, observes project files without any database handle, then appends the
derived recovery events in a second worker operation. Recovered, not-applied
and uncertain classifications retain their exact payloads, partial-write order
and A/B scoping. An injected SQLite trigger rejects a recovery event without
creating false terminal truth; after removing the fault, the same worker
recovers once and the next pass is empty.

Removing the `Store` field made the compiler expose three remaining consumers:
plugin and Resource project-revision commits now await the common identity
service, and render-job artifact reload uses `ArtifactRepository`. The startup
plugin reconciler retains a short-lived local Store until its separate service
migration, but no synchronous connection is stored in global Workspace state.

`WorkspaceBrokerState` now contains only Broker authority and a cloneable
executor handle. The Workspace lane still serializes Ark/revision mutations and
publishes identity only on guard release, while Agent, Store and plugin
background work continues independently. Focused tests pass (Agent file 8 with
1 exporter ignore; lane 6; plugins 71; Resource 8 with 1 exporter ignore;
render 5). The complete Server matrix passes 115 tests and Desktop passes 354
with 21 explicit ignores. The 193-command inventory, schema, IPC, version and
NEWS behavior are unchanged.
