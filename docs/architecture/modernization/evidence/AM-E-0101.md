## Result and review

Wasmtime remains exactly `38.0.4`; its `component-model` feature is explicit and
the dependency tree contains no `wasmtime-wasi`. The repository-owned
`rho:plugin@1.0.0` WIT world compiles into typed bindings and declares only
exports. Its guest-step envelope is typed; JSON remains limited to operation
arguments/results.

Admission uses a fresh Engine configured with the existing core-host fuel,
epoch and disabled-proposal policy plus explicit Component Model support. Four
focused tests prove deterministic zero-import admission and pre-execution
rejection of malformed bytes, core modules, component imports and oversized
input. The complete extension runtime passes 224 tests, plugin authoring passes
13 and focused desktop plugin integration passes 71, preserving core-v2.

An initial locked run correctly exposed that the repository's minimal `wat`
test dependency had Component text parsing disabled. Enabling only its
`component-model` test feature produced the locked fixture toolchain; no
production permission or runtime authority changed.
