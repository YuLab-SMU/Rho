## Result and review

`ComponentPluginHost` type-checks the generated WIT exports through
`PluginPre` before Store allocation or guest execution, then instantiates behind
an empty linker. It preserves the existing host frame and lifecycle state model
for Hello, Activate, Echo, Heartbeat, Quiesce and Dispose. Guest-returned errors
become the stable `guest_rejected` code; guest strings are never copied into
host diagnostics.

The host has a fresh per-plugin Engine and a bounded Store: two module instances
(guest plus canonical adapter/fixup), one memory, one table, two-MiB per-memory,
1,024 table elements, deterministic fuel and an epoch deadline. Focused tests
prove successful typed lifecycle, export mismatch before execution, returned
rejection, dispose trap, fuel exhaustion, minimum and dynamic memory failure,
timeout quarantine idempotence, `Send`, and sibling-project survival.

The complete extension runtime passes 230 tests, plugin authoring passes 13 and
focused desktop plugin integration passes 71. Version-matched
`wit-component 0.239.0` is development-only fixture tooling; Wasmtime remains
`38.0.4` and no WASI dependency or host import was introduced.
