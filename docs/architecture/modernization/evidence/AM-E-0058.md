## Result and review

All production revision commits following `broker.project_changed()` now await
one shared `StoreExecutor` service. Project file create/write/delete and manual
invalidation, Agent file apply/Undo, artifact exports, plugin boundary recovery
and startup identity initialization retain their existing broker and filesystem
authority while removing SQLite work from the Tokio task that owns the
Workspace lane.

The lane remains held until the exact owned `WorkspaceIdentity` is durable, so
another Ark or revision mutation cannot overtake the commit. A SQLite trigger
fault test rejects the update, observes the previous identity unchanged, then
removes the fault and proves the same worker can persist the next revision.
Callers still return or publish refreshed plugin context only after that awaited
commit succeeds.

The complete desktop matrix passes 353 tests with 21 explicit ignores. Focused
project, Agent-file and plugin suites pass, the 193-command IPC inventory is
unchanged, and no schema, public response, version or NEWS behavior changes.
