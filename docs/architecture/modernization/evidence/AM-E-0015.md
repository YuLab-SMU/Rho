## Result and review

`apply_agent_file_edit` and `undo_agent_file_edit` now export one complete
command contract from their Rust request and response types. Generated
requests retain the exact nested `request` argument and camel-case Tauri JSON.
The response includes the authoritative project snapshot and workspace
identity that Rust has always serialized, with every bounded Rust integer
explicitly projected as the existing JavaScript `number` contract.

The former real transport asserted that Rust's `afterSha256` response was an
`after_sha256` field. The browser mock returned that handwritten snake-case
field, so browser tests hid the real-desktop drift. The new narrow facet accepts
the generated camel-case wire response and performs one explicit normalization
to the established frontend `after_sha256` business API. The existing App Undo
path therefore receives the digest in both real and mock transports without a
product API migration. The mock also returns complete project/workspace data.

Two clean generations are byte-identical and a one-byte stale fixture fails.
Rust serde fixtures prove exact request and response casing, nested
project/workspace shapes, and JavaScript-safe numbers. Focused frontend tests
prove both exact request objects, the real `afterSha256` normalization, stale
digest rejection, and complete mock assignability. The existing App regression
still proves a successful apply exposes Undo.

The complete Rust matrix passed. The desktop suite reported 340 passed and 12
ignored opt-in/exporter tests, including concurrent same-file admission,
queued cancellation, project-switch exclusion, exact unsaved-buffer Undo,
create/delete Undo, forged/no-op replay rejection, disk-write and post-write
failure truth, incomplete-ledger recovery, reopen behavior, and project
isolation. The full frontend gate passed all eleven generated binding suites,
193 registered commands across 25 Rust files, 36 files/262 tests, the production
build, tracked asset identity, Chrome smoke, and real interactions.

The entry bundle moved from 854,242 to 855,131 raw bytes and from 237,565 to
237,740 bytes under an explicit Node zlib level-9 measurement: +889 raw and
+175 gzip bytes. This is engineering telemetry, not a fixed development veto;
review found no material performance regression.

A separate post-test review compared the diff with the active Agent file
editing contracts. Command names, request JSON, response JSON, project-relative
containment, proposal/event identity, digest and editor-anchor rejection,
durable mutation ledger, project transition exclusion, recovery, schema, and
broker authority are unchanged. No dependency or lockfile changed. No new
filesystem, credential, network, approval, public-protocol, release, signing,
installation, or publication authority was introduced.
