## Result and review

All seventeen Store-backed handlers in `commands/plugins.rs` now submit their
existing query, lifecycle, permission or contribution operation to the shared
`StoreExecutor`; the source contains no `read_store`, `Store::open` or raw
SQLite access. The executor lends one `BorrowedStore` alias, and only the
required registry/helper call families became generic over `StoreConnection`.
Owned-Store callers and their default types remain source compatible.

Runtime-context construction now takes `project_transition_gate` only long
enough to capture the current project root and the lane's last fully committed
identity. It never acquires `WorkspaceBrokerLane`. Update, rollback, uninstall
and restore retain their pre-existing full-operation transition gate and use an
under-gate helper; no ordinary handler gained a long global lock. Uninstall and
restore still acquire the Workspace lane only after durable file completion to
advance and persist the authoritative Broker project revision.

The held-lane test proves runtime-context construction completes while a second
lane waiter remains blocked. The worker lifecycle test proves a rejected
enable does not poison the executor, then enables, lists, disables and reads
durable terminal state through the same connection worker. All 70 plugin tests
pass lifecycle CAS, grant/audit, guest failure, recovery and A/B isolation; the
complete desktop matrix passes 350 tests with the suite's 21 explicit ignores.
The 193-command inventory and serialized contracts are unchanged.

Review found no command name, JSON, schema, transaction, permission, grant,
guest ABI, project revision, version, NEWS or release change. Boundary
teardown, reconciliation and heartbeat still borrow the legacy Workspace Store
and remain tracked by AM-F-0003.
