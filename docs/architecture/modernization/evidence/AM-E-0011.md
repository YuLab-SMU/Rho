## Result and review

`get_agent_turn_detail` now returns one typed desktop view over the existing
Store-owned turn, event, approval, and context-receipt records. The former
`serde_json::Value` conversion and object insertion are gone. The generated
module owns the command string and exact `turnId` argument, imports the existing
generated `AgentTurnSummary`, and does not declare a duplicate summary type.
Two clean generations are byte-identical and a one-byte stale fixture fails.

Rust serialization fixtures cover events, approvals, nullable fields, context
receipts, and JavaScript-safe counters and revisions. Existing Store scenarios
pass for not-found, normalized roots, conversation scope, and two-project
isolation. The real transport and browser mock satisfy one-method
`AgentTurnDetailTransport`; null and backend rejection pass through, while an
unknown stored Agent mode fails at the shared frontend compatibility boundary.
The context-plan projection remains the existing public subset of the generated
durable context item instead of gaining persistence identities.

The frontend gate passed 32 files and 250 tests, seven deterministic generator
suites, the 193-command inventory across 25 Rust files, generated assets,
Chrome smoke, and real interactions. The full Rust workspace passed; the
desktop suite reported 336 passed and eight existing opt-in/generator tests
ignored, with this exporter exercised by its dedicated generator suite.

The entry bundle moved from 852,107 to 852,274 raw bytes and, under an explicit
Node zlib level-9 measurement, from 236,895 to 236,949 bytes: +167 raw and +54
gzip bytes. These values are engineering telemetry, not a fixed development
veto, and no material regression was found.

Command name, argument key, JSON fields, ordering, null not-found behavior,
project isolation, Store schema, preview shape, and mock behavior are unchanged.
No version, NEWS, schema, permission, public protocol, release, signing,
installation, or publication change is required or claimed.
