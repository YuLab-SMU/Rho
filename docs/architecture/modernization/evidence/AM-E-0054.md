## Result and review

`ArkSession` now exposes an async event callback while the original synchronous
API remains a compatibility wrapper. The receive loop awaits every callback
before receiving the next correlated event, and its focused regression proves
that a callback may suspend, preserves call order and returns its exact failure.
The local `rho-server probe-ark` path uses that API; a real Ark 0.1.252 process
on R 4.5.2 emitted the complete busy-to-idle event sequence and shut down
cleanly.

Runtime execution admission, running transition, Workspace run linkage, each
projected append and terminal transition now use `RuntimeOutputRepository` on
the single Store worker. Policy lookup and append share one worker closure, so
the revisioned capture limit cannot drift between those operations. Auxiliary
Ark output has no queue: every event awaits its append, retaining bounded
ordered backpressure. Once an append fails, execution continues as before and
the durable terminal state remains truthfully `partial` or `unavailable`.

The focused and complete Store/Desktop matrices cover capture limits,
deduplication, cancellation, recovery and two-project isolation. Static review
finds no `read_store` call in `runtime_registry.rs`; the 193-command inventory,
schema, IPC, version, NEWS and release behavior are unchanged.
