# 应用外壳工作台状态迁移要求

Rho 应用外壳接收 Core 退出的布局、焦点、窗口恢复及呈现状态保存责任。
这是待实施要求；当前外壳使用 Core 的 `windows.*` 和视图状态接口，渲染和本地
待确认状态见 [布局适配](../ui/src/plugin-layout.ts) 与
[窗口状态](../ui/src/plugin-window-state.ts)。本文不表示新持久化机制已经实现。

## 所有权

外壳拥有窗口布局及版本、停靠、焦点、可见性、关闭与恢复的产品流程，负责托管
插件视图并保持凭据私有。Core 继续拥有连接认证、授权、实例生命周期与通用资源边界。
工作台状态不能成为 CLI、MCP 或科学调用的必要前提，也不另建科学执行路径。

场景定义、历史与准备由 [Manager](../../Rho-plugins/plugins/manager/MIGRATION.md)
承接，外壳应用明确的布局意图；[Studio](../../Rho-plugins/plugins/studio/MIGRATION.md)
通过相同能力接入开发组合。[Editor](../../Rho-plugins/plugins/editor/MIGRATION.md)
和 [Console](../../Rho-plugins/plugins/console/MIGRATION.md)各自解释内容，外壳不把它们
统合成自己的文档模型。画布和声明编辑归 Studio，运行渲染由选定消费者验证。

这些跨仓链接使用三仓相邻检出布局；独立克隆可按路径在
[插件仓库](https://github.com/YuLab-SMU/Rho-plugins)查找。应用保持无 Cargo workspace，
不通过导入 Core 私有实现建立持久化。

## 必须承接的用户能力

| 用户动作 | 迁移后必须保留的结果 |
| --- | --- |
| 拖动、分组、选择或隐藏视图 | 保存布局并保留原视图身份和本地内容，不改变科学 Provider |
| 刷新、重连或重开窗口 | 恢复已确认布局和 Owner 状态；旧观察不覆盖新编辑，缺少实例时明确标记 |
| 准备并应用场景 | 准备不改变当前布局；应用检查捕获版本，冲突或失败保留旧布局及部分准备结果 |
| 关闭视图 | 协作保存有明确确认；缺失确认不等于已保存；关闭与释放实例分别处理 |
| 打开开发预览或测试视图 | 科学权限隔离与模式标识继续有效，私有凭据不进入 iframe 或场景定义 |
| 处理 Owner 暂时不可用 | 显示受影响入口及已保留信息，不冻结无关读取，也不自动启动替代实例 |

## 保存和并发

布局与插件状态需要明确的持久化及确认入口，不能以 React 状态或仅在内存中的引用
宣称已保存。选择实现时优先复用维护中的文件和存储机制；声明写入范围、并发版本、
崩溃行为及内容限额，不预建新的通用文档平台。需要后台适配时，其实现归应用层。

插件状态按项目、调用者及相应视图或内容身份隔离。外壳只保存受授权的 Owner 数据，
不解释内容，也不将 token、原生凭据或权限写入布局。限额说明保护对象、配置方式和
超限行为。草稿确认、布局确认、文件保存及科学 Operation 完成分别表达。

应用布局的版本检查与完整替换由外壳拥有；多步实例准备仍由 Manager 分步跟踪，
不能把它声称为一次可回滚的科学事务。未确认的保存请求保持原身份和捕获输入，
新编辑与旧请求分别保留。若保存入口采用受管能力，则复用 Core Operation；
本地呈现状态采用自己的确认机制，不重新实现科学日志。

## 旧状态和接入顺序

已确认布局、视图状态和关闭记录不能随 Core 产品表退出而自动删除。
读取、导出或显式迁移路径需要单独验证；仅保留旧字节但无法访问仍是未完成能力。
后端替换不承诺保留 R 内存，资产刷新不改变不可变插件或自动新增 Host 能力。

先选择一条普通窗口保存／恢复流程，实现应用所有的契约和持久化；随后分别接入
Manager 的场景应用和各插件的状态确认。组件可以独立交付，未接入项明确标为待迁移。
消费端 SDK、产物构建、rho.lock.json 和组合验收只在选定集成任务中更新。

## 应用验收

在临时项目验证：布局修改后刷新；隐藏和移动 Editor／Console 后内容保持；
旧布局版本被拒绝；场景应用失败不改旧布局；关闭保存失败可见且不释放实例；
重连不重放原 Operation。普通无窗口调用同时不依赖工作台状态。

fixture 预览还需验证科学调用、外部访问与下载限制；真实 R 连续性另由相应集成流程
证明，不能由窗口夹具代替。不得重启用户 Host 或 R 会话。
代表性宽度、键盘、IME 和 Unicode 要实际检查；重大交互改动沿用
[设计](RHO-DESIGN.md)规定的 Paper 评审。
产品完成要求承接流程和所选组合真实通过，Core 接口退出或 UI 构建不代替这些结果。
