## 5. 决定 1：布局渲染器

**维持默认：自建的组合树渲染器，W6 删除 dockview。**

- 难例通过：未保存的脚本经过 Agent 改布局、人重排、切换布局后，仍是同一个编辑器元素；自己的
  撤销接着可用，焦点留在编辑器里。
- 组合保真：六棵树（单视图、两个标签、左右、上下、三层、不等分）在 1440 和 1024 下轴向、顺序、
  权重误差都是 0%（门槛 2%）；390 下折叠成按阅读顺序排列、可用键盘操作的标签，记录不变。
- W2 在这个渲染器上加了整套 Rho 层、视图自己的页头和运行视图，没有一处需要 dockview 的能力。
  每个视图有自己的持久容器和页头元素，移动时不重新挂载。
- 停车场里的两项（拖拽排序/自由停靠、分隔条写回组合）不依赖 dockview：前者是 P1，后者在 W5
  经 `composition.apply` 实现。

## 6. 决定 2：浏览器能否停止 Agent 的运行

**维持默认：能，限定在授权边界内，W4 实施。**

现状（代码事实）：

- `action.cancel` 只接受提交者本人取消；`requests.lookup` 和 `requests.cancel` 只在调用者
  自己的请求文件里查找。
- 浏览器方法范围（`src/browser-access.ts` 的 `browserMethods`）没有 `action.*`。W4 要加
  `action.cancel`；按决定 3（通用参数表单），还要加 `action.submit`。这是本检查点批准的边界变更，
  不扩展到别的方法。

W4 实施时必须先写成的服务端测试：

1. 跨项目请求被拒绝；
2. 配对范围不包含该项目的浏览器被拒绝；
3. 猜测的 ID 与不存在的 ID 返回同一个错误；
4. 记录请求者，原提交者不变；
5. Agent 取消自己的运行，行为不变；
6. 受理取消不等于已经停止：界面分别显示“已请求停止”和“已停止”。

## 8. 本里程碑的修正与发现

- **标尺 M2 的“可收起”：** 展开控件可以不在被展开的区域里，只要用 `aria-controls` 指向它
  （ARIA 的展开模式）。表格提问的操作移到视图页头后需要这条规则；被展开的线程仍只能一键收起。
- **表格提问：** 操作和状态是插件自己的视图控件，和文档的“保存”一样放在视图页头；展开的草稿或
  线程是临时附加，按 M2 计量。Rho-plugins 的改动只加了可选的 `headerTarget`，不传时行为不变。
- **新令牌 `--color-verified-text`：** 原来的已验证绿色写文字只有 4.13:1，文字改用 4.5:1 的
  深一档；圆点和描边仍用原色。
- **回来摘要不重复打断：** 仍等人决定的布局建议只在打断里出现，摘要不再列一遍。
- **声明事项进入实时 `Screen`：** 回放的 `trace.ts` 早就把任务地图映射为事项，实时的
  `live-trace.ts` 没有；W2 补上。否则 W6 删除旧任务地图后，声明事项会完全不可见。
- 停车场新增两项：运行视图只能写 “stderr retained”（浏览器不能读 `action.output`）；运行事实
  只给代码和路径的摘要，所以写 “code version N of M” 而不是文件名。两项都放到 W4。
